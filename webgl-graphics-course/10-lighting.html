光照：法线与 Phong 三件套 ​

立方体贴上棋盘格之后，你想再进一步：加一盏方向光，让它有点明暗、有点立体感。着色器里写了一行亮度，运行起来却傻眼了——六个面亮度一模一样，转起来还是一张平面卡片的错觉，最多加了个会转的贴图。更迷惑的是第二种写法：你记着「向量跟矩阵走」，把法线乘上模型矩阵再送进着色器，画面倒是每个面不一样亮了，可物体一被拉伸，明暗就出现在不该出现的地方：亮面偏了、暗面渗光，越看越不对劲。两笔账其实是一笔：第一种写法里法线压根没传进着色器，光照没有原料，算了个寂寞；第二种写法原料传了，但喂错了矩阵。本章把这笔账算清：法线是什么、为什么它不能直接吃模型矩阵、以及一套用了半个世纪、至今还在教科书首页的光照公式——Phong 三件套。

出发前清点：歇班一章的家当全员复工 ​

先清点数学侧。第 9 章清点时说过，向量们歇班，讲光照时才全员复工——今天到期。点积是「方向一致度打分机」，马上要给「表面朝光的姿势」打分；归一化只留方向，法线全程以单位向量出场；叉积与向量投影在推导与验证里打杂。矩阵这边也不缺人：齐次坐标、列主序、矩阵乘法从右往左作用，MVP 三台机器原样值班——视图矩阵把世界搬到相机跟前，透视投影把视锥体压进操场，宽高比照旧传画布的宽除以高，正交投影那台平行光路的机器本章歇班。模型矩阵是本章的怀疑对象：它对位置永远是对的，对法线却未必。齐次坐标里还藏着一个待兑现的细节——位置补 w=1、方向补 w=0，法线是方向，这个 0 本章用上了。

管线侧是渲染管线那三段：顶点着色器管「东西在哪」，光栅化把三角形圈成格子，片元着色器管「格子涂什么色」。分工有一处搬家：前九章片元着色器只做查表和混色，本章起它要真正算物理——每个格子各自算一遍光。进料照旧：顶点属性从缓冲区逐顶点进料，第 8 章立方体顶点表里那三个一直没人取用的 normal 分量（交错布局里偏移 12 字节）今天正式开工；随时间变的量——光源位置、三件套强度、光洁度——全走统一变量；法线从顶点到片元走可变变量，沿线做线性插值，这笔插值的账本章要算。渲染循环每帧清屏重画，动画量用增量时间缩放，第 3 章的缓动手法与片元着色器开头的精度限定符照旧。裁剪坐标系与透视除法的账不用重算，本章顶点坐标的处理一行不改。

遮挡与绘制方式也照旧：深度缓冲与深度测试开着，本章两件物体加光源标记共三件，遮挡照旧由账本裁决；索引绘制一次 drawElements 引用顶点表；缠绕方向从外面看逆时针 = 正面，背面剔除开着省一半片元——球面生成时也要按这个约定排顶点。纹理那套查表词汇——UV 坐标、纹素、采样、过滤——本章歇班：立方体顶点表里的 uv 字段没人取用，颜色全部算出来；第 13 章组装世界时，贴图与光照才会合流。

法线：表面接光的姿势 ​

为什么需要第三根箭头 ​

问一个具体问题：同一个光源照过来，为什么正对它的面亮、斜对它的面暗、背对它的面黑？因为一束光泼到表面上，真正接住多少，取决于表面「迎光」的姿势——正对着摆，全接住；侧着摆，光从表面上滑过去，只接到一部分。要让着色器算这笔账，就得给每个面配一个描述姿势的数。这个数就是法线（normal）——从表面垂直戳出来的小箭头：它指向哪，表面就朝哪；它与光方向夹角多小，表面迎光就多正。

第 8 章埋的伏笔今天兑现：createCube() 的顶点表里，每面四个顶点各带一份法线，六面分别是 ±X、±Y、±Z 六根朝外的箭头，单位长度、逐顶点存好——当时只说「光照的入场券」，现在入场。为什么每面一份而不是每个角点一份，第 8 章算过账：顶点是「位置加全部逐顶点属性」的整包，角点被三面共享而法线各异，只能拆开存。

一根箭头怎么打分：N·L 复工 ​

有了姿势的箭头 N（法线）和光来的方向 L（从表面指向光源），打分交给第 4 章的点积：两个单位向量的点积，就是它们夹角的余弦——正对满分、斜着打折、垂直零分、背面负分。跟着算一遍，这是本章的承重演算，建议拿笔：

text
面正对光    N=(0,0,1)  L=(0,0,1)
  N·L = 0×0 + 0×0 + 1×1 = 1            满分，全接住
面转过去 45°（或光挪 45°，一个意思——打分只认夹角）
            N=(0,0,1)  L=(√½,0,√½)
  N·L = √½ ≈ 0.7071                     掉到七成
再转到 90° N=(0,0,1)  L=(1,0,0)
  N·L = 0                               明暗分界线，一点不接
光绕到背面  N=(0,0,1)  L=(√½,0,−√½)
  N·L = −0.7071 → max(N·L, 0) = 0       背面不发光

一个面转 45°，分数从 1 掉到 0.707——亮度跟着掉三成，立体感就来自这个连续的衰减。最后一步的 max 不是装饰：负分不是「负亮度」，是「光在背面，这面一丁点都接不到」，必须钳成 0，否则负数掺进颜色会把画面算出鬼影。

打分的另一半：法线也要跟着物体动 ​

物体转了、拉伸了，表面姿势变了，法线必须跟着变，否则打分打的是旧姿势。你大概已经想到了最直觉的做法：法线乘模型矩阵，跟顶点一起走。第 8 章的演示干脆没让法线吃任何矩阵——局部法线直传，只用来当「这张面的身份证」挑底色，错了也看不出来。下一节说为什么这个直觉做法是开章第二个坑。

拉伸的坑：法线矩阵 ​

X 拉伸 2 倍，垂直关系搬歪了 ​

模型矩阵对位置永远是对的——位置就该跟着机器走。法线不一样：它要的不是「跟着表面动」，而是「变换之后仍然垂直于变换后的表面」。这两件事在旋转和均匀缩放下恰好等价（方向要么整体转过去、要么长度变了方向不变），于是平时不出事；非均匀缩放一出，就分道扬镳。拿具体的数算——平面 x + y = 1，一张 45° 的斜面：

text
拉伸前：平面 x + y = 1，法线 n = (1,1,0)/√2 ≈ (0.707, 0.707, 0)
模型矩阵 X 拉伸 2 倍后：平面变成 x/2 + y = 1（x 方向涨了一倍）

真值法线（拉伸后平面的垂直方向）：
  normalize(0.5, 1, 0) = (1,2,0)/√5 ≈ (0.447, 0.894, 0)

错路——直接拿模型矩阵变换法线：
  M·n = (2×0.707, 0.707, 0)，归一化 → (2,1,0)/√5 ≈ (0.894, 0.447, 0)   偏向 X！
对路——逆转置矩阵变换法线：
  (M⁻¹)ᵀ·n = (0.5×0.707, 0.707, 0)，归一化 → (1,2,0)/√5 ≈ (0.447, 0.894, 0)   对了

错路的箭头偏向被拉伸的 X 轴（0.894 对 0.447），与真值的夹角余弦只剩 0.8——约 36.87°，恰是 3-4-5 三角形那个角（cos = 4/5）。偏了这么多还拿去打分，明暗自然出现在不该出现的地方。直观账：X 拉伸把斜面的坡度压缓了，真值法线应该更竖、更不偏 X；直接乘模型矩阵却把它往 X 方向拉——方向反了。

逆转置：专门搬「垂直关系」的机器 ​

能保持垂直关系的矩阵，数学上可以推导出来。法线 n 与表面内任意切线 t 垂直，即点积 n·t = 0；变换后切线变成 M₃t（M₃ 是模型矩阵左上 3×3，位置才需要第 4 列的平移，方向不需要）。想找一个矩阵 K 让 Kn 始终垂直于 M₃t：(Kn)·(M₃t) 化开是 n·(KᵀM₃t)——Kᵀ 读「K 的转置」，即行列互换后的 K。只要 KᵀM₃ 是单位阵的倍数，括号里至多是 t 的常数倍，与 n 的点积照样是 0。解出来 K = (M₃⁻¹)ᵀ——模型矩阵 3×3 部分的逆、再转置，简称逆转置。它就是法线矩阵（normal matrix）。给想较真的读者一句话直觉：逆是把拉歪的表面搬回原位的机器，转置再把「垂直」的读数对回新表面；先撤后对，垂直就保住了。

两个好消息让它用起来不贵。其一，纯旋转下 (R⁻¹)ᵀ = R——旋转矩阵的逆就是转置，再转置转回来，法线矩阵就是模型矩阵本身；均匀缩放下结果是旋转除以缩放倍数，归一化后与模型矩阵殊途同归。换句话说：物体不拉伸时，直接乘模型矩阵根本不会出错——这就是这个坑能潜伏多年的原因。其二，平移完全不吃进来：法线是方向不是位置，齐次坐标里方向补 w=0，第 4 列的平移量对它无效——搬桌子不转姿势。

实现落在 mat4 上。数学还有个一步到位的化简，值得单独讲。A⁻¹ = adj(A)/det——伴随矩阵除以行列式；而伴随又是余子式矩阵的转置——余子式即删掉所在行与列后剩下的 2×2 小行列式，一共九个。逆转置两边再取转置，两个「转置」互相抵消：答案恰好是余子式矩阵直接除以 det。九个余子式各除一次就完事，不必先造完整逆再转置。首次登场，全貌如下：

ts
// src/math/mat4.ts · normalFromMat4
export function normalFromMat4(m: Mat4): Mat4 {
  // 左上 3×3 按数学习惯命名：a_{row}{col}，列主序下 a_{rc} = m[c*4+r]
  const a11 = m[0]
  const a12 = m[4]
  const a13 = m[8]
  const a21 = m[1]
  const a22 = m[5]
  const a23 = m[9]
  const a31 = m[2]
  const a32 = m[6]
  const a33 = m[10]
  // 行列式（按第一行展开）
  const det =
    a11 * (a22 * a33 - a23 * a32) -
    a12 * (a21 * a33 - a23 * a31) +
    a13 * (a21 * a32 - a22 * a31)
  // 逆转置 = 余子式矩阵 ÷ det：out[c*4+r] = C_{rc}/det
  const out = new Float32Array(16)
  out[0] = (a22 * a33 - a23 * a32) / det
  out[4] = -(a21 * a33 - a23 * a31) / det
  out[8] = (a21 * a32 - a22 * a31) / det
  out[1] = -(a12 * a33 - a13 * a32) / det
  out[5] = (a11 * a33 - a13 * a31) / det
  out[9] = -(a11 * a32 - a12 * a31) / det
  out[2] = (a12 * a23 - a13 * a22) / det
  out[6] = -(a11 * a23 - a13 * a21) / det
  out[10] = (a11 * a22 - a12 * a21) / det
  out[15] = 1
  return out
}

出口是 Mat4 形状（左上 3×3 装法线矩阵、右下角 1、其余 0），可以直接喂 uniformMatrix4fv。两个约定写在 JSDoc 里：出口的列不必是单位长度（均匀缩放会整体乘一个常数），所以着色器里照例再 normalize 一次；det 为 0 的退化矩阵（某轴缩放为 0）会除零产出废数值，不抛异常——与 normalize 收零向量返回零向量同一档处理，调用方保证模型矩阵可逆。

Phong 三件套：环境光、漫反射、高光 ​

姿势的分数有了，剩下的把它变成颜色。1975 年裴祥风（Bui Tuong Phong）提出的光照模型把表面亮度拆成三个分量，各管一种物理现象，合起来就叫 Phong 光照模型。它不是物理精确的（真实世界远比它复杂），但它便宜、直觉、效果像样——教科书到引擎至今都在用它的直系后代。

环境光：阴天兜底 ​

三件套最便宜的一件。只用漫反射的话，背光面 N·L 钳成 0，纯黑——可现实里背阴的墙也不是全黑：天空、地面、邻居的窗户都在反光，从四面八方漏来一点。环境光（ambient light）就是这笔账的极简近似：不问方向、全场一视同仁，给所有表面垫一个底亮度。公式一行：ambient = ambientStrength，强度通常给 0.1 上下——兜底而已，给大了画面发灰。

漫反射：哑光墙面 ​

墙面、纸张、水泥地这类粗糙表面，把打来的光向四面八方弹开，哪个方向看都一样亮——亮度只取决于接光多少，正是 N·L 打的分。这就是漫反射（diffuse reflection）：diffuse = max(N·L, 0)。开章那张「六个面一模一样」的立方体，缺的就是这一项；有了它，正对光的面最亮、斜面按余弦衰减、背面只剩环境光垫底。

高光：光滑塑料的反光斑 ​

塑料、瓷器、车漆这类光滑表面还有一招：朝某个方向镜面式地弹出一团亮斑，你一移动视线，亮斑跟着滑。这是高光（specular highlight）。方向怎么定：把光来的方向 L 关于法线弹出去得到反射方向 R——GLSL 内建 reflect(I, N) 的公式是 I − 2·dot(N,I)·N（I 是指向表面的入射方向；规范原文如此，N 必须先归一化）；光照里喂 reflect(−L, N)，得 R = 2(N·L)N − L。然后问「视线 v 与 R 对齐吗」：对齐就亮，偏开就暗，且用幂次压尖——pow(max(R·v, 0), shininess)。shininess 是光洁度：越大斑越小越锐，从巴掌大到针尖全靠这一个数。跟着算一遍尖的程度：偏离角使得 dot(R, v) = √½ 时，shininess = 8 得 (√½)⁸ = 1/16，还看得见；shininess = 64 得 (√½)⁶⁴ = 2⁻³²，约等于零——同一个偏离角，幂一高就掐灭，这就是「针尖」。

三件套合流，量程收拢 ​

三个分量加起来是亮度：intensity = ambient + diffuse + specular。会超界吗？会——正对光且视线对准反光斑时 0.2 + 1 + 1 = 2.2。超界的亮度写进普通的 8 位帧缓冲时会被摁回 [0,1] 再转成字节，这是规范写死的行为（定点帧缓冲只装得下这个量程）；所以 CPU 版显式收拢，与着色器殊途同归。实验场的新模块 src/light/phong.ts 就是这套公式的 CPU 参考实现，设计目标只有一条：与 GLSL 着色器逐行同形，让每个数都能在 Node 里对账。三个零件先出场：

ts
// 拼版（src/light/phong.ts 三个零件连排，函数体与仓内逐字一致，函数间 JSDoc 省去）
export function reflect(i: Vec3, n: Vec3): Vec3 {
  return add(i, scale(n, -2 * dot(n, i)))
}

export function diffuse(n: Vec3, l: Vec3): number {
  return Math.max(dot(n, l), 0)
}

export function specular(n: Vec3, l: Vec3, v: Vec3, shininess: number): number {
  const r = reflect([-l[0], -l[1], -l[2]], n)
  return Math.pow(Math.max(dot(r, v), 0), shininess)
}

合流的入口，全貌如下：

ts
// src/light/phong.ts · computePhong
export function computePhong(
  n: Vec3,
  l: Vec3,
  v: Vec3,
  shininess: number,
  ambientStrength: number,
): PhongComponents {
  const amb = Math.max(ambientStrength, 0)
  const dif = diffuse(n, l)
  const spe = specular(n, l, v, shininess)
  return {
    ambient: amb,
    diffuse: dif,
    specular: spe,
    intensity: Math.min(Math.max(amb + dif + spe, 0), 1),
  }
}

约定与着色器完全一致：n、l、v 一律传单位向量——n 是法线、l 从表面指向光源、v 从表面指向眼睛。手算一笔验货：N = (0,0,1)、L = (√½,0,√½)、视线正对 V = (0,0,1)、shininess = 32、环境光 0.1——漫反射 √½ ≈ 0.7071；反射方向 R = (−√½,0,√½)，dot(R,V) = √½，高光 (√½)³² = 2⁻¹⁶ ≈ 0.0000153；总和 ≈ 0.8071，正好落在量程内。这一笔就是测试里的对账数，等下还要回来。index.ts 照例 re-export：computePhong、diffuse、specular、reflect 与类型 PhongComponents。

GPU 上的同形对照 ​

着色器版长什么样？演示组件 DemoPhong 的片元着色器，与上面四个函数逐行对得上：

glsl
// 用法示例（DemoPhong 演示同款片元着色器；强度系数全拨到 1 时与 src/light/phong.ts 逐行同形）
precision mediump float;                    // 精度限定符：第 3 章立的规矩
varying vec3 v_normal;                      // 可变变量：法线从顶点插值而来
varying vec3 v_worldPos;                    // 表面位置：算 l 和 v 都要用它
uniform vec3 u_lightPos;                    // 统一变量：光源位置（世界坐标）
uniform vec3 u_cameraPos;
uniform vec3 u_baseColor;                   // 物体基础色
uniform float u_ambient;                    // 环境光强度（滑杆）
uniform float u_diffuseK;                   // 漫反射强度系数（滑杆）
uniform float u_specularK;                  // 高光强度系数（滑杆）
uniform float u_shininess;                  // 光洁度（滑杆）
void main() {
  vec3 N = normalize(v_normal);             // 插值会缩短向量——先归一化补回
  vec3 L = normalize(u_lightPos - v_worldPos);
  vec3 V = normalize(u_cameraPos - v_worldPos);
  float diff = max(dot(N, L), 0.0) * u_diffuseK;         // = diffuse(N, L) 再乘强度
  vec3 R = reflect(-L, N);                  // = reflect(−L, N)
  float spec = pow(max(dot(R, V), 0.0), u_shininess) * u_specularK;  // = specular(...) 再乘强度
  vec3 color = u_baseColor * (u_ambient + diff) + spec * vec3(1.0);
  gl_FragColor = vec4(color, 1.0);          // 超 [0,1] 的亮度写入时被摁回量程
}

同一行公式，两个世界各跑一份：CPU 这份可以被 vitest 断言、被纸笔复算；GPU 那份跑得飞快，装进你的画布。对账的底气就在「同形」两个字。

为什么在片元着色器算，不在顶点着色器算 ​

有个省事的诱惑：法线和位置都在顶点着色器手里，光照也在那里算一次，把亮度当可变变量传下去插值，不就省了逐片元的计算？这个做法有名字（Gouraud 着色），历史上的确用过，但它有个肉眼可见的破绽：高光斑比三角形小的时候整个消失——三个顶点都没踩中亮斑，插值只能插出三个暗数。根子在插值本身：可变变量是线性插值，插的是数值、不是方向。

还有一笔账要算给法线自己。顶点着色器送出的法线是单位向量，但插值是逐分量加权平均：两个顶点的法线分别是 (1,0,0) 与 (0,1,0)，片中点的插值是 (0.5, 0.5, 0)，长度 √½ ≈ 0.707——不是 1，而且角度越岔、缩得越短。拿缩短的 N 去打分，分数整体偏低，画面变暗还不均匀。修法便宜：片元着色器里 normalize 一次，长度补回 1，方向本来就没错。逐片元算光照比查表贵几个乘法，但离 16.7 毫秒的帧率预算还远，谈不上掉帧——光栅化后的三角形本来就是逐片元的活，这笔预算 GPU 出得起。换来的是每个格子拿到自己的法线、自己的打分——立方体六个面差六个亮度，球面亮暗连续过渡，立体感这才真正长出来。

渐进实验：两件新家当进仓 ​

本章的实验场增量有两件。第一件是 mat4 的 normalFromMat4，上面已贴全貌；测试用手算锁它：纯旋转下 rotY(90°) 把 +X 法线转到 −Z（与第 5 章旋转测试同一笔账）；平移不吃进去（先 translate 再缩放旋转，法线矩阵与不 translate 时逐元素相等）；均匀缩放下各列归一化后与模型矩阵殊途同归；X 拉伸 2 倍的 45° 斜面，逆转置归一化后与几何真值重合、直接乘模型矩阵则差出 cos = 0.8 的夹角。

第二件是 src/light/phong.ts。为什么 CPU 上再写一遍光照？着色器跑在 GPU 里，断言和纸笔都够不着；把同一组公式搬进 TypeScript，45° 的 0.7071、高光的 2⁻¹⁶、量程收拢的 2.2→1，全部变成机器可查的数。演示组件与第 13 章组装世界时的光照接线，都拿它当原理基准。

球体是本章演示的新道具，几何在组件内联生成——用法示例性质，不进实验场。经纬细分：按纬度切 12 圈、经度切 16 片，格点坐标用球面参数方程 (cosφ·sinθ, cosθ, sinφ·sinθ) 算出，索引绘制连成三角带。它有个立方体给不了的好处：球面上每个顶点的法线就是顶点位置本身归一化（球心在原点，半径方向即垂直方向），明暗过渡连续，高光斑走到哪看得一清二楚。

Phong 三件套合流：环境光垫底、漫反射按 N·L 打分、高光按对齐度取幂——挪动光源，明暗分界线跟着走

演示是一颗立方体加一颗球，还有一颗亮黄小方块标记的光源。它是点光源——光有位置、每个格子各自朝它量方向；方向光是它推到无穷远的极限（方向处处一样），开章的两笔坑两种光都成立。玩法按这笔账走：

  • 拖光源的方位角、仰角、半径滑杆：光绕着物体走，看明暗分界线跟着转——正对光的亮、斜面的按余弦暗下去、背面只剩环境光。立方体六个面从此六个亮度。
  • 三件套各有关掉开关：只留漫反射是哑光石膏；关漫反射开高光是玻璃弹珠的怪感；关到只剩环境光，整个物体糊成一张剪影——三项各自的贡献一目了然。
  • shininess 从 2 拉到 256：高光从巴掌大的一团摊开，收成针尖大的一点亮——同一颗球，从石膏变成抛光塑料。
  • 勾上「法线可视化」：线框加法线小箭头叠加显示，光源挪动时看箭头与光方向的夹角，正对时箭头顶着光、亮；岔开时按余弦暗。
  • 复刻痛点的一手：把 X 拉伸滑杆拉到 2，然后勾上「法线吃错矩阵」（法线改吃模型矩阵）。球的明暗立刻开始撒谎——尤其是被拉伸的腰部，亮区偏移、暗面渗光；取消勾选，明暗回到与几何吻合。再开「法线可视化」，两根错对的箭头肉眼可见。X 拉伸滑回 1，两种算法的差异消失——坑只在非均匀缩放下露头，正如正文推的账。

验证：手算对账，门槛背书 ​

两道门槛在 companion/ 下跑：pnpm run typecheck 加 pnpm test——94 条断言全绿，旧 85 条一字未动，新 9 条是本章里程碑。手算挑几笔：45° 入射的漫反射 = cos45° = √½（测试直接与 Math.SQRT1_2 对账）；视线对准反射方向时高光 = 1，偏离后 shininess = 8 得 1/16、shininess = 64 得 2⁻³²，大幂更尖；三件套叠加正对光 0.2 + 1 + 1 = 2.2 收拢到 1，全背光只剩 0.2。非均匀缩放那条测试值得整段看——它把开章第二个坑原样写成了断言。

ts
// tests/lighting.test.ts · 非均匀缩放的必要性（X 拉伸 2 倍，45° 斜面法线手算对账）
  it('非均匀缩放的必要性：X 拉伸 2 倍，45° 斜面法线手算对账', () => {
    // 原平面 x + y = 1 的法线 n = (1,1,0)/√2；模型矩阵 X 拉伸 2 倍后
    // 平面变成 x/2 + y = 1，几何真值法线 = normalize(0.5, 1, 0) = (1,2,0)/√5
    const M = scale(2, 1, 1)
    const n: readonly [number, number, number] = normalize([1, 1, 0])
    // 错路：直接拿模型矩阵变换法线再归一化 → (2,1,0)/√5——偏了
    const wrong = normalize(transformPoint(M, n))
    expect(wrong[0]).toBeCloseTo(2 / Math.sqrt(5), 4)
    expect(wrong[1]).toBeCloseTo(1 / Math.sqrt(5), 4)
    // 对路：逆转置 = diag(0.5, 1, 1) 变换再归一化 → (1,2,0)/√5——与真值一致
    const right = normalize(transformPoint(normalFromMat4(M), n))
    expect(right[0]).toBeCloseTo(1 / Math.sqrt(5), 4)
    expect(right[1]).toBeCloseTo(2 / Math.sqrt(5), 4)
    const truth = normalize([0.5, 1, 0])
    expect(dot(right, truth)).toBeCloseTo(1, 4) // 逆转置与几何真值重合
    expect(dot(wrong, truth)).toBeCloseTo(0.8, 4) // 错路与真值夹角 cos=4/5（≈36.87°，3-4-5 的角）
    expect(length(transformPoint(normalFromMat4(M), n))).toBeCloseTo(
      Math.sqrt(0.625),
      4,
    ) // 逆转置出口长度 √(1/8+1/2)——没归一化，着色器里还要 normalize
  })

先红复刻一把（实际跑过的账）：把 diffuse 里的 Math.max 摘掉，只留 dot(n, l)——跑 pnpm test，「光在背面漫反射为 0」那条当场红，期望 0、实际 −1。max 不是装饰，是公开承诺的一部分：背面不发光。改回来，绿。再把 normalFromMat4 里的行列式 det 换成 1（假装它是单位阵），X 拉伸那条红——逆转置除以 det 那一步不能省。改回来，全绿。

小结 ​

本章让颜色从「查表查来」变成「算出来」。法线是从表面垂直戳出来的小箭头，描述表面接光的姿势；打分交给第 4 章的点积——N·L 一出，正对满分、45° 七成、垂直零分、背面钳 0。法线的变换不能偷懒吃模型矩阵：非均匀缩放会把垂直关系搬歪，X 拉伸 2 倍时 45° 斜面的法线偏出 cos = 0.8 的夹角；要保垂直只能走逆转置——normalFromMat4 用「余子式矩阵除以行列式」一步到位，纯旋转与均匀缩放下它退化成模型矩阵本身，平移永远不吃进来。Phong 三件套各管一层物理：环境光无方向兜底、漫反射按 N·L 打哑光墙面的分、高光按反射方向与视线的对齐度取幂出反光斑；三件相加收拢进 [0,1]，与 8 位帧缓冲的量程对齐。光照在片元着色器里逐格子算——插值会把法线缩短（(1,0,0) 与 (0,1,0) 的中点只剩 0.707 长），normalize 补回，高光斑才不丢。实验场进账两件：mat4.normalFromMat4 与 light/phong 的 CPU 参考，测试总数 94。读者已能解释「六个面一模一样」与「拉伸后明暗错位」两笔账，并把 Phong 三件套在纸笔上复算出来。
