可操控的相机：轨道与漫游 ​

上一章的场景树搭好了，太阳系转得像模像样——但你受够了用滑杆看它。这周的新需求很朴素：给画布加上拖拽旋转和滚轮缩放。你给 mousemove 写了两行增量：横向位移加进一个角度、纵向位移加进另一个角度，再把两个角度乘进相机的姿态。第一次拖没问题，转着转着不对劲了：水平拖过 180° 之后，垂直拖动，画面开始朝反方向转——你想抬头，画面偏偏低头。滚轮那边更直接：想「离远点」，你直接把 eye 的 z 坐标减一截，结果相机不后退，径直扎进场景里，方块从脸中间穿过去。两个 bug 同一个病根：把相机姿态当成「可以一点点叠加的量」在改。姿态一叠加，转过的方向就开始反过来咬你。这一章把姿态还原成「每次从角度现造的量」：轨道与漫游两台相机，一次把拖拽、滚轮、WASD 全部接对。

出发前清点：三要素之后的空位 ​

数学侧全员复工：向量、点积、叉积、归一化、单位向量——第 7 章 lookAt 造 f/s/u 三根正交基用的就是这套家伙什，今天同一套手艺换个出发点再来一遍；向量投影有一场客串（漫游相机想贴地走时，把 forward 压平靠它）。矩阵家族的纪律今天从「变换物体」搬到「转头点头」上再演一遍：矩阵乘法从右往左作用、顺序不可交换；列主序、齐次坐标照旧值班。三台机器各就各位：模型矩阵由场景树的局部矩阵链乘出世界矩阵结算；视图矩阵是今天的主角——lookAt 的三要素 eye/center/up 要开始接收拖拽与键盘的输入；透视投影与正交投影两台镜头不动，视锥体、透视除法、宽高比、裁剪坐标系的账都照旧。管线侧：顶点着色器、光栅化、片元着色器三段接力，GPU 吃重复计算，帧率预算 16.7 毫秒的账照记——两块画布各一个 WebGL 上下文，本章这点绘制量离掉帧很远。缓冲区与顶点属性一动不动（改的是「眼在哪」，不是「坐标怎么传」）；统一变量继续每帧喂 MVP；演示里的颜色这回再走一趟可变变量——顶点侧的面色沿片元插值过去。渲染循环与增量时间给键盘移动定步长：按住 W 一秒走三格，帧率不匀也等速；线性插值与缓动、精度限定符照旧带着。深度缓冲与深度测试给演示的实心方块把关遮挡；索引绘制、缠绕方向、背面剔除今天歇班（演示用 drawArrays 画方块就够了）。纹理一套（UV 坐标、纹素、采样、过滤）和光照一套（法线、法线矩阵、环境光、漫反射、高光）都歇班——先把相机的账算干净，场景素颜上班；第 13 章组装世界时它们和相机同框。场景图的树原样挂在仓里。

清点完发现一个空位：第 7 章教了「三要素怎么变成视图矩阵」，没教「三要素从哪来」。当时靠滑杆手填，交互一上手，滑杆就不够用了。本章进仓一个小模块：scene/camera，两个纯函数 orbitEye 与 viewBasis——名字先立此存照，原理讲完再见面。

轨道相机：绕着雕塑走一圈 ​

查看一个物体有两种姿势。第一种：物体不动，你绕着它走——看雕塑、看 3D 模型、看商品三维图时干的都是这件事。轨道相机（orbit camera）就是这种姿势的代码化——相机绕着目标点沿球面转圈的查看方式。像美术馆里绕雕塑走一圈：你到雕塑的距离大体不变，变的只是站在哪个方向、蹲多低。

球坐标：三个数定一个眼位 ​

绕着走的时候，「眼在哪」怎么记？直接记世界坐标 (x, y, z) 也能用，但拖拽的输入天然是角度——横向拖一下，意思是「绕过去一点」；纵向拖一下，意思是「抬高一点」。顺着输入的形状记状态，就是球坐标（spherical coordinates）——不用 x/y/z，改用「转到哪边、抬多高、离多远」定位一个点的坐标法：

  • 方位角：绕 Y 轴转过的角度。0° 眼在 +Z 一侧，90° 转到 +X 一侧——手性（旋转的正方向朝哪边转的约定）与第 5 章右手定则下 rotY 的正方向一致；
  • 极角：从 +Y 轴量起的角度。0°＝正头顶，90°＝贴地平视，180°＝正脚下；
  • 半径：眼到目标点的距离。
text
 侧视（站在 +X 往 -X 看）——极角管「抬多高」：

        +Y 极轴
        │       ● eye（离地高度 = r·cos p）
        │     ╱ │
        │   r ╱  │ r·sin p（水平距离）
        │   ╱    │
        ●───────┴────── 水平面（p = 90° 时眼贴地：高度 0）
      target（球心，固定，交给 lookAt 当 center）
text
 俯视（从 +Y 往下看）——方位角管「转到哪边」：

        +Z（a = 0°）
         │ ﹨
         │   ﹨  a 从 0° 涨到 90°，眼沿圆弧从 +Z 侧扫到 +X 侧
         │     ●   a = 45°：水平朝向 (0.707, 0, 0.707)
         │   ﹨
         │ ﹨
         ●──────────── +X（a = 90°）
       target

换成公式一行：eye = target + r·(sin p·sin a, cos p, sin p·cos a)。三个数各管一根弦：cos p 管高度，sin p 管水平分量，sin a 和 cos a 再把水平分量分给 x 和 z。跟着算三笔（测试逐位对账的就是它们）：

text
orbitEye(0°, 90°, 5)：高度 5·cos90° = 0，水平距 5·sin90° = 5，a = 0° 水平朝 +Z
  → eye = (0, 0, 5)       贴地站在 +Z，平视原点
orbitEye(90°, 90°, 5)：a = 90°，水平朝 (sin90°, cos90°) = (1, 0)，即 +X
  → eye = (5, 0, 0)       绕到了 +X 一侧
orbitEye(0°, 60°, 4)：高度 4·cos60° = 2，水平距 4·sin60° = 2√3 ≈ 3.464
  → eye = (0, 2, 3.464)   抬高了两格

为什么球坐标不怕拖过 180° ​

开章的翻车，病根是「姿态被累积」。拿球坐标记轨道相机，这笔坏账根本立不起来：状态只有三个数，眼位每帧从三个数现造——这一帧拖了多少，只改角度、重建眼位，上一帧的姿态从来不掺和。水平拖过 180°、360°、720° 都一样：方位角就是个数字，绕一圈回到原地，三角函数天然周期，方向永远攒不出错。

极角倒是有一个不能去的地方：极点。第 7 章算过这笔账——相机飞到正头顶往下看，up=(0,1,0) 与视线平行，cross 归零、lookAt 退化、画面消失。所以 orbitEye 把极角收拢进 [1°, 90°]：下界离极点留 1°，眼位最高到「差一度正头顶」；上界 90°＝贴地——场景的地面底下没有可看的东西，拖过头就贴着地滑，钻不下去。收拢的活交给第 3 章的 clamp，一行。方位角不收拢：它没有禁区。

滚轮：半径的活，不是眼位的活 ​

缩放的正确记账也顺带解决。想「离近点看」，球坐标里改的是半径：r 从 10 缩到 6，眼位沿「从 target 指向 eye」的同一根线滑向 target——沿视线方向进退是球坐标自动送的行为，不用单独算方向。开章那个扎进场景的 bug，错在直接改眼位的某个分量：eye 的 z 减一截，动的是世界 -Z 方向，与相机朝哪无关。这笔账全看相机此刻站在哪：初始位（+Z 侧）z 减一截是径直扎进方块；转到侧面（±X 侧）变成横着挪，远近根本没变；转到对面（−Z 侧）又碰巧变成径直退出去——同一个手势三种结果。半径是个距离，天生没有方向可错；滚轮只跟它打交道。

漫游相机：站在场景里走 ​

第二种查看姿势：你不绕着场景走，你站在场景里面。漫游相机（walk camera）——站在场景里边走边看的相机：眼睛一米六，WASD 迈步，拖拽转头。它比轨道相机多一本账：轨道相机里「眼在哪」由三个球坐标数唯一决定；漫游相机里位置和朝向是两本独立的账——朝向一本（拖拽管），位置一本（键盘管），各有各的输入，互不顶替。

朝向：两个角，转头加点头 ​

朝向只需要两个角，名字都是从飞机借来的：

  • 偏航角（yaw）——左右转头的角度：绕世界 Y 轴转，正方向与第 5 章 rotY 一致（右手定则）。yaw=90°＝从初始朝向向左转四分之一圈；
  • 俯仰角（pitch）——上下点头的角度：抬头为正、低头为负。正负 90° 是「正头顶/正脚下」，基向量在那里退化，收拢进 ±89°——道理与轨道的极角收拢同一条。

站在原点、yaw=0、pitch=0 时相机朝哪？第 7 章立过规矩：相机默认站在原点朝 -Z 看。所以 forward（画面深处的方向）初始是 (0,0,-1)，right（右手边）是 (1,0,0)，up（头顶）是 (0,1,0)。

本章的承重演算来了：yaw 转到 90°、pitch 归零，forward 指向哪？拿第 5 章的账本手算——rotY(90°) 把 +Z 转到 +X，也把 -Z 转到 -X，于是 forward = R_y(90°)·(0,0,-1) = (-1, 0, 0)：朝 -X 看。再补两根：right = normalize(cross(forward, (0,1,0)))，手算 (-1,0,0)×(0,1,0) = (0,0,-1)——面朝 -X 时右手边是 -Z；up = cross(right, forward) = (0,1,0)，头还正着。两个角度怎么合成这一根 forward？顺序是关键，下一节算给你看。

组合顺序：先点头后转头，换不得 ​

两个角合出一根 forward，直觉写法是让两次旋转接力。第 5 章的纪律在这儿等着：旋转的先后不可交换。拿最容易看出差距的一组角度（yaw=90°、pitch=90°）把两种顺序都算一遍：

text
先 pitch 后 yaw（本书固定顺序 R_y(yaw)·R_x(pitch)，坐标先过右边的 R_x）：
  (0,0,-1) ─R_x(90°)→ (0,1,0)     先在初始朝向上抬头，看向正上方
  (0,1,0)  ─R_y(90°)→ (0,1,0)     绕 Y 转头不带动竖直方向
  forward = (0, 1, 0)              朝天

先 yaw 后 pitch（反序 R_x(pitch)·R_y(yaw)，坐标先过右边的 R_y）：
  (0,0,-1) ─R_y(90°)→ (-1,0,0)    先转身朝 -X
  (-1,0,0) ─R_x(90°)→ (-1,0,0)    rotX 只混 y、z 两根轴，x 纹丝不动
  forward = (-1, 0, 0)             朝 -X

同一对角度，一个朝天、一个朝 -X——顺序一换，答案分道扬镳。两种顺序各对应一种「绑法」：固定序里 yaw 绑在世界的 Y 轴上，pitch 绑在转身之后自己的额头上——转过身，点头方向跟着转身走；反序里 pitch 绑在世界的 X 轴上——转了身，脖子还留在原地。开章的翻车正是反序的账：yaw=180°（面向 +Z）时再「抬头」，forward = R_x(p)·(0,0,1) = (0, -sin p, cos p)，pitch 为正、y 分量却为负——你拖「抬头」，画面朝下。再配上 up 跟着歪，画面整个斜过去。修法只有一句话：固定一个顺序，每帧从 (yaw, pitch) 现造 forward——角度是唯一的状态，矩阵是角度的临时投影。这句话你在第 11 章「每帧重建 local」里见过同一个骨架。

相机基向量与移动：沿自己的轴走 ​

朝向定了，移动的账还差一步。按 W 的意思是「朝画面深处走」——但画面深处是世界哪个方向？yaw=0 时是 -Z，yaw=90° 时是 -X，转个头答案就变。键盘只知道「前」和「右」，它不知道世界轴。所以移动不能沿世界的 x/y/z 算，要沿相机自己的三根轴——相机基向量（camera basis）：forward（画面深处）、right（右手边）、up（头顶），两两垂直、各自单位长。第 7 章 lookAt 里的 f/s/u 就是同一套东西，手艺一道没换——那里从「眼到目标」现造，这里从 yaw/pitch 现造。

有了基向量，移动是一行账：W 前进 = eye + forward·step，S 后退 = eye − forward·step；D 右移 = eye + right·step，A 左移反过来。step 用增量时间缩放。斜走（W 与 D 同按）就是基向量上的线性叠加：

text
eye' = eye + forward·2 步 + right·1 步

yaw = 0 时：  (0,0,0) + (0,0,-2) + (1,0,0)  = (1, 0, -2)
yaw = 90° 时：(0,0,0) + (-2,0,0) + (0,0,-1) = (-2, 0, -1)

同一串按键，转身前后走出的对角线方向不同——步数不变，基向量换了。这就是「斜着走的人不沿经纬线爬」：朝东北走的人一步迈在对角线上，不是先爬完南北再爬东西。forward 与 right 严格垂直（点积为 0，测试有断言），两路步子叠加才不会互相串味。

一个诚实的边界说明：这样移动严格沿基向量，抬着头按 W 会带你离地（fly 风格，演示里就是这样）。想要贴地行走，把 forward 的 y 分量清零再归一化即可——第 4 章压平向量那套活，本章不展开。

渐进实验：scene/camera 进仓 ​

老规矩，测试先行。tests/camera-controls.test.ts 写好 14 条断言，此刻 scene/camera 还不存在。跑 pnpm test 一片红：Failed to load url ../src/scene/camera——渐进语义的机械证明。实现之后逐条转绿，先看两条承重断言的真身。

/** 轨道极角上界：90°＝贴地平视——地面底下没有可看的东西，拖过头就贴着地滑。 */
export const ORBIT_POLAR_MAX_DEG = 90
/** 俯仰角界限：±89°，离正头顶/正脚下各留 1°——forward 竖直时 cross(forward, 上) 归零、基向量退化。 */
export const PITCH_LIMIT_DEG = 89

/**
 * 球坐标 → 轨道眼位：给定方位角、极角、半径与轨道中心（target），算出
 * 相机站在球面上哪一点。target 原样交给 lookAt 当 center，up 照旧
 * (0,1,0)——第 7 章的机器一行不用改。
 *
 * 角度用度数，约定（手性与第 5 章 rotY 一致）：
 * - 方位角 azimuthDeg 绕 Y 轴：0°＝站在 +Z 一侧，90°＝转到 +X——
 *   eye = target + r·(sin p·sin a, cos p, sin p·cos a)；
 * - 极角 polarDeg 从 +Y 量起：0°＝正头顶，90°＝贴地平视，180°＝正脚下。
 *
 * 极角越界收拢进 [1°, 90°]（clamp 的活）：下界离极点留 1°——极点上
 * up 与视线平行，lookAt 退化；上界 90°＝贴地，轨道场景的地面底下没有
 * 可看的东西。方位角不收拢：绕一圈回到原地，三角函数天然周期。半径
 * 不收拢：缩放边界（最小/最大距离）是场景设计决定，由调用方负责。
 *
 * 手算样例（tests/camera-controls.test.ts 逐位对账）：
 *   orbitEye(0°, 90°, 5)  = (0, 0, 5)        贴地站在 +Z，平视原点
 *   orbitEye(90°, 90°, 5) = (5, 0, 0)        方位角转到 +X
 *   orbitEye(0°, 60°, 4)  = (0, 2, 3.464)    y=4·cos60°、z=4·sin60°
 *   orbitEye(0°, 0°, 5)   = (0, 4.9992, 0.0873)  极角收拢到 1°
 *   orbitEye(0°, 90°, 3, [1,2,3]) = (1, 2, 6)  target 平移整颗球
 */
export function orbitEye(
  azimuthDeg: number,
  polarDeg: number,
  radius: number,
  target: Vec3 = [0, 0, 0],
): Vec3 {
  const azimuth = (azimuthDeg * Math.PI) / 180
  const polar = (clamp(polarDeg, ORBIT_POLAR_MIN_DEG, ORBIT_POLAR_MAX_DEG) * Math.PI) / 180
  return [
    target[0] + radius * Math.sin(polar) * Math.sin(azimuth),
    target[1] + radius * Math.cos(polar),
    target[2] + radius * Math.sin(polar) * Math.cos(azimuth),
  ]
}

再看漫游这一半：CameraBasis 类型与 viewBasis 全貌。

ts
// src/scene/camera.ts · 漫游半边：CameraBasis 与 viewBasis（函数体与仓内逐字一致）
/** 相机基向量：两两垂直、各自单位长的前/右/上——相机的三根轴在世界里的读数。 */
export interface CameraBasis {
  /** 画面深处的方向（视线）：W/S 沿它走，lookAt 的 center 由 eye+forward 得到。 */
  forward: Vec3
  /** 相机右手边的方向：D/A 沿它走。 */
  right: Vec3
  /** 相机头顶的方向：喂给 lookAt 当 up（已经扶正，与 forward 严格垂直）。 */
  up: Vec3
}

/**
 * yaw/pitch → 相机基向量：forward（画面深处）、right（右手边）、up（头顶）
 * 三根两两垂直的单位向量。漫游相机的朝向与移动全从它们出发：
 * lookAt(eye, eye+forward, up) 出视图矩阵，W/S 沿 forward、D/A 沿 right。
 *
 * 角度用度数，两个角各管一个动作：
 * - 偏航角 yawDeg——左右转头：绕世界 Y 轴，正方向与第 5 章 rotY 一致
 *   （右手定则，俯视时逆时针；yaw=90° 后 forward 从 -Z 转到 -X）；
 * - 俯仰角 pitchDeg——上下点头：抬头为正、低头为负。
 *
 * 组合顺序固定「先 pitch 后 yaw」：forward = R_y(yaw)·R_x(pitch)·(0,0,-1)
 * ——坐标先过 R_x（在初始朝向 -Z 上点头），再过 R_y（整体转头）；等价
 * 的读法是 yaw 住世界 Y 轴、pitch 住转身之后自己的额头。顺序换了结果
 * 就变（R_y·R_x ≠ R_x·R_y）：把 pitch 放到外层＝点头住世界 X 轴，转身
 * 180° 后再「抬头」画面反而朝下——拖拽翻车的账就在这一步。固定顺序、
 * 每帧从 (yaw, pitch) 现造 forward，两个角就永远不会互相搅局。
 *
 * right = normalize(cross(forward, (0,1,0)))、up = cross(right, forward)
 * ——与第 7 章 lookAt 造 f/s/u 同一套手艺，只是这里从角度出发、lookAt
 * 从目标点出发。俯仰角收拢进 ±89°（clamp 的活）：离正头顶/正脚下各留
 * 1°，否则 forward 竖直、cross 归零，基向量退化——与 orbitEye 的极角
 * 收拢同理。yaw 不收拢：绕一圈回原方向。
 *
 * 手算样例（tests/camera-controls.test.ts 逐位对账）：
 *   viewBasis(0°, 0°)   forward=(0,0,-1)、right=(1,0,0)、up=(0,1,0)
 *   viewBasis(90°, 0°)  forward=(-1,0,0)、right=(0,0,-1)、up=(0,1,0)
 *   viewBasis(0°, 30°)  forward=(0, 0.5, -0.866)——pitch 上抬、y 分量为正
 */
export function viewBasis(yawDeg: number, pitchDeg: number): CameraBasis {
  const yaw = (yawDeg * Math.PI) / 180
  const pitch = (clamp(pitchDeg, -PITCH_LIMIT_DEG, PITCH_LIMIT_DEG) * Math.PI) / 180
  // 先 pitch 后 yaw 的固定顺序（见 JSDoc）：yaw 住世界 Y、pitch 住额头。
  const forward: Vec3 = [
    -Math.cos(pitch) * Math.sin(yaw),
    Math.sin(pitch),
    -Math.cos(pitch) * Math.cos(yaw),
  ]
  const right = normalize(cross(forward, [0, 1, 0]))
  const up = cross(right, forward)
  return { forward, right, up }
}

两个函数各只有一个没写出来的依赖事实：sin/cos 之和。forward 的三行就是 R_y·R_x·(0,0,-1) 展开后的结果——展开过程就是上一节的两笔演算，照抄进代码而已。角度进出都是度数，弧度只在函数体内活一行；拖拽的增量、界面的读数天然是度数，实验场替调用方把换算包了。src/index.ts 照例追加。

小结 ​

相机姿态的正确记法是角度，不是矩阵的叠加。轨道相机绕目标点沿球面转圈：球坐标三个数（方位角绕 Y、极角从 +Y 量起、半径）唯一确定眼位，target 固定交给 lookAt，极角收进 [1°, 90°] 躲开极点退化；滚轮只碰半径，沿视线进退自动成立。漫游相机站在场景里走：偏航角与俯仰角只管朝向，组合顺序固定「先 pitch 后 yaw」——yaw 绑世界 Y 轴、pitch 绑转身后的额头，反序就会在拖过 180° 后方向反转；移动沿相机基向量 forward/right/up（与 lookAt 的 f/s/u 同款手艺），W/S/D/A 是基向量上的线性叠加，不沿世界轴。两种相机同一条纪律：角度是唯一的状态，眼位与基向量每帧现造，方向永不累积出错。实验场进账一件：scene/camera 的 orbitEye、viewBasis 与 CameraBasis，测试总数 116。读者已能把拖拽、滚轮、键盘接进第 7 章的 lookAt，并解释开章两个 bug 各自的账。

概念去向：相机进世界清单、与场景树同框装配，第 13 章收尾。
