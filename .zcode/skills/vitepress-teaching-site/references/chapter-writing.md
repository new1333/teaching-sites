# 章节写作契约

本文是写作角色与评审角色共享的唯一正文标准。每章再读取 [`verification-and-gates.md`](verification-and-gates.md) 解析出的单一模式文件。

## 默认结构

未在 outline 声明 `structure` 时使用：

```text
可选前情 → 钩子 → 原理 → 演练 → 验证 → 收束
```

- **前情**：只提本章真正依赖的已知能力，优先用问题唤回；不复述上一章摘要。
- **钩子**：呈现 outline 中具体可观察的现象。
- **原理**：先解释约束和“为什么存在”，再讲机制。
- **演练**：形态由验证模式决定。
- **验证**：读者亲自预测、操作并对照结果。
- **收束**：回收开篇现象，盘点新能力，给迁移自查。

天然不合默认结构的对比、推演或复盘章，按 outline `structure` 写；评审按声明验收。

## 教学契约

### 1. 钩子形成闭环

开篇在前 1500 字内出现 `hook.phenomena`，场景具体到读者能说出“发生了什么”。收束先解释同一现象，不把钩子留成装饰。

### 2. 术语首现能被外行复述

专业词第一次出现时，当场说清它是什么、拿来做什么。英文原名不是解释。能用日常词表达时不发明行话。

承重概念按依赖程度教：

- 只用于辨认的词：一句人话定义；
- 支撑本章结论、里程碑或后章推理的概念：至少交代**成因与载体**；
- outline `new_concepts`：按需要完成**成因 → 载体 → 演算 → 锚点**，直到读者能自己推出结论。

四步是诊断框架，不是内容配额。某概念不需要结构图或类比时不硬加。

### 3. 成因通过反事实检验

写“因为 X”前先问：没有 X 会发生什么？能给出可验证后果，X 才是成因。公开资料没有解释设计动机时，写“规范规定/实现选择”，不编造目的。

客观事实、定义、监管规则、协议与硬件行为对照 bible authority docs。故事情节可以虚构，故事中的物理和机制必须真实。课程简化当场声明，并在 divergence 附录集中登记（若大纲声明该附录）。

### 4. 承诺面等于交付面

标题、总表、开篇承诺和 acceptance 提到的每一项都要在正文建立。超出本章范围时明确写目标章或差异附录，并登记 promise；不以静默省略缩小交付。

### 5. 承重知识有独立载体

读者即使不打开 companion，也能验证核心推理：给自包含 REPL、纸笔演算、结构表、时序图或可判定任务。载体由知识性质决定。

### 6. 引用与现实一致

- companion 片段首行标注真实路径与符号，如 `// src/store.ts · createStore`。
- 用法示例写 `// 用法示例`；合成视图写“拼版/教学示意”并指向终态。
- 里程碑依赖路径展示完整，不用 `...`、`同上` 或注释空壳代替逻辑。
- zero-trace 不出现目标仓库源码。
- guided-walkthrough 使用 `owner/repo@sha:path`，引用与锁定 ref 逐字一致。
- 后章重构改变终态时，回写所有受影响正文。

### 7. 验证由读者执行

验证槽至少包含：

1. 一条第二人称动作；
2. 一次“先猜后跑/先算后核对”；
3. 成功结果和一个有辨识力的失败或变体；
4. 结果与本章结论之间的解释。

作者贴一段测试输出不等于读者验证。可感知成果优先让读者直接看到、听到或操作。

### 8. 自查检验迁移

自查默认存在，数量由内容决定。题目满足：

- 不能从正文原句直接抄答案；
- 换一个输入、情境或失败模式；
- 题干不泄露答案；
- 给可回查小节、附录行或 `<details>` 答案。

### 9. 连贯性写进账本

前向承诺只保留当前理解必需的去向。每条写入 `promises.json`；目标章必须兑现或显式改期。章末 rolling summary ≤200 字，只记已建立概念、验证物变化和读者能力。

### 10. 呈现服务教学

- 代码密度按 profile：`full` 展开；`collapsed` 折叠非承重长块；`minimal` 只保留最小切片。
- 代码块标语言；HTML 仅用于 VitePress 必需组件/媒体。
- 中文正文中英文与数字留空格，句子一次表达一件事，避免翻译腔和企业黑话。
- 加粗、比喻、图表与字数都服从承重点。防御阈值用于发现噪音，不是要求把数量写满。

## 分模式演练

| 解析模式 | 演练槽 |
|---|---|
| `code-lab` | 从失败行为到最小实现，再展示门槛 |
| `canvas-app` | 运行页面并嵌真实导出资产 |
| `worksheet` | 跟算 fixture，数字来自导出 |
| `observation` | 操作清单与具体可对照现象 |
| `repo-probe` | 锁定源码片段 + 对应探针 |
| `none` | 证据包、反例、推导或复盘对账 |

细节只读对应的 `verification/*.md`。

## Chapter lint

```bash
node scripts/course-lint.mjs {course_dir} docs/{NN}-{slug}.md \
  <bible 术语...> --new <本章 new_concepts...> --pain <hook.phenomena...>
```

v2 outline 存在时脚本自动解析语言、source policy、章级 verification 与 review 豁免。显式参数只用于旧课程或诊断。

Lint 失败后根据检测信号定向修一轮；它检查的是可机械识别的下限，不替代概念与事实评审。info 项也要处理，尤其是 promise 登记与篇幅异常。

## 写作完成条件

- 默认槽位或声明结构完整；
- acceptance 的 prose/source/experience 条目都能在正文定位；
- 新概念首现、事实来源和承诺均有落点；
- 验证槽让读者执行并解释结果；
- lint 退出码为 0；
- rolling/promise 草稿只描述落盘后的真实状态。
