# 章节写作契约

本文是写作角色与评审角色共享的唯一正文标准。每章再读取 [`verification-and-gates.md`](verification-and-gates.md) 解析出的单一模式文件。

## 默认结构

未在 outline 声明 `structure` 时使用：

```text
可选前情 → 钩子 → 原理 → 演练 → 验证 → 收束
```

- **前情**：只提本章真正依赖的已知能力，优先用问题唤回；不复述上一章摘要。
- **钩子**：呈现 outline 中具体可观察的现象。
- **原理**：先解释约束和“为什么存在”，再讲机制。
- **演练**：形态由验证模式决定。
- **验证**：读者亲自预测、操作并对照结果。
- **收束**：回收开篇现象，盘点新能力，给迁移自查。

天然不合默认结构的对比、推演或复盘章，按 outline `structure` 写；评审按声明验收。

## 教学契约

### 1. 钩子形成闭环

开篇在前 1500 字内出现 `hook.phenomena`，场景具体到读者能说出“发生了什么”，并能对号入座一个“我经历过 / 马上能复现”的时刻；做不到的场景降级为背景，不硬凑故事。钩子素材（现象、实验、历史事故、数据、疑问）交替使用，同一叙事模板全书不超过 2 次。收束先解释同一现象，不把钩子留成装饰。

### 2. 术语首现能被外行复述

专业词第一次出现时，当场说清它是什么、拿来做什么。英文原名不是解释。能用日常词表达时不发明行话。

承重概念按依赖程度教：

- 只用于辨认的词：一句人话定义；
- 支撑本章结论、里程碑或后章推理的概念：至少交代**成因与载体**；
- outline `new_concepts`：按需要完成**成因 → 载体 → 演算 → 锚点**，直到读者能自己推出结论。

四步是诊断框架，不是内容配额。某概念不需要结构图或类比时不硬加。

每个术语全书完整定义一次；后续出现交给术语表链接，不以括号重定义复述，复盘章尤其禁止——打断读者答题节奏的是重教旧词。定义句的主语就是被定义的术语，破折号与冒号两侧的名字和定义一一对应，不给相邻概念共用一个定义句。

### 3. 成因通过反事实检验

写“因为 X”前先问：没有 X 会发生什么？能给出可验证后果，X 才是成因。证伪读者的直觉前，先替直觉说句公道话——它从哪来、在什么范围内合理——再指出恰好不成立的边界；直接否定会让读者防御。公开资料没有解释设计动机时，写“规范规定/实现选择”，不编造目的。

客观事实、定义、监管规则、协议与硬件行为对照 bible authority docs。故事情节可以虚构，故事中的物理和机制必须真实。课程简化当场声明，并在 divergence 附录集中登记（若大纲声明该附录）。

### 4. 承诺面等于交付面

标题、总表、开篇承诺和 acceptance 提到的每一项都要在正文建立。超出本章范围时明确写目标章或差异附录，并登记 promise；不以静默省略缩小交付。

### 5. 承重知识有独立载体

读者即使不打开 companion，也能验证核心推理：给自包含 REPL、纸笔演算、结构表、时序图或可判定任务。载体由知识性质决定。

### 6. 引用与现实一致

- companion 片段首行标注真实路径与符号，如 `// src/store.ts · createStore`。
- 用法示例写 `// 用法示例`；合成视图写“拼版/教学示意”并指向终态。
- 里程碑依赖路径展示完整，不用 `...`、`同上` 或注释空壳代替逻辑。
- zero-trace 不出现目标仓库源码。
- guided-walkthrough 使用 `owner/repo@sha:path`，引用与锁定 ref 逐字一致。
- 后章重构改变终态时，回写所有受影响正文。

### 7. 验证由读者执行

验证槽至少包含：

1. 一条第二人称动作；
2. 一次“先猜后跑”：猜测落纸成离散可判定的值——“恰好 1 条红”“约 47 MiB”“二选一”，不许写“应该会出问题”；
3. 成功结果和一个有辨识力的失败或变体，首选**定向破坏**——指认精确到行的改动，先预言可观察症状，执行后解释“哪条没变、它守的是什么”，改回并确认复原（规格见 [`prose-patterns.md`](prose-patterns.md)）；
4. 结果与本章结论之间的解释。

作者贴一段测试输出不等于读者验证。可感知成果优先让读者直接看到、听到或操作。

### 8. 自查检验迁移

自查默认存在，数量取本章独立推理边界的数量（通常 1-5 问），可由预测变体实验替代问答题。题目满足：

- 不能从正文原句直接抄答案；
- 换一个输入、情境或失败模式；
- 题干不泄露答案；
- 给可回查小节、附录行或 `<details>` 答案。

### 9. 连贯性写进账本

前向承诺只保留当前理解必需的去向。每条写入 `promises.json`；目标章必须兑现或显式改期。章末 rolling summary ≤200 字，只记已建立概念、验证物变化和读者能力。账本之外，承诺还要写成读者可感的叙事——见下文「衔接与收束的叙事写法」。

### 10. 呈现服务教学

- 代码密度按 profile：`full` 展开；`collapsed` 折叠非承重长块；`minimal` 只保留最小切片。
- 代码块标语言；HTML 仅用于 VitePress 必需组件/媒体。
- 中文正文中英文与数字留空格。一段推进一个新推理步；需同时持有两个以上新概念的论证拆成编号步骤或小节。避免翻译腔和企业黑话的可执行判据：主谓完整句优先、一段一个断言、括号内定义不超过一句。
- 加粗、比喻、图表与字数都服从承重点：加粗一节至多 2 处，允许存在无强调的安静段。防御阈值用于发现噪音，不是要求把数量写满。
- 不写即时性措辞（“就在你读这一章的这周”“目前最新”）——改相对表述或登记 timeliness 义务。
- bible/outline 的字段名（anchor、phenomena、hook 等）不得作为读者可见词汇进入正文；类比用自然语序呈现，全书统一标签时在首现处向读者解释一次。

## 书级节奏与反疲劳

教学契约管单章下限；本节管“连起来读”的体验。单章全对、全书疲惫是最常见的退化，机械检查只能看见一角。

- **句式配额**：同一开篇或收束句式全书至多 3 次，连续两章不得同款开场。轮换衔接姿态（清旧账 / 悬案回收 / 新现象 / 换视角）；事故叙事（“凌晨三点，告警响了”）全书至多 2 次且细节必须服务机理。
- **重音预算**：加粗与句尾立论一节 ≤2 处，每 2-3 节留一段无强调的安静叙述。“自查恒等于 3 问”、逐字同款的验证收尾句，都是模板信号。
- **章末分工**：有术语附录的课程，收束只做回查指针 + 1-2 个易错点，不逐词复述定义；累积路线表只留“下一站 + 更远的路”两三行，完整地图归首页与终章；全书能力对账只在终章出现一次，单章收束不复述。
- **密度预算**：一章 new_concepts 超过 5 个时开篇先挂词表；二级术语（标准库名、宏名、周边工具名）降为内联括注，不进推理主线。
- 每写完一章，与相邻章比对开篇前两行与收束段，句式相同即改写。lint 的 `rhythm-info` 行是这个比对的机械下限。

## 衔接与收束的叙事写法

promises.json 是数据账；正文还要把它写成读者可感的叙事债。范式与摘录见 [`prose-patterns.md`](prose-patterns.md)，要点：

- **埋账**：章末的前向承诺写成具体悬案——一个读者已亲见但未解释的现象、一颗声明过位置的雷——而不是方向陈述（“下一章我们将学习 X”）。
- **清账**：开章至多清 2-4 笔旧账，逐笔点名来源章与原话，本章正文有对应兑现处。
- **收束重考**：收束以回答开篇之问的口吻重述因果链，禁止以清单复读小节标题；终章优先重施开篇测试，把 driving question 原文收口成一段答案。

## 分模式演练

| 解析模式 | 演练槽 |
|---|---|
| `code-lab` | 从失败行为到最小实现，再展示门槛 |
| `canvas-app` | 运行页面并嵌真实导出资产 |
| `worksheet` | 跟算 fixture，数字来自导出 |
| `observation` | 操作清单与具体可对照现象 |
| `repo-probe` | 锁定源码片段 + 对应探针 |
| `none` | 证据包、反例、推导或复盘对账 |

细节只读对应的 `verification/*.md`。

`code-lab` 的红绿节奏：先展示一条具体的红（报错或红测试原文）→ 最小实现转绿 → 门槛全量跑。重构/手术章开场先交代改动面（见 `prose-patterns.md`「手术清单开场」）。

## Chapter lint

```bash
node scripts/course-lint.mjs {course_dir} docs/{NN}-{slug}.md \
  <截至本章的累积术语...> --new <本章 new_concepts...> --pain <hook.phenomena...>
```

术语传“截至本章的累积术语”（bible 全量口径只用于终章与全书评审）；中途章传全书术语会因“未到教期的词”误报缺失。

v2 outline 存在时脚本自动解析语言、source policy、章级 verification 与 review 豁免。显式参数只用于旧课程或诊断。

Lint 失败后根据检测信号定向修一轮；它检查的是可机械识别的下限，不替代概念与事实评审。info 项也要处理，尤其是 promise 登记与篇幅异常。

## 写作完成条件

- 默认槽位或声明结构完整；
- acceptance 的 prose/source/experience 条目都能在正文定位；
- 新概念首现、事实来源和承诺均有落点；
- 验证槽让读者执行并解释结果；
- 与相邻章比对过开篇与收束句式（书级节奏契约）；
- lint 退出码为 0；
- rolling/promise 草稿只描述落盘后的真实状态。
