# 领域事实核查 + 统一的「简化与真机差异」清单

## Question

课程里对客观领域事实的断言（硬件行为/协议/规范），要不要强制「权威文档对照」环节？「本课程简化 vs 真实行为」的差异要不要统一清单？

证据（7 处事实级问题，全部有 file:line）：
- 第 7 章「$2004 的读也会推进 OAM 指针」——权威文档明文相反（写推进、读不推进）；更糟的是以「测试第二条读数立刻抓出来」的 TDD 叙事背书，测试与实现同错形成自洽假象（companion 源码同样错）。
- 第 3 章镜像「解码电路只看低 13 位」——位算术错误（正确：只接低 11 位），图文自相矛盾，读者用它推不出自查题的 `0x7ff`。
- 第 10 章 VBlank 240 置位——违反本章自己的验收项（241-260），同类简化（半拍差）被郑重声明，整线偏差静默通过。
- 第 9 章 sprite 0 hit「x=0 与 x=255 都不触发」表述不准确（真机仅 x=255 恒不触发）。
- 第 4 章「SP=$FD 的历史玄学没有教材敢解释」——不实（有公认解释）；「D 标志稍后会用到」——本平台根本无实现。
- 第 3 章开放总线「残留通常是 0」——真机行为是保留最后总线值。
- 附录寄存器表列出「bit5 精灵溢出」但实现没有、正文没教，与附录自己的「未实现」清单自相矛盾。

根因：流程里测试通过被当成事实正确的背书，无任何「对照权威文档」环节；简化声明零散随机。

要决定的选项（可组合）：
1. 写作硬要求：凡断言「真机/规范如此」类客观事实，须对照主题权威文档核实——可移植表述（权威文档按主题在备课/圣经期指定），并要求「测试与实现一致」不得作为事实正确的证据；
2. 统一「简化与真机差异」清单：appendices 新 kind（如 divergence）或并入 reference-table 规则——所有静默简化必须进清单，正文声明处指向它；终检对账（清单 vs 实现 vs 附录寄存器表）；
3. 备课/圣经阶段建「事实断言 → 来源」对照表，写作期只准引用表内已核实事实。
