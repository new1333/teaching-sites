# lint 反噬修正：检测意图，别催生模板

## Question

哪些 lint/写作规则在实跑中造成了模板化反噬，怎么修？

证据：
- pain-point 信号词检查（开篇 1500 字内须含「坑/报错/崩溃…」）→ 每章开篇硬造第一人称踩坑故事；第 3 章甚至为过 lint 把大纲设定的 pain_point 改写成别的场景，直接导致文验收落空（与 007 联动）。
- term-intro 句式检查（首现句须含括号注释/破折号/「也就是」等结构信号）→ 「中文（english——解释）」句式全书模板化，连章标题都被套上「寄存器（register）与取指（fetch）执行循环」；第 2 章还有生成残留措辞「下一部分章节展开」。
- 需要排查的其他规则：判词密度、闪前配额是否也催生了规避写法（如把该讲的内容甩给附录以规避闪前计数——第 11 章长度计数器表、跨页加拍都是「甩附录」实例）。

要决定的选项：
1. pain-point 检测改为「大纲 pain_point 的现象关键词须出现在开篇」——检测与 spec 对齐，而不是任意信号词；
2. term-intro 保留存在性检查（术语必须解释），句式判定降级为建议或放宽模式库；
3. 全面排查一轮：对现 course 产物跑规则-产物对照，列出每条规则的实际副作用清单再定去留。
