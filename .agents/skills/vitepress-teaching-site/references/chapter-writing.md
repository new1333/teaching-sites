# 章节写作纪律

**每会话首次动笔前读完本文件**——笔感基准和 lint 规则决定成稿质量；长时间中断或 lint 连续报警时再重读，不必每章读。子智能体分工下（见 `subagents.md`），章写作与评审智能体每次 spawn 都是全新会话，每次都先读本文件；主智能体亲自补位写作时照本条执行。

## 骨架（五槽位 + 可选前情槽）

**槽位必填，槽内形态随 profile**（公理 1：骨架是跨形态不变量，槽内内容是形态细则）：

**（前情，可选）** → **开章钩子** → **原理**（先「为什么存在」，再「怎么工作」）→ **演练**（形态任选：code-lab 的渐进实验引用实验场真实代码 / worksheet 的跟算（数字由导出脚本产出）/ observation 的实操任务 / repo-probe 的走读）→ **验证**（读者动作，验证物输出两侧可见）→ **收束**（小结 + 自查）。

- **前情槽**（011 P2-7）：承前启后的回顾，≤150 字或 ≤8 条短句，**半数提问式**（「还记得 X 为什么不能 Y 吗？」）——回顾是提问的机会，不是摘要的复读。第 1 章、part 首章可省。
- **开章钩子**：四种形态任选其一（大纲 `hook.kind` 声明），验收标准只有一个——**具体到现象**，不再是「必须是 bug 故事」：
  - `bug-story`：真实 bug 场景（「组件销毁后定时器还在每秒拉数据」）；
  - `real-incident`：公开事故、市场现象、历史事件（「某年某月某交易所熔断的分钟级行情」）；
  - `observation`：现象观察（「你大概注意过 X，但没想过为什么」）；
  - `ability-gap`：已能什么 vs 还差什么（复习章、进阶章的天然开法：「上一章你能 A 了，但遇到 B 还是无从下手」）。
  反噬教训（011 P2-8）：22/22 章全部第二人称亏损剧本、收尾对照章为凑「bug 开章」硬造故事——**钩子为教学服务，不为模板服务**。
- **验证槽的读者动作**（011 P0-1）：必含至少一条**第二人称动作指令**（读者跑什么、算什么、应看到什么），以及至少一处**「先猜后跑」**——读者跑前先预言某断言结果，或对验证物做一处指认好的小破坏、指出哪条检查会红。作者视角的测试输出转录不算验证段。
- **收束槽的自查**：自查**默认开**（不再是可选）；数量只是默认起点（teaching 章小结通常 ≥2 问，其中 ≥1 问预测/动手型），真正的军规约束的是**题的质量**：① 不得是正文原句可抄的问题（换数字、换情境）；② 题干不含答案或可直接套用的公式；③ 每问附答案锚点（可回查的小节/速查表行，或 `<details>` 折叠答案——VitePress 原生支持）。

## 硬要求·不变量组（跨一切课程形态成立）

1. **开章钩子具体到现象**：把本章 spec 的 hook/pain_point 写成读者能脑补出画面的具体场景，不写概念式铺垫（形态四选一见上）。
2. **说人话，术语首现必解释**：专业名词第一次出现时，当场用一句大白话说清「它是什么、拿来干嘛」——只标英文原文不算解释，默认读者已经认识更不行。行话只在「业界通用叫法、读者以后躲不开」时才用，且首现必须翻译成人话；能用日常词说清的概念，不发明新词。自查标准：把这句解释念给一个没接触过这行的人听，他能复述个大概才算过。黑话（赋能、抓手、底层逻辑这类词）零容忍。**扩面（011 P0-2）：承重概念的首现定义同规受检**——首现定义不得与后续推演矛盾（「符号位」式补码定义与溢出推演矛盾即阻断）。
3. **教核心原理，终点随课程原型**：读者读完达到 profile.archetype 对应的终点（做出最小实现 / 读懂并讲解机制 / 独立演算判断 / 独立完成操作）——不是 API 文档，也不是复刻。
4. **代码片段标注出处，且出处必须真实**：伴生实验场的代码片段首行注释写明文件与函数（`// src/store.ts · createSetupStore`），用法示例标 `// 用法示例`，拼合视图标「拼版」。标注 `src/…` 的代码必须与验证物**当前形态**逐字一致——允许追加教学注释，不允许标识符或结构差异；标注了出处却对不上，比不标注更伤信任。全书核心函数首次登场时给一次全貌（含生长点注释），后续章节只贴增量。承重逻辑（milestone 依赖的路径）禁用 `...`/「同上」开天窗，**也禁用注释占位分支**（`/* 高序号先画 */` 这类空壳）——省略只允许出现在标注「拼版」的视图，且该函数的完整形态全书至少出现过一次。某章的历史形态只允许以「拼版·教学示意」标注出现，并注明终态在哪章交代。
5. **承诺面 = 交付面**：本章以标题、总表、「一次讲清」式开篇承诺列出的每一项，正文必须有着落——按概念教学的四步教透，或当场声明去向（「X 留到第 N 章」「本课程不实现，差异清单见附录」）。静默缩水（表格里列了、正文再不提）是阻断项：标题不承诺本章不教的东西，承诺面超载时拆章或降标题。
6. **承重知识给「不进验证仓也能验证」的载体**：引用伴生仓之外，每个承重知识点至少配一种读者独立可验证的载体——REPL 可跑的自包含片段，或纸笔可复算的数值演算；结构类概念可用位图/结构表。选哪种由知识点性质决定，不设数量配额；首章立下的自包含标准不得在后续章静默放弃。
7. **事实断言对照权威文档，「故事可以虚构，物理不可以」**：对客观领域事实（硬件行为、协议、算法标准、监管规则）的断言，写作时对照圣经的权威文档清单核实；**测试通过与实现一致不构成事实正确的证据**——测试与实现同错时会互相背书。**扩面（011 P0-2）：承重概念的首现定义、痛点/钩子故事内的每一处技术性断言，按同等标准核验**——故事情节可以虚构，故事里的物理与机制不可以。课程对真实行为的每处简化必须在正文声明，并集中登记在差异清单附录（大纲声明了该附录时）；未声明的差异是事故。worksheet 形态下正文承重数字由脚本导出、守门断言随导出脚本走（见 `verification-and-gates.md`）。
8. **闪前有账，承诺必清（011 P0-3）**：正文中「第 N 章（N＞本章）会……」预告每章 ≤3 处，只留「当下不讲清楚就无法理解」的；概念去向统一收在章末地图或小结。**每条闪前承诺当场登记 `.course/promises.json`**（`{ from, target, what, status }`），目标章生成时注入清账项，全书评审机械核销——写着「第 8 章细算」而第 8 章只字未提，是账本违约。回看（引用已写过的章）不受限。
9. **判词句密度**：每章加粗判断 ≤8 处（含列表标签；上限是防御阈值不是目标）。平实句是主体——句句加粗等于没有加粗。箴言体是复盘文体，不是教学文体。
10. **比喻登记**：每章常驻比喻 ≤2 个（贯穿全书的核心比喻记入 bible）；装饰性比喻一律改回技术名。比喻要承重，不要猎奇；禁用词黑名单按课程追加（默认含「集中营」）。
11. **rolling_summary**：章末产出 ≤200 字前情摘要（已建立的 API/概念、本章验证物变更点、读者已能做什么）——写入 `.course/rolling.json`，下一章必带。
12. **结构基线**：代码块标注语言；不用 HTML 标签（嵌资产的技术标签除外，见 vitepress-assembly.md）；不写「本章小结」式重复标题；frontmatter 写 `title:`（中文标题）。**字数**：teaching 章正文默认 ≥1200 字（中文，不含代码），上限不设——写满凑字反而降质，讲透即收；**review/总览章可在 outline 声明 `length_exempt` 豁免下限**（lint 按声明检查）——字数是防御下限，不是目标值，更不是配额。

## 硬要求·形态细则组（只对声明了对应 profile 的课程生效）

- **zero-trace 档（默认）**：**零外部源码引用**——示例代码只出自伴生实验场或自包含用法示例；不写「与真源码对照」段落。可以提真实库的公开概念与行为（「Vue 没有官方 isComputed」），但它的代码一行不进正文。
- **guided-walkthrough 档**：仓库是教学对象本身——正文代码块**必须**标注 `owner/repo@sha:path` 且与锁定 ref 逐字一致（lint/final-check 机械比对）；「零外部源码引用」在此档替换为「引用与锁定 ref 逐字一致」；仍然一章一个可讲清的机制，「导读」不等于「逐文件流水账」。
- **code-lab**：演练槽 = 渐进实验（引用实验场真实代码，讲演进思路）；验证槽 = 双硬门槛两侧可见；里程碑可被读者感知时给「亲手开机」指引（入口命令与能看到/听到什么）。
- **canvas-app**：可感知成果硬语义（011 P1-5）——**测试输出不算可感知面**；演示组件必须 `import` 实验场/数据脚本的产物（平行手抄组件是阻断项）；正文嵌由实验场现场产出的资产，聚合站 base 兼容；hero 措辞与读者可运行产物一致。
- **worksheet**：演练槽 = 跟算（数字与图表数据由导出脚本产出，正文不手写承重数字）；验证槽 = 答案核对脚本输出两侧可见（期望答案 vs 演算输出）。
- **observation**：演练槽 = 实操任务（勾选式清单，每条含读者操作 + 应看到的具体现象）；验证槽 = 任务清单过可判定性（禁「感受一下」类模糊描述）。
- **中文课程**：中文与英文/数字之间加空格；短句（超 80 字长句拆短，一句只装一件事）；禁翻译腔。其他语言跳过中文专用 lint 规则（`--lang en`），通用规则（出处真实、承诺账、判词密度、省略纪律、钩子对齐、字数下限）全语言生效。

## 承重概念分级（011 P1-4）

教学覆盖按**承重程度**划线，不按「大纲是否声明」划线：**承重概念**（结论、里程碑、后续推演依赖的概念——无论大纲有没有把它写进 new_concepts）不适用硬要求 2 的一句话兜底，至少「成因 + 载体」两步起步；成因须过**反事实检验**——「如果不这样会怎样」，答得出才许写「因为」；答不出就诚实写「未见公开解释，按真机照抄」，**禁伪成因**（「设计如此」不是成因）。被声明的陌生概念按下方四步完整教；未声明但承重的，按分级补齐——讲不透就别让正文依赖它。

## 笔感基准（两段范文）

**钩子开章范文**（bug-story 形态，约 150 字）：

> 「周五上线的看板组件销毁后，定时器还在每秒拉一次数据——内存曲线一路向右上方走。这不是 React 或 Vue 的 bug，而是"组件状态"与"组件实例"被当成了同一个东西。这一章我们先亲手踩一遍这个坑，再看看 pinia 用什么结构把状态从组件树里拽出来。」
>
> 写作要点：从具体场景切入；先现象后原理；句子短；术语首次出现时中英并列、当场用一句人话解释；不用「我们可以看到」「值得注意的是」这类填充语。

**讲原理而非贴源码范文**（状态管理主题，一章开头的节选）：

> ### 一解构就断连
>
> 你大概写过这样的代码：
>
> ```ts
> const store = useCounterStore()
> const { count, increment } = store   // 😈
> ```
>
> 页面上 `count` 纹丝不动了。这不是 bug，是你把「活的」东西拿成了「死的」快照。
>
> `store` 是 `reactive(...)` 返回的 Proxy。Proxy 的魔法只属于**这个代理对象本身**——你通过它读属性，它才会帮你建立依赖、通知更新。`const { count } = store` 是一次普通的属性读取：把当时的数字取出来，装进一个普通变量。从此这个变量与 store 再无关系。`increment` 倒是能用，因为它只是读了个函数引用——**丢响应性的从来只有数据，函数天然免疫**。
>
> 这个「数据会断、函数不会」的不对称，正是解法的全部线索：把每个数据字段包成一个 `ref`，解构时拿到的是 ref 对象——一个永远指向 store 内部字段的活引用；函数则原样透传。
>
> （随后给出十行实现 + 三行验证；结尾可以一句带过真实库的公开事实——「真 pinia 也用这一招探测」——但不引它的代码、不列它的行数。）

## 陌生概念怎么教（大纲声明 new_concepts 时）

教学生手的东西，形状固定四步，顺序不能倒：**成因 → 载体 → 演算 → 锚点**。

- **成因**：先答「为什么存在」——约束、钱、电路或历史，落到具体事实上（须过硬要求「反事实检验」）。规则没有成因，就会被记成巧合。
- **载体**：空间结构、位布局、时序类概念，给一张 ASCII 图或结构表——读代码时脑补不出的结构才配图；纯文本就能承载，零依赖。
- **演算**：可算的概念配一段 ≤20 行的「跟着算一遍」，用真实数字、一步得出可见结果——读者亲手推出结论，才不是在背结论。
- **锚点**：首次引入时挂到读者已知世界的类比。用校准问卷测出的那个锚点，不临场发明；一句话即收，展开比喻反而抢戏。

讲透即收：有的概念一句成因就够，硬配图和例题是凑数，与凑字同罪。配多少由「读者能否自己推出这个结论」决定，不由配额决定。

四步是大纲声明的陌生概念的完整教法；没被声明的其余专业名词按硬要求 2 兜底——首现给一句人话，一个都不能漏。被本章标题、总表或开篇承诺覆盖但未声明过的知识点，同样按「成因 + 载体」的标准对齐（硬要求 5/6）：讲不透就别承诺，承诺了就必须有着落。

**范文**（四步各就各位，约 300 字）：

> ### 一个字节画不出一个像素
>
> 你今天写的代码里，一个像素四个字节（RGBA）；NES 的显存里，**一个字节装着八个像素的「第 0 位」**——颜色被劈成两张「镂空板」分开存，叠起来才拼出色号。为什么这么怪？算笔账：打包存 2 bit 同样是 16 字节，位平面一分钱没省。它省的是电路：渲染芯片用两根 1 位移位寄存器并行吐位，同一时刻各出一位、拼起来就是色号——**存储格式就是渲染电路的形状**。
>
> ```text
> 字节 0-7 （平面 0）：每字节的 8 个 bit = 一行 8 个像素的低位
> 字节 8-15（平面 1）：同样 8 行的高位
> 行 y 像素 x（从左数）的色号 = ((平面1[y] >> (7-x)) & 1) << 1 | (平面0[y] >> (7-x)) & 1
> ```
>
> 跟着算一遍：平面 0 的第 0 字节是 `$AA`（10101010），平面 1 的对应字节是 `$00`——这一行从左到右就是 1,0,1,0,1,0,1,0。给我任意 16 个字节，你都能在纸上画出这块瓦片；走到这一步，「位平面」对你就不再是黑话。
>
> 锚点：两张盖章用的镂空纸板，单看只有透与不透，叠在灯箱上才显出四种明暗。

写作要点：成因要落到钱、电路、历史这类硬约束，不许「设计如此」；图只画脑补不出的结构；演算一步出可见结果；锚点一句话即收。

## lint 自检（写完一章后，机械执行）

别用眼睛扫——lint 脚本是**仓库级共享资产** `scripts/course-lint.mjs`（issues/012 改造 D 上移：不再以文本内嵌各课程、落进被 gitignore 的 `.course/` 逐课漂移；脚本本体与变更说明以仓库 scripts/ 为正本）。对本仓库课程直接：

```bash
node scripts/course-lint.mjs courses/{course} docs/NN-slug.md <术语1> <术语2> ... \
  --new <本章新教术语...> --pain <大纲 hook/pain_point 的现象词...>
```

（用于新仓库时，把 `scripts/course-lint.mjs`、`scripts/course-final-check.mjs` 原样复制进目标仓库的 `scripts/`，与 portal 脚手架同批提交。）

参数与规则要点：`--lang zh|en`（默认 zh；中文专用规则——中英空格/被字句/翻译腔/长句/黑话/term-intro 句式——仅 zh 生效，通用规则全语言生效）；`--source-policy` 默认读 outline.profile（zero-trace 禁外部源码引用；guided-walkthrough 允许但必须带 `owner/repo@sha:path` 标注并核对锁定 ref）；`--verification` 启用形态专项检查（observation 的任务清单可判定性）；min-chars 按 outline 本章声明自动豁免（review/`length_exempt`）。outline.json 存在时脚本自动读本章 spec（hook 现象词、豁免、政策），CLI 显式参数优先。

terminology 检查传术语表全部条目＋圣经读者模型的陌生概念（容 3 条未出现）；term-intro 只查 `--new` 传入的本章新教术语（首现段落内有解释信号——检测意图而非句式，issues/010 教训：检测器对齐 spec，不奖励模板）；pain-point 开篇检查以 `--pain` 的大纲现象词为准。lint 还会输出 `info:` 行（如本章闪前指向哪几章、应登记 `.course/promises.json`）——info 不阻断，但承诺账登记是硬要求 8，别忽略。

未过 → **只修检测器指出的问题**，定向修订一轮，不重构内容、不动代码块。修订一轮即饱和——再修只会降质（负面经验：无外部信号的自我纠错会降质，负面清单单独使用无效，所以要靠正向模板字段 + 事后检测器这套组合）。
