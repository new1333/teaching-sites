支撑、阻力与斐波那契：人多的路口，价格会堵车 ​

三月里你在一只 20 元的股票上抄了底。买入前你打开画线工具，在前低 18.6 元画了一条横线，标上「支撑位」。两天后盘中击穿，你安慰自己是假动作；收盘 18.2 元，你把线擦了挪到 18 元，说这次才是真支撑。一周后又破，再挪到 17.2 元。同一个位置，三次画线三次打脸，最后你干脆不画了，改去问群里的大神。复盘时你想明白一件事：手画支撑位的毛病不在手，在「画在哪里」从头到尾没有判据。线破了又立、立了又破，是因为那根线本来就只存在于你的屏幕上。

先把两个词说清。支撑（support——跌到这里就有人接盘、跌势常在这里减速的价位区间）与阻力（resistance——涨到这里就有人抛、涨势常在这里喘气的价位区间）是一体两面。它们说的是同一个事实：某些价位附近，买卖双方会反复到场。本章要把「某些价位」从感觉变成判据。路线是三件事：讲清路口为什么存在，再把找路口、数触碰、画刻度各写成一个函数。

路口为什么存在：挂单排队与念念不忘 ​

第 2 章讲过盘口：买单卖单各排五档，价格优先时间优先地等撮合。支撑阻力位的第一成因就藏在这张排队表里——挂单聚集。股价从 11 元回落到 9.6 元那次没接住的人，记住了这个价；下次价格再跌回 9.7 元，他会提前在 9.6 附近挂买单等回踩。等的人多了，这个价位的买一买二买三档就排起长队。卖单砸下来，先撞上这些排队买单：要全部吃光才跌得动，于是跌势在这里减速，甚至被顶回去。阻力是镜像：11 元附近买套的人，等价格涨回来解套就卖，上方几档堆着一批卖单，涨势到这里撞墙。位的成因不在图上，在盘口的排队里——图上的横线只是排队表的投影。

第二成因是心理的：锚定效应（anchoring——人对第一次看到的价位念念不忘的行为偏差，最初的重点数字成了心里的锚）。18.6 元买入的人，判断涨跌不自觉都拿 18.6 当参照：回到 19 元他就觉得「赚了」，想卖。成千上万人的锚不同，但在两个地方会扎堆：整数的关口（10 元、20 元，人人看得见），与自己成本最近的极值（前高、前低）。锚定了位的候选位置，挂单给了位的实体，两者叠出路口。锚点就用课程的老比喻：支撑阻力位是人多的路口——车流（卖单）涌到路口，红绿灯（排队买单）决定堵不堵。

盘口的形状长这样（数字为教学示意）：

text
卖五 11.10   200 手   ← 阻力上方：更早买套的人排队等解套
卖一 11.01  1200 手   ← 位附近的卖墙：解套盘加短线获利盘
———————— 价差 ————————
买一 11.00   900 手
买二 10.99  1500 手   ← 支撑位附近：等着回踩接货的买单排队
买三 10.98  3800 手   ← 上次回踩没买到的人，都挂在这

还有一笔账要算清：触碰不是越多越硬，也可能越测越薄。每次回踩 9.6 元，排在档位上的买单就被成交吃掉一批；新的接盘挂单要等新的人产生兴趣。供给消耗与新人补充在赛跑——前三波卖单把排队买单一层层吃掉，第四波常常直接穿过去。所以「三次触碰的位第四次易破」是机制上说得通的经验，不是定律。触碰次数量的是位被证明过几次，不承诺它守得住下一次。谁的成本压在哪个价位，下一章的筹码分布会画出整张地图，这里先把机制记下。

假突破：路口的收割机制 ​

位既然多人盯着，就有第二种人盯着盯位的人。假突破（false breakout——价格刺破支撑或阻力后又迅速收回原侧的走势，专门收割止损盘与追单）的机制在盘口上一层层看得见，不需要阴谋论。止损盘指买家们进场前就定好的认输卖价：跌到那里，自动变卖单。

  1. 止损扎堆。多头买入后把止损单挂在支撑位下方一点点——人人都这么挂，位的另一侧三五个价位内堆着一层止损卖单。
  2. 刺破触发。价格跌穿支撑，这层止损单全部触发。A股没有交易所原生的止损单，止损靠行情 App 的条件单实现：触发后台代下委托。按市价口径就是吃单（第 2 章的规则）。瞬间涌出的卖单，去砸下方已经变薄的买单簿。
  3. 加速下探。卖单撞进的正是真空区——原来排在支撑附近的买单刚被跌穿时消耗殆尽，价格一根 K 线内砸出一截。
  4. 收回。触发完的止损没有了后续卖压，事先在低位挂买单的人成交接货，价格弹回支撑上方。止损者卖在了最低点，追空的人套在低位。

整个过程可以没有任何人操纵：止损单扎堆本身就是下跌的燃料。有没有资金故意砸穿这层止损，盘面上看不出来——能说的只是，扎堆的止损给「刺破后收回」这种走势发了工资。反方向同理：向上假突破引诱追买单进场，冲高后大单压回，追单被套在山顶。

所以判读突破必须先声明口径，第 10 章趋势线用过的那句在这里原样适用：盘中影线刺破不算，收盘站稳才算。写成条件句：若你持有多头仓位、价格收盘跌破支撑，常见的应对是次日收盘仍在其下就执行离场，不等反弹。若盘中刺破而收盘收回（假突破的形状），常见的应对是不动仓位、也不抢反抽。假突破事后看是机会，事中它与真突破形状相同。区分要靠次日收盘与量能——真突破常伴随放量，第 12 章的量能刻度直接可用。失效条件也要写明：连续两日收盘收不回原侧，或收回后量能持续萎缩，按真突破处理。

枢轴点：把「拐角」变成函数 ​

判据的地基第 10 章已经打好，只是当时是导出脚本里的教学标注。枢轴点（pivot——一段行情里掉头的局部高点或低点拐角）的判据一句话：某个高点，左右各 k 根 K 线的高点都没有超过它，是波峰；低点同理是波谷。本章把它正式搬进实验场，判据一字不改，k 默认仍是 3。

ts
// src/levels/pivots.ts · pivots 全貌
/** 枢轴识别：一个高点在左右各 k 根内都是严格最高，是波峰；一个低点同理是波谷。
 *  判据与第 10 章教学标注逐字一致：
 *  - 严格不等号——两个相等的高点谁也不是峰（平顶留给第 7 章的双根形态，这里不越界）；
 *  - 需要右侧 k 根——最新 k 根内的拐角要等窗口凑满才确认，这不是缺陷是诚实：
 *    枢轴是回顾性判据，把它当实时信号用，等于逼它在没有证据时下结论；
 *  - 原始极值里同类相邻时只留更极端的一个——峰谷必须交替，行情才被切成一段段坡。 */
export function pivots(candles: readonly Candle[], k: number = DEFAULT_PIVOT_WINDOW): Pivot[] {
  assertPivotArgs(candles, k, 'pivots')
  const raw: Pivot[] = []
  for (let i = k; i < candles.length - k; i++) {
    let isHigh = true
    let isLow = true
    for (let j = i - k; j <= i + k; j++) {
      if (j === i) continue
      if (candles[j].high >= candles[i].high) isHigh = false
      if (candles[j].low <= candles[i].low) isLow = false
    }
    if (isHigh) raw.push({ index: i, side: 'high', price: candles[i].high })
    if (isLow) raw.push({ index: i, side: 'low', price: candles[i].low })
  }
  const kept: Pivot[] = []
  for (const p of raw) {
    const last = kept[kept.length - 1]
    if (!last || last.side !== p.side) kept.push({ ...p })
    else if ((p.side === 'high' && p.price > last.price) || (p.side === 'low' && p.price < last.price))
      kept[kept.length - 1] = { ...p }
  }
  return kept
}

两个诚实条款值得再念一遍。其一，需要右侧 k 根：最后一根 K 线冲出全程新高，也不能当场宣布枢轴——拐角要等 3 根之后才能确认，这不是缺陷，是判据拒绝在没有证据时下结论。其二，严格不等号：两个相等的高点谁也不是峰，恰好压平的平顶不归这里管（第 7 章的双根形态有它自己的容差判据）。

聚类成位：从拐角到路口 ​

拐角有了，位就是拐角的聚类。手画为什么打脸？因为「11.04 和 10.97 算不算同一个位」全凭眼睛裁量。写成判据只有三步：枢轴价位从低到高排队；相邻两个的差不超过容差 tol 就并成一群；群内价位的平均数是位价，群的个数是触碰次数。

ts
// src/levels/levels.ts · 位的类型
/** 位的角色：位在最新收盘价上方是阻力（涨到有人抛），下方是支撑（跌到有人接） */
export type LevelKind = 'support' | 'resistance'

/** 一个支撑/阻力位 */
export type Level = {
  /** 位价：簇内枢轴价位的算术平均 */
  price: number
  /** 触碰次数：聚进这个位的枢轴个数——路口被路过几次 */
  touches: number
  /** 与最新收盘价比出的角色：位本身不变，角色随价格站边换（支撑阻力互换的机制落点） */
  kind: LevelKind
  /** 触碰发生的 K 线下标（时间旧→新），逐个可回图核对 */
  indices: number[]
}

拿上图的真实数字跟着算一遍，容差取 0.2 元：

text
高点价位升序：10.93、10.97、11.04
相邻差 0.04、0.07，都 ≤ 0.2 → 并成一群（触 3）
位价 =（10.93 + 10.97 + 11.04）÷ 3 = 32.94 ÷ 3 = 10.98 元
低点同理：9.59、9.61、9.62 → 一群，位价 9.61 元（触 3）
末根收盘 11.60 元：10.98 在其下 → 角色「支撑」；9.61 也在其下 → 角色「支撑」

画到图上。两条横线不是画线工具画出来的——它们是 levels 聚类的输出，以等值序列铺在叠加层上；每一枚触碰标记对应表里的一根 K 线。

先看顶。第 8、24、38 根三次试顶，一次比一次低（11.04 → 10.97 → 10.93），每次都被位的卖墙打回——前两波的买盘在墙下耗尽。第 50 根第四次上攻，收盘 11.09 元站上位价 10.98 元，第 52 根收 11.60 元。这时图例变了：顶位的名字成了「支撑 10.98（触 3·原阻力）」。位没有动，动的是价格的站位——位的角色由价格站在哪边决定，不由它的历史决定。这正是「破了又立」的另一面：支撑跌破后就不再自动是支撑，它变成头顶的阻力；哪天收盘站回去，它又变回支撑。同一个价位，三种身份，判据只有一条：和最新收盘价比高低。

开章那三次打脸现在能说清了。你在 18.6 画线，是把它当墙；实际上它是路口——排队的人每一波都会换。判据版本的操作是：位在哪，聚类说了算；被证明过几次，触碰次数说了算；破没破，收盘口径说了算。三件事都有数，打脸的「手感」就没有位置了。容差是这套判据唯一的自由度（图上显式取 0.2 元，实验场默认取全序列平均振幅的一半），调容差会改群的边界——但调多少、结果怎么变，是摆在明面上的参数，不是屏幕上的手感。

斐波那契回调：自我实现的刻度 ​

最后一种位，不由历史触碰聚成，由比例算出。斐波那契回调（Fibonacci retracement——在一段已走完的行程上，按 0.236、0.382、0.5、0.618 等固定比例从终点往回画的潜在回撤刻度）是行情软件里的标配工具。按陌生概念的四步走。

成因。比例来自斐波那契数列相邻项的比值（1、1、2、3、5、8……每项除以后一项，收敛到 0.618 一带）。但行情为什么理睬一串数学比值？它不理睬。斐波那契刻度起作用的原因只有一条：行情软件给了一键画线，全市场的人在同一时段、同一段明显行情上，画出几乎同一组数。买方在 0.382、0.5 附近预先埋单，回踩到位时真有承接，于是「灵了」，于是下一次更多人埋单。斐波那契不是自然规律，是一份用的人多了就部分兑现的约定——它失效的方式也在这句话里：用的人不再信，它就什么都不是。

载体。一段行程两条边界，往回拉三道刻度：

text
终点 ② 13.09 ─┬─ 0.236 ─ 12.41   （浅回撤：强势整理）
              ├─ 0.382 ─ 11.99   （常见第一档承接）
              ├─ 0.500 ─ 11.65   （半分位，交易界加的，不是数列比值）
              └─ 0.618 ─ 11.31   （深回撤：再往下跌，行程存疑）
起点 ① 10.21 ─┘

演算。上图行情里，行程两端不是随手选的，是 pivots 扫出的两个拐角：起点谷 10.21 元（第 4 根），终点峰 13.09 元（第 24 根）。行程 = 13.09 − 10.21 = 2.88 元。0.5 档 = 13.09 − 2.88 × 0.5 = 13.09 − 1.44 = 11.65 元；0.382 档 = 13.09 − 1.10 = 11.99 元；0.618 档 = 13.09 − 1.78 = 11.31 元。回踩谷 11.49 元（第 33 根）落在哪一档？回撤比例 =（13.09 − 11.49）÷ 2.88 = 1.60 ÷ 2.88 ≈ 55.6%，在 0.5 与 0.618 之间。锚点：在一段涨幅上按黄金分割比例画刻度——用的人多了，刻度本身变成路口。

ts
// src/levels/fib.ts · fibLevels 全貌（含刻度常量）
/** 四档回调比例：升序固定，0.5 不是斐波那契比值、是交易界硬加进来的半分位 */
export const FIB_RATIOS = [0.236, 0.382, 0.5, 0.618] as const

/** 一档回调刻度 */
export type FibLevel = {
  /** 回调比例：0.382 即从 to 往 from 方向回撤行程的 38.2% */
  ratio: number
  /** 刻度价位：to − (to − from) × ratio */
  price: number
}

/** 回调刻度：给定行程两端 from 与 to（涨跌皆可），返回四档刻度（按比例升序）。
 *  涨幅段（from 低 to 高）量的是回撤支撑候选；跌幅段（from 高 to 低）量的是反弹阻力候选——
 *  同一条算式，方向由两端的相对位置自带。两端相等是零段行程，没有回调可言，拒绝计算。 */
export function fibLevels(from: number, to: number): FibLevel[] {
  if (!Number.isFinite(from) || !Number.isFinite(to)) {
    throw new Error(`fibLevels：from 与 to 必须是有限数字，收到的是 ${from}/${to}`)
  }
  if (from === to) {
    throw new Error('fibLevels：from 与 to 不能相等——零段行程没有回调刻度可言')
  }
  return FIB_RATIOS.map((ratio) => ({ ratio, price: to - (to - from) * ratio }))
}

三道刻度与回踩谷同图。每道刻度都是一条等值横线。第 33 根的低点 11.49 元扎进 0.5 到 0.618 之间的地带，随后回升，末根收在 11.79 元。一张图讲一个故事，但失效场景必须同时说透。其一，单边强势行情不给回踩：刻度画好了，价格贴着 0.236 上面就走，等回踩的人踏空。其二，噪声大的行情回踩过深：跌破 0.618 甚至跌回起点，这段行程本身作废，刻度跟着作废。其三也是最要命的：行程两端是人选的——选不同的两个拐角，行程不同，刻度整体平移。同一段行情，甲从大拐角画、乙从小拐角画，两个人的 0.382 相差好几个点，谁也不比谁权威。所以条件句只能是：若价格回踩进入 0.382 到 0.5 一带、且出现缩量回踩加放量收复的承接（量能刻度用第 12 章的），常见的应对是把止损放在 0.618 下方一点的位置参与；收盘跌破 0.618 即失效，按行程作废处理，不与刻度吵架。

见红后实现。三个新模块都是小纯函数：src/levels/pivots.ts 与 src/levels/fib.ts 的全貌前文已贴，levels 的聚类主体补在这里。

ts
// src/levels/levels.ts · levels 全貌
export function levels(candles: readonly Candle[], opts: LevelsOpts = {}): Level[] {
  if (!Array.isArray(candles) || candles.length === 0) {
    throw new Error('levels：candles 不能为空')
  }
  const k = opts.k ?? DEFAULT_PIVOT_WINDOW
  const tol = opts.tol ?? avgRange(candles) / 2
  if (!(tol > 0) || !Number.isFinite(tol)) {
    throw new Error(`levels：tol 必须是正数（聚类容差），收到的是 ${tol}`)
  }
  const lastClose = candles[candles.length - 1].close
  if (!Number.isFinite(lastClose)) {
    throw new Error(`levels：最后一根的收盘价必须是有限数字（位的角色由它比出），收到的是 ${lastClose}`)
  }
  const ps = pivots(candles, k)
  if (ps.length === 0) return [] // 凑不出枢轴就凑不出位：不猜
  // 聚类：价位升序排，相邻差 ≤ tol 并成一群（顺序聚类，一群可略宽于 tol——拥挤本身就说明这是个宽路口）
  const sorted = [...ps].sort((a, b) => a.price - b.price)
  const clusters: Pivot[][] = []
  for (const p of sorted) {
    const cur = clusters[clusters.length - 1]
    if (cur && p.price - cur[cur.length - 1].price <= tol) cur.push(p)
    else clusters.push([p])
  }
  return clusters
    .map((cluster): Level => {
      const price = cluster.reduce((s, p) => s + p.price, 0) / cluster.length
      return {
        price,
        touches: cluster.length,
        kind: price > lastClose ? 'resistance' : 'support',
        indices: [...cluster].sort((a, b) => a.index - b.index).map((p) => p.index),
      }
    })
    .sort((a, b) => b.price - a.price)
}

简化之处照实声明并登记附录差异清单：枢轴判据取 k=3 与严格不等号（平顶不判、确认延迟 3 根）；触碰按枢轴计数，未形成拐角的回踩不算触碰；聚类容差图上取 0.2 元、默认取平均振幅一半，顺序聚类允许一群略宽于容差；位的角色按最新收盘价二分，恰压位价的情形未特殊处理；斐波那契 0.5 档非数列比值；行情为固定种子的路径合成数据，非真实行情。

小结 ​

  • 支撑阻力的成因有二：盘口的挂单聚集（位的实体）与锚定效应（位的位置候选）；位是人多的路口，不是墙。
  • 假突破的收割机制在盘口上自洽：止损扎堆、刺破触发、市价吃单砸进薄档、无后续卖压后收回——判读口径是收盘站稳，量能做旁证。
  • 枢轴判据从第 10 章教学标注转正，一字未改：左右各 k 根严格极值加同类去重；确认延迟 k 根，平顶不判。
  • 位是枢轴价位的聚类：位价取簇均值、触碰次数取簇大小、角色由最新收盘价比出；支撑阻力互换不靠记忆，靠站位。
  • 斐波那契回调是自我实现的约定：全市场画同一组数，刻度变成路口；行程两端是人选的，这是它最大的软肋，跌破 0.618 即行程作废。
