# 指令集全家福：五十六条官方指令

两个来自真实游戏的症状。其一：主角中弹，血量应该从 1 减到 0，屏幕上却跳出 -1 和一串乱码——程序员忘了，`SBC` 减法借的是进位（carry）标志 C，用之前没 `SEC`（把 C 置 1），减出来的数差了一。其二：菜单按一下「下」，光标直接穿到最后——分支（branch，查便签决定要不要跳走的指令）看错了便签，本该查「不等于零」的 `BNE` 写成了查「等于零」的 `BEQ`，循环一次都没进。这一章把五十六条官方指令一次装齐，这些翻车点的每一个，都会变成你亲手断言过的行为。

56 条听着吓人，其实五十四条是老朋友的三种新组合：老动词（装入、存储、算逻）、老状语（上一章的寻址模式）、加上几张新便签的读写。真正的新知识只有三块：进位与溢出（两个「加出格了」的警报，马上细说）这对便签的分工；子程序（subroutine，用完即返回的小段程序）怎么靠栈记住回路；比较（只做减法、只留便签）怎么和分支（查便签决定跳不跳）搭档。

## 一、全景：五十六条在干什么

```text
装入/存储  LDA LDX LDY STA STX STY     数据在寄存器与内存间搬家
传送      TAX TAY TXA TYA TSX TXS     寄存器之间直接倒手
栈        PHA PHP PLA PLP             压栈/弹栈（A 或标志字节）
算术      ADC SBC INC DEC INX INY DEX DEY
逻辑      AND ORA EOR BIT             位运算 + 位测试
移位旋转  ASL LSR ROL ROR             连同进位 C 一起转
比较      CMP CPX CPY                 只动便签不动寄存器
跳转      JMP JSR RTS RTI BRK         去哪、怎么回来
分支      BCC BCS BEQ BNE BMI BPL BVC BVS  查便签决定跳不跳
标志开关  CLC SEC CLI SEI CLV CLD SED
空操作    NOP
```

数一数正好五十六个名字。它们乘上寻址模式，展开成 151 个 opcode——上一章的指令表骨架这次批量入住，靠的是组合子：动词函数乘以寻址函数，自动铺出整族变体。

```ts
// src/cpu/instructions.ts · readerOps（8 变体读取族的装配线，节选）
function readerOps(apply: Apply, [opImm, opZp, opZpx, opAbs, opAbsx, opAbsy, opIzx, opIzy]: number[]): void {
  def({
    [opImm]: imm(apply),
    [opZp]: at(zeroPage, 3, apply),
    [opZpx]: at(zeroPageX, 4, apply),
    [opAbs]: at(absolute, 4, apply),
    [opAbsx]: at(absoluteX, 4, apply),
    [opAbsy]: at(absoluteY, 4, apply),
    [opIzx]: at(indirectX, 6, apply),
    [opIzy]: at(indirectY, 5, apply),
  })
}

readerOps(ldaA, [0xa9, 0xa5, 0xb5, 0xad, 0xbd, 0xb9, 0xa1, 0xb1]) // LDA 全族
readerOps(adcA, [0x69, 0x65, 0x75, 0x6d, 0x7d, 0x79, 0x61, 0x71]) // ADC 全族
```

`LDA`、`ADC`、`AND`……七个「8 变体族」共用这一条装配线，只有 apply 动词和八个 opcode 号不同。五十六条指令的实现代码，体量跟它的名声完全不符。

## 二、进位与溢出：两张便签的分工

C 和 V 都是「加法出了格」的便签，但它们服务两套读法：

- C（进位，carry）服务无符号读法：255 是上限，`$FF + $01` 装不下，C=1。它是多字节大数运算的接力棒——低字节的进位，让高字节用 `ADC` 接住。
- V（溢出，overflow）服务带符号读法：一格字节两副面孔，正数上限 127，`$50 + $50`（80+80）按补码读是 80+80=160，超出了 127，V=1。程序想处理「带符号的数」时查它。

演算一遍接力。十六位数 `$00FF + $0001` 用两步装进两格字节：低字节 `CLC; LDA #$FF; ADC #$01` 得 `$00` 且 C=1；高字节 `LDA #$00; ADC #$00`——看仔细，加的是零，但 ADC 会把上一步的 C 加进来，得 `$01`。合起来 `$0100`，分毫不差。血量显示 -1 那个 bug 的根源就在这：**SBC 全程靠 C 传借位，用前必须 `SEC` 把它置 1**（置 1 的含义是「先假装不借位」），否则差一。

```ts
// src/cpu/instructions.ts · adcA（进位与溢出怎么写）
function adcA(cpu: CPU, m: number): void {
  const sum = cpu.a + m + (cpu.c ? 1 : 0)
  cpu.c = sum > 0xff
  cpu.v = (~(cpu.a ^ m) & (cpu.a ^ sum) & 0x80) !== 0 // 同号相加变号 = 溢出
  cpu.a = sum & 0xff
  cpu.setZN(cpu.a)
}
```

V 那行位运算值得三秒钟注视：操作数同号（`~(a^m)` 最高位为 1）而结果变了号（`a^sum` 最高位为 1），才是溢出——异号相加永远安全。至于减法：`SBC` 的实现是把操作数按位取反后直接进 `adcA`——第 1 章的补码在电路层的回声，减法器电路就这么被省掉了，一条 `m ^ 0xff` 白送。

## 三、子程序与栈：怎么记住回来的路

JSR（jump to subroutine，跳去子程序）要解决一个跳转没有的问题：跳走之后怎么回来？答案是栈——RAM `$0100-$01FF` 这 256 格，配 SP 指针。JSR 把「回来的门牌」压进栈再跳走；RTS（return from subroutine，从子程序返回）从栈里弹出它跳回来。

配对里藏着本章开篇那个「跳进去回不来」的经典坑：JSR 压栈的不是返回地址，是返回地址减一；RTS 弹出后要加一。这套别扭绕圈来自 1975 年的电路走线，没人能修，只能照抄：

```ts
// src/cpu/instructions.ts · JSR 与 RTS（节选）
0x20: c => { // JSR：压「返回地址-1」，RTS 弹出后 +1 回到下一条
  const target = absolute(c)
  const ret = (c.pc - 1) & 0xffff
  c.push(hi(ret))
  c.push(lo(ret))
  c.pc = target
  return 6
},
0x60: c => { // RTS
  const l = c.pop()
  const h = c.pop()
  c.pc = (word(l, h) + 1) & 0xffff
  return 6
},
```

压栈顺序是高字节在先、低字节在后，弹栈反着来——6502 栈向下长（SP 减小），弹出的必须是最后压进的低字节。JSR/RTS 差一字节、PHA/PLA 顺序颠倒，两类症状在自制模拟器里都高发，我们的测试把「跳去、干活、回到调用点下一条」整条链路断言了一遍。

## 四、比较与分支：便签的读者终于登场

从第 4 章贴上 Z/N/C 便签到现在，一直没人读它。本章它们的两批读者到了。

比较指令 `CMP` 做一次减法但把结果扔掉，只留便签：A 和操作数谁大（C）、等不等（Z）、差是正是负（N）。寄存器本身毫发无伤——这就是它和 `SBC` 的全部区别，游戏里「血量够不够买装备」这类判断全靠它。

分支指令查一张便签决定跳不跳：`BNE` 查 Z=0（上一条的结果不是零就跳）、`BEQ` 查 Z=1，`BCC/BCS` 查 C，以此类推。跳的目标用上一章的相对寻址。两者一配合，「循环」就诞生了：

```text
LDX #3        ; 计数器 3
loop: DEX     ; 3 → 2 → 1 → 0
BNE loop      ; X 不是 0 就回 loop
```

本章测试里跑的「数组求和」是完整形态：`LDA (data,Y)` 取数、`ADC` 累加、`STA` 存回、`INY/DEX` 推进、`BNE` 回环，最后 `JSR` 进子程序把结果搬家——循环、子程序、分支、进位链在一次运行里全部当值。

## 五、这一轮真实踩过的三个坑

先测后写在第六章格外值钱，三个坑全是被测试当场抓获的，值得留给读者：

第一个坑在上一章就埋下了：`indirect` 读低字节时把指针当成了零页地址（`read(ptrLo)` 而非 `read(指针)`），而第 5 章那条测试竟然是绿的——它把指针数据写在 `$0800`，恰好经 RAM 镜像落进 `$0000`，bug 读的格子和测试写的格子被镜像缝在了一起。直到本章用 `$02FF` 做指针，巧合消失，bug 现形。教训：**测试绿不等于没 bug，只等于已覆盖的输入下没 bug**。

第二个坑是我自己的汇编：求和循环里 `ADC $20` 后忘了 `STA $20`，累加结果每轮都被下一轮覆盖，最终零页那格纹丝不动。写模拟器的人也会犯汇编的错——「实现正确」和「用得正确」是两回事，断言最终内存状态（而不是只断言不崩）才能抓住它。

第三个坑最隐蔽：INC/DEC 最初忘了更新 Z/N 便签。单看「内存里的数加了 1」完全正确，但它悄悄弄脏了后续每条分支的判断依据——便签是指令间的暗通信渠道，谁忘了贴，谁就把坑埋给别人。

## 小结

- 56 条 = 老动词 × 老状语 + 三块新知：C/V 分工（无符号接力棒与带符号警报）、JSR/RTS 栈配对（压返回地址减一）、CMP 动便签不动寄存器 + 分支查便签。
- SBC 就是取反后的 ADC，减法电路白送。
- 便签是指令间的暗渠道：任何写入内存的指令忘了顺手更新 Z/N，坑都会出现在别人的分支里。
- 测试绿只覆盖已测输入；镜像巧合能让 bug 借绿通行，换指针位置一测即现形。
