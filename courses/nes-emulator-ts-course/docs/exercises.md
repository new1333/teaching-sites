# 练习路线：把实验场亲手再写一遍

读代码是「看会了」，写代码才是「真会了」。`companion/tests/` 里的 107 个断言按章排布、append-only、先红后绿——它们天然是一份 TDD 作业梯子：**实现被抽走，测试还在，你的任务是让它从红转绿**。

## 玩法

```bash
# 1. 克隆本课程仓库后，进入实验场
cd courses/nes-emulator-ts-course/companion
pnpm install

# 2. 清空实现（保留测试与脚手架）
rm -rf src

# 3. 从第 3 章的测试开始
npx vitest run tests/03-cartridge-and-bus.test.ts   # 全红 —— 出发

# 4. 写代码让它变绿，然后：
npx vitest run tests/04-cpu-heartbeat.test.ts       # 下一章
# ……按章号一路走到 tests/12
```

## 三条规则

1. **按章号顺序推进**：后面的测试依赖前面建立的模块（`bits.ts` → `bus.ts` → `cpu/` → `ppu/` → `apu/` → `nes.ts`）。每章测试文件的头部注释和断言名就是需求说明。
2. **旧章测试持续全绿**：每写完一章，回头跑全量 `pnpm test`。旧测试是 API 兼容哨兵——你第 6 章的实现要是破坏了第 4 章的承诺，当场现形。
3. **先看红再动手**：新章测试先跑一次确认失败原因符合预期（缺模块？断言红？），再开始写。红的原因本身是需求文档。

## 提示卡

- 公共 API 面（模块路径、函数签名）见每章测试的 `import` 与调用——测试只依赖公共行为，你可以自由设计内部结构。
- 卡住时回看对应章节正文的「渐进实验」段落与速查表（附录）。
- 想加难度：不看正文，只靠测试名与断言反推需求——这是「测试即规格」的真实练习。

## 毕业项目

跑通全部 12 章测试后，给自己出一道附加题：写一张新卡带（用 `fixtures/makeNromCartridge` 拼字节），让画面格 (0,0) 显示一个 8x8 的「笑脸」图块、循环播放三音符旋律，按 A 键时第 0 号精灵跳到画面中央——这正是第 12 章集成测试的变体，出题人和考生都是你。
