# CPU 心跳：寄存器与取指执行循环

上一章结尾我们埋了一个伏笔：`prgWithReset` 会把入口地址写进卡带末尾的 `$FFFC/$FFFD`。现在开机试试。大部分自制模拟器作者的第一次运行都翻车在同一处：CPU 跑了两三条指令，一头扎进未知的门牌段，最后撞上自家抛出的 `unknown opcode`。抓个现场：程序明明是「装载数据、存起来」三步，可 PC（寄存器——CPU 手边的小格子，马上认识）早已飞出程序区。原因：它把本该当数据的字节 `$05` 又当成了下一条指令，一错再错，直到撞进我们特意设的错误护栏。

跑飞不是 bug，是 CPU 的工作方式没被实现对。这一章给大脑装上心跳：寄存器、标志位、以及那个一切解释器共有的骨架——取指、译码、执行，循环往复。

## 一、六个格子：6502 的全部家当

1975 年的 6502 芯片便宜得惊人（当年售价 25 美元，同行卖 200），便宜的原因之一：内部小得可怜。CPU 内部屈指可数的几个超高速小格子叫寄存器（register）——数据必须先搬进来才能参与运算。6502 的全部工作状态就装在这样几个格子里。

```text
A   累加器      算术逻辑的主工作台，加减、与或都在这做
X   变址 X      既是临时格，也能给地址加偏移
Y   变址 Y      同上，另一个
PC  程序计数器   两个字节宽：下一条要执行的指令的门牌号
SP  栈指针       指向 RAM 里 $0100-$01FF 这 256 格（调用子程序时的「记住做到哪」）
P   标志位字节   六张便签，见下
```

五个数据类寄存器之外，第六个成员 P 不是一格数据，而是打包的六个标志位（flag——CPU 做完一次运算顺手留下的便签，供后续指令查阅）：

- `Z` 零标志：结果是不是 0。
- `N` 负标志：结果最高位是不是 1（按第 1 章的补码读法，就是「是不是负数」）。
- `C` 进位标志：加法满 255 溢出、减法不够借位时亮起，还是多字节大数运算的「进位接力棒」。
- `V` 溢出标志：带符号数加出了 -128~127 的边界——比如 +64 加 +64，结果按补码读成了 -128，V 就亮。指令章会给它一套完整的数值推演。
- `I` 中断屏蔽：一位开关，亮着时对「可屏蔽中断」装聋作哑，接中断的章节会用到。`D` 十进制模式：让加法按十进制算的开关——但 NES 用的这颗 6502 变体根本没实现它，恒为摆设（原版 6502 有，游戏机里这颗被砍掉了），我们保留这个位但永远不动它。

便签的意思是：没有人「使用」标志位的值，除非下一条指令主动去查——分支指令查 Z 决定跳不跳，比较指令查 C 判断大小。CPU 自己从不解释便签，只负责如实记录。

## 二、心跳：CPU 永动的三步循环

程序在内存里不是「代码块」，只是一串字节。让它活起来的，是 CPU 永不停歇的三步循环：

```text
        ┌──────────────────────────────────────────┐
        ▼                                          │
  ┌───────────┐   ┌───────────┐   ┌───────────┐    │
  │ 取指      │──▶│ 译码      │──▶│ 执行      │────┘
  │ 读 PC 处  │   │ 这字节是  │   │ 干完这事  │
  │ 的一个字节│   │ 什么动作？│   │ PC 已指向 │
  │ PC 前进一格│  │           │   │ 下一条    │
  └───────────┘   └───────────┘   └───────────┘
```

取指（fetch）：按 PC 门牌读一个字节，PC 加一。译码（decode）：这个字节是操作码 opcode——一个字节一个动作的编号表，CPU 的动词词典；`$A9` 查表知是「把紧跟的字节装进 A」。执行（execute）：照办，可能还要按需多读几个字节当操作数。然后回到取指，直到断电。

用机器码写「把 5 装进 A，再存到内存 $0200」，就是三个动作的编码。

```text
门牌    字节      动作
$8000   A9 05    LDA #$05  ← 取 A9（译码：装入紧跟字节到 A），执行时再取 05
$8002   8D 00 02 STA $0200 ← 取 8D，执行时再取两字节拼地址，把 A 写过去
$8005   EA       NOP       ← 什么也不做
```

注意 `$8002` 处的两字节操作数 `00 02`。想写地址 `$0200`，内存里躺着的却是低字节 `00` 在前。这个方向叫小端序（little-endian，多字节数据低位字节存前面的排列约定）。6502 全家都是这个方向，第 5 章寻址模式的地址计算会大量跟它打交道，现在先把「低在前」焊进直觉。

每条指令还要花时间——完成一条指令消耗的时钟拍数叫周期数（cycle count）：`LDA #imm` 花 2 拍、`STA abs` 花 4 拍、`NOP` 花 2 拍。眼下的 `step()` 只把它返回出来，真正的用处在第 10 章：主循环要靠它知道「这条指令占了 CPU 几拍、PPU 该跟着走几步」。

## 三、复位向量：开机第一跳的门牌

冷启动的 CPU 面对一个悖论：PC 该指向第一条指令，可 PC 的初值从哪来？答案在上一章的卡带里。开机时 CPU 固定执行一次「读 `$FFFC`、读 `$FFFD`，拼成 16 位装进 PC」——这两个格子就是复位向量（reset vector，一条存放「开机后第一条指令地址」的门牌）。于是游戏厂商把入口地址烧在卡带末尾，CPU 一通电就循着它跳进程序。

这解释了 `prgWithReset` 为什么往 PRG 末两格写字节：16KB PRG 映射到 `$8000-$FFFF`，`$FFFC/$FFFD` 恰好是 PRG 的最后两格。也解释了为什么复位后 SP 是 `$FD` 而不是 `$FF`——6502 的复位本质上是一次「假装的中断」：硬件照中断的规矩把 PCH、PCL、P 三个字节依次压栈，这三个值并不可靠、也没人去读。SP 从上电的 `$00` 起步、向下压三格、在 256 格的栈里绕一圈，正好落在 `$FD`。我们照抄这个结果。

## 四、落地：三十行心跳

寄存器用普通字段、标志位用布尔值——比打包进一个字节直观得多，位打包的练习留在读者手里。核心是 `step()`：

```ts
// 拼版·教学示意：本章的 step 骨架（三条指令的 switch 形态）；
// 仓库 src/cpu/index.ts 里的 step() 终态是「查表驱动 + NMI 入口」，第 6 章讲它的演进
step(): number {
  const opcode = this.fetch()
  switch (opcode) {
    case 0xa9: {                       // LDA #imm：立即数装入 A
      const v = this.fetch()
      this.a = v
      this.setZN(v)
      return 2
    }
    case 0x8d: {                       // STA abs：A 写入绝对地址
      const lo = this.fetch()          // 先读低字节（小端序）
      const hi = this.fetch()
      this.bus.write(word(lo, hi), this.a)
      return 4
    }
    case 0xea:                         // NOP
      return 2
    default:
      throw new Error(`unknown opcode ${toHex(opcode)} at ${toHex16(this.pc - 1)}`)
  }
}
```

三个细节值得停一下。`fetch()` 每读一字节 PC 顺手指向下一格，取指与取操作数共用它，PC 的推进天然正确。`setZN` 是「便签纪律」：装入类指令必须顺手更新 Z/N，分支指令将来要靠它判断。最后那个 `throw` 是我们给跑飞装的护栏：撞见不认识的 opcode，报出「什么字节、在哪个门牌」，而不是静默地错下去——本章开头那个跑飞现场，最后就是被它逮住的。

## 小结

- 6502 的家当：A/X/Y 三个通用格、PC 下一条门牌、SP 栈顶指针、六张标志便签（Z/N/C/V/I/D）。
- 取指-译码-执行循环是一切解释器的心脏；opcode 是一个字节一个动作的编号，操作数低字节在前（小端序）。
- 复位向量 `$FFFC/$FFFD` 解决「PC 初值从哪来」；SP 复位值 $FD 照抄真机。
- 每条指令有周期数，`step()` 返回它，第 10 章的主循环靠它同步 PPU。
- 未知 opcode 抛错带地址，跑飞第一时间暴露。

自查：`A9 05 8D 00 02 EA` 这串字节执行完后，A、$0200、PC 各是什么？LDA #$80 会点亮哪张便签、为什么？下一章把这个三词动词表扩成十三种「去哪取操作数」的说法——同一个 LDA，有八种写法。
