# 模拟器是一台「假机器」：整机地图与施工路线

「我下载了 6502 的指令手册，抄了三天 opcode 表。第四天想写第一行代码，盯着空文件发呆——CPU 要总线，总线要卡带，卡带里的程序又要等 PPU 的信号……先写哪个？全都互相依赖，全都写不动。」这不是虚构的崩溃独白，是这类「假装一台机器」的项目最常见的弃坑现场。代码一行没写就放弃，问题不在毅力，在没有地图。

这一章仍然不写代码。我们要画出全书的施工图：NES 里住着谁、它们靠什么节拍协作、这门课的十二步分别盖哪块砖。地图在手，后面每一步你都知道自己站在哪。

## 一、模拟器在「假装」什么

模拟器（emulator）——用软件扮演一整台机器的程序。它要让 1983 年为 NES 写的游戏代码相信：自己正运行在一颗真的 6502 CPU、一块真的图形芯片上。判定成败的标准只有一条：**跑在模拟器里的程序，行为和跑在真机上分不出差别。**程序是唯一考官，它读到的每个数字、收到的每个信号都得对。

被扮演的这台机器是 1983 年任天堂推出的家用游戏机 NES（欧美市场叫 NES，日本叫 Famicom——两者主板几乎相同，本文统一称 NES）。它是「8 位机」：CPU 一口一箱，每箱一个字节。性能寒酸，但正因如此，整台机器小到可以被一个人完整理解——这也是为什么几十年后仍有人为它写模拟器入门。

## 二、三演员一台戏

打开机壳，主板上真正干活的是三颗芯片加两个外设。

**CPU 6502——大脑。**一颗 8 位处理器，负责执行卡带里的程序：读手柄、算逻辑、决定下一帧画面摆什么。它有自己的几个寄存器（下一部分章节展开——CPU 手边几个超高速小抽屉），以及一个重要癖好：**它眼里的世界只有一排门牌号**，从 $0000 到 $FFFF 共 64KB。它不关心门牌背后是内存、是显卡还是手柄，访问 $2002 和访问 $0000 在它看来毫无区别。这个「一视同仁」的癖好，正是第 3 章的主角。

**PPU 2C02——画师。**专用的图形芯片，NES 画面的全部出自它手。关键在于它和 CPU 是分家的：PPU 自带一套记忆——图案册、拼贴布局、调色板、精灵登记表（这些名字到画面部分再一一展开），CPU 的 64KB 门牌里摸不到这套记忆的任何一个字节。CPU 想改画面，只能通过 8 个寄存器（可以想成传菜窗口）递单子：设置窗口地址、一个字节一个字节地塞数据。画师则按自己的节拍，把图案画成 256×240 像素的一帧送进电视。

**APU——乐手。**音频电路，物理上和 CPU 封装在同一块芯片里，但在模拟器里我们把它当独立演员对待：四个声道（两种方波、一种三角波、一种噪声），各自独立发音，由程序写寄存器控制。它是全书最后登场的部件。

卡带——剧本仓库。游戏本体不在主机里，而在插着的卡带上：PRG ROM 存程序（给 CPU 的剧本）、CHR ROM 存图形图案（给 PPU 的画册）。卡带上还有一块换页电路（mapper），本课程只实现最简单的 0 号方案，其余的在附录提一句去向。

手柄——唯一的输入。按键状态通过 $4016 这个门牌按位读出，具体协议留到合体章。

## 三、全机的节拍器

三个演员各干各的就会乱套，全机靠一个晶振节拍器同步——主时钟（master clock），一块每秒振动两千多万次的石英，所有芯片的每一步都按它的拍子走。NES 里 CPU 和 PPU 跑的速度不一样：**PPU 的动作频率是 CPU 的 3 倍**。成因很实在：PPU 每秒要吐出 60 帧画面、每帧几十万个像素，活多手快；CPU 做的是逻辑判断，可以慢条斯理。模拟器里我们不需要真的造一个每秒 2100 万拍的晶振，只需要保住这个比例——CPU 走一步，PPU 走三步，1:3 就是全书主循环的心跳。

## 四、一帧的诞生

把节拍器和 PPU 合起来看，就能看懂「帧」——电视上的一幅完整画面——是怎么诞生的。1983 年的电视是阴极射线管：电子枪从左上角开始，一行一行往右扫出亮点，扫完一行跳回下一行开头，扫满 240 行后回到左上角，如此往复。每一行叫一条扫描线（scanline）。

```text
一帧 = 262 条扫描线，每条 341 个 PPU 周期，每秒 60 帧

扫描线   0-239 │ 可见区：PPU 逐行画出 256×240 的画面，此时不让 CPU 改数据
扫描线     240 │ 画完最后一行：PPU 拉响「收工铃」（VBlank 开始）
扫描线 241-260 │ 歇息窗口（VBlank）：电子枪正在回程，CPU 抓紧改下一帧的数据
扫描线     261 │ 预热：PPU 取好下一帧第一批图案，回到扫描线 0
```

VBlank（垂直消隐，vertical blanking的缩写）——电子枪从画面底端回到左上角的回程空档，约 20 条扫描线那么长。它是全机最重要的协作窗口：画面正在显示时改画面的数据，观众会看到撕裂和花斑；VBlank 期间电子枪在「赶路」，改数据绝对安全。所以几乎每个 NES 游戏的主循环都是同一个形状：等 VBlank 来 → 在窗口里把下一帧的数据备好 → 回去处理逻辑 → 再等下一次。

「收工铃」由 PPU 拉响、CPU 接听，接听动作叫中断（interrupt）——硬件打来的电话铃：CPU 暂停手头工作、按门牌号找到处理程序、办完回来继续。它的完整机制在第 10 章实现，此刻你只需要记住画面协作的节奏：**画的时候不许改，改的时候在窗口。**

## 五、整机结构图

把上面所有部件放进一张图。这张图就是全书的施工总平面，建议留着随手翻：

```text
// 拼版：整机结构总平面图（全课程唯一一张总图）
                    ┌────────── 主时钟（节拍器）──────────┐
                    │  每一拍：CPU 动 1 步 · PPU 动 3 步    │
                    └──────────────┬─────────────────────┘
                                   ▼
     ┌─────────────── CPU 6502（大脑：跑程序）───────────────┐
     │  · 寄存器：A/X/Y/PC/SP/P（手边小抽屉）                │
     │  · 地址视野：64KB 门牌号 $0000-$FFFF                  │
     └───┬───────────────┬───────────────┬─────────────────┘
         │ 总线（64KB 门牌街，读写都从这里走）                │
   ┌─────┴─────┐   ┌─────┴─────┐   ┌─────┴─────┐   ┌──────┴─────┐
   │ 2KB RAM   │   │  卡带     │   │ PPU 窗口   │   │ APU/手柄    │
   │ 临时草稿纸 │   │ PRG 程序  │   │ $2000-07  │   │ $4000-401F │
   │ $0000-07FF│   │ CHR 图案  │   │ 8 个寄存器 │   │ 声音与按键  │
   └───────────┘   └───────────┘   └─────┬─────┘   └──────┬─────┘
                                         ▼                ▼
                          ┌── PPU 2C02（画师）──┐   ┌── APU（乐手）──┐
                          │ 自带记忆（CPU 摸不到）│   │ 4 个独立声道    │
                          │ 图案册/拼贴/调色板/OAM│   │ 方波×2 三角 噪声 │
                          │ 输出 256×240 帧 → 电视│   │ 输出声音 → 扬声器│
                          └────────────────────┘   └───────────────┘
```

看图读一遍一帧的旅程：游戏程序（在 PRG 里）被 CPU 执行 → CPU 通过 PPU 窗口把图案和布局备进画师的记忆 → PPU 按节拍画出整帧 → 扫到 240 线拉响 VBlank 收工铃 → CPU 接到中断，在窗口里更新下一帧数据。声音则独立并行：程序写 APU 寄存器，乐手自己发声。

## 小结

- 模拟器的唯一考官是程序本身：行为分不出差别，就算扮演成功。
- 三个演员：CPU 大脑（只认 64KB 门牌）、PPU 画师（记忆分家、只开 8 个寄存器窗口）、APU 乐手（四声道独立）；外加卡带剧本仓与手柄输入。
- 全机一个节拍器：CPU 动一步、PPU 动三步，1:3 是主循环的心跳。
- 一帧 262 条扫描线：可见区画、240 线拉铃、VBlank 窗口改数据；「画时不改、改在窗口」是全机协作的纪律。
- 十二步施工表已排定，下一步从门牌街开工。

自查三问：为什么 CPU 改不了 PPU 的记忆、只能递窗口？1:3 的成因是什么？VBlank 为什么是改画面的唯一安全期？答得上来，这张地图就长在你脑子里了。下一章开工：把 ROM 文件里的卡带解析出来，铺好那条 64KB 的门牌街。
