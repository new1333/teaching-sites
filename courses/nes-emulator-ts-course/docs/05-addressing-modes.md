# 寻址模式：同一个动作的十三种说法

一个真实的翻车现场：想让 CPU 从内存 `$40` 取个数，程序里写下的机器码是 `AD 40 00`——`AD` 是「绝对地址版取数」，操作数 `40 00` 拼出的地址是 `$0040`，看起来没事。可另一位作者想取 `$4000`，手滑写成了 `A5 40 00`——`A5` 只吃一个字节当门牌，那个 `00` 就被当成了下一条指令。程序跑飞，内存被一串错误写入砸得稀烂，崩得毫无征兆。同一个「取数」动作，6502 有十三种写法，写错一种，轻则读错门牌，重则整条指令流错位。

这一章把这十三种说法一次讲清、全部实现。它们是第 6 章五十六条指令的地基——指令是动词，寻址是状语，动词只有寥寥几个，状语才是 6502 编程的主角。

## 一、操作数从哪来：十三种约定

CPU 每条指令都要回答一个问题：操作数在哪？在指令流里、在家门口、在任意门牌、还是在指针格记着的门牌？每种答案就是一种寻址模式（addressing mode——「操作数从哪来」的约定）。先给全表，再挑最难的三种细讲：

```text
立即数 #imm     数据就在指令流里：A9 05，紧跟的 05 就是数本身
零页 zp        门牌在 $00-$FF：A5 05，一个字节当门牌，省一个字节
零页,X         零页门牌加 X 变址
零页,Y         同上，加 Y（只有 LDX/STX 用到）
绝对 abs       两个字节拼任意门牌：AD 00 02 → $0200
绝对,X / 绝对,Y  绝对门牌加变址，可跨页
间接 (abs)     指针格里存着真正的门牌（只有 JMP 用）
(零页,X)       先加 X 找到指针格，再取门牌
(零页),Y       先取门牌做基址，再加 Y
相对 rel       单字节偏移，给分支指令用
隐含           操作数隐含在指令名里：NOP、INX，没有操作数
累加器         操作数就是 A 本人：ASL A，第 6 章见
```

十种要算地址，各是一个函数；隐含和累加器没有操作数，立即数直接从指令流取——这三种天然不进地址函数。先看为什么家门口那 256 格值得单独一套寻址。

## 二、零页：家门口的 256 格

零页（zero page）——地址 `$0000-$00FF` 这 256 格，门牌高字节恒为 `00` 的那一页。页（page）——256 字节为一页，高字节就是页号。零页是第 0 页，CPU 家门口。

为什么专门为它设计一套寻址？钱。1975 年内存按字节计价，指令长度就是成本：`AD 34 12`（绝对，三字节）与 `A5 34`（零页，两字节）访问同一格 `$1234` 之外的所有零页格，后者省一个存储字节、还少读一次内存快一拍。翻翻 6502 程序，零页永远是最挤的地方——编译器把它当寄存器组的延伸用，256 格寸土寸金。

零页的代价是一条特殊纪律：零页里的地址运算只在 8 位里转。`$FF + 3` 不进位到 `$102`，而是回绕（wrap-around，加满 255 后从 0 重新数）到 `$02`。硬件成因：零页寻址的加法器只有 8 位宽，高字节根本没有参与运算。我们的实现一行就是这个事实：

```ts
// src/cpu/addressing.ts · zeroPageX
export function zeroPageX(cpu: CpuCore): number {
  return (cpu.fetch() + cpu.x) & 0xff // 零页回绕：加完仍锁在 $00-$FF
}
```

`& 0xff` 一刀切掉进位，回绕复刻完毕。不知情的游戏会故意用它循环访问零页表格——把回绕「修」成进位的模拟器，会让这些程序当场错乱。

## 三、间接：地址的地址

间接寻址（indirect addressing）——指令里给的不是数据的门牌，而是「存着门牌的格子」的门牌：先读指针格，拼出真地址，再去取数。多绕一层，换来的是运行时才能确定的地址——高级语言里数组、函数表、虚调用，落到 8 位机上全靠这一层。

`(零页),Y` 是最常用的间接形式：指针格存 16 位基址，加 Y 变址——C 语言的「指针 + 下标」在 6502 上的直接对应物。它也有一个页边界陷阱：指针格在 `$FF` 时，高字节从 `$00` 取，不是 `$100`。真机如此，因为零页寻址的地址加法器只有 8 位——上一节的回绕在这里又咬了一口：

```ts
// src/cpu/addressing.ts · indirectY
export function indirectY(cpu: CpuCore): number {
  const ptr = cpu.fetch()
  const base = word(cpu.bus.read(ptr), cpu.bus.read((ptr + 1) & 0xff)) // $FF+1 → $00
  return (base + cpu.y) & 0xffff
}
```

注意区分两段路：指针格内部的 `(ptr + 1) & 0xff` 回绕（零页纪律），与基址加 Y 的 `& 0xffff` 不回绕（16 位运算正常进位）。前者是硬件怪癖，后者是正常算术。

还有一个更著名的坑中之坑：`JMP (绝对)` 在指针为 `$xxFF` 时，低字节从 `$xxFF` 取、高字节却从该页第 0 格 `$xx00` 取——不是下一页。这是 6502 芯片的真实硬件 bug，当年被骗的软件不计其数，如今每一个模拟器都要忠实复刻它。我们的 `indirect` 里那行注释 `// $xxFF 的下一格是 $xx00` 就是它的实现——高字节地址 `(ptrLo + 1) & 0xff` 只在页内回绕。

## 四、相对：补码的返场

分支指令不存绝对门牌，只存一个单字节偏移：向前最多 127 格、向后最多 128 格。第 1 章的补码在这里返场——字节 `$FC` 按补码读是 -4，分支目标就是「越过偏移字节后的 PC」减 4。存偏移不存门牌的好处：整段代码搬家（重定位）后分支依然有效，因为「往前 4 格」不关心自己身在何处。

相对寻址也贡献了本章实现时最隐蔽的一个 bug。我最初写的是一行式：

```ts
// 用法示例：错误示范——差一拍
return (cpu.pc + toSigned(cpu.fetch())) & 0xffff
```

测试当场抓住：目标地址差了 1。原因是 JavaScript 的求值顺序——左边的 `cpu.pc` 先被读走（还没越过偏移字节），然后 `fetch()` 才推进 PC。正确写法必须先取偏移、后用 PC：

```ts
// src/cpu/addressing.ts · relative
export function relative(cpu: CpuCore): number {
  const offset = toSigned(cpu.fetch()) // 先取偏移（fetch 顺带把 PC 越过它）
  return (cpu.pc + offset) & 0xffff
}
```

「取操作数本身会推进 PC」这个动作副作用，从第 4 章 `fetch()` 一直潜伏到现在才真正咬人。这正是先写测试的回报：错误只存活了一轮。

## 五、接入指令表：动词 × 状语

寻址函数就位，指令表从 switch 长成了一张真正的表。LDA 的八个变体共用一个组装函数——动词相同、状语不同，正好用高阶函数表达：

```ts
// src/cpu/instructions.ts · OPCODES 表（本章形态，节选）
const ldaAt = (addr: (cpu: CPU) => number, cycles: number) => (cpu: CPU): number => {
  cpu.a = cpu.bus.read(addr(cpu))
  cpu.setZN(cpu.a)
  return cycles
}

export const OPCODES: Record<number, Inst> = {
  0xa9: { run: cpu => { cpu.a = cpu.fetch(); cpu.setZN(cpu.a); return 2 } }, // #imm
  0xa5: { run: ldaAt(zeroPage, 3) },
  0xb5: { run: ldaAt(zeroPageX, 4) },
  0xad: { run: ldaAt(absolute, 4) },
  0xbd: { run: ldaAt(absoluteX, 4) },
  0xb9: { run: ldaAt(absoluteY, 4) },
  0xa1: { run: ldaAt(indirectX, 6) },
  0xb1: { run: ldaAt(indirectY, 5) },
  0x8d: { /* STA abs，第 4 章旧识 */ },
  0xea: { run: () => 2 }, // NOP
}
```

`step()` 不再认识任何指令——它只取 opcode、查表、执行、返回周期数。这张表是第 6 章的主战场：五十六条指令进来，全部长成 `动词 × 状语` 的组合。

顺带一提周期数里的小心思：`(零页),Y` 是 5 拍，`(零页,X)` 反而要 6 拍——后者先算指针格再取指针，多一次内存读。周期数本课程只取基础值（跨页加拍的精细规则在附录提一句去向），主循环用它们估节拍已经够用。

## 小结

- 十三种寻址 = 「操作数在哪」的十三种约定；十种要算地址，三个特例不走地址函数。
- 零页是家门口 256 格：省一字节快一拍的优惠区，代价是 8 位回绕纪律（`& 0xff`）。
- 间接寻址是「地址的地址」，指针页边界回绕与 JMP 间接页 bug 都是真机行为，必须照抄。
- 相对寻址用单字节补码偏移，重定位免疫；实现时要先取偏移再用 PC。
- 指令表已经长成 `动词 × 状语` 的组合结构，等第 6 章批量入住。
