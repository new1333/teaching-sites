# 按时长定密度：视频宏观抽帧

店里那台监控录了 10 分钟的片子，你想让 AI 帮着看看有没有异常。最直接的做法：每秒截一张图，全部交给视觉大模型（看得见照片的那位远程助手，第 1 章的老朋友）。10 分钟 × 每秒 1 张 = 600 张图，一张不落全送出去。模型确实都看了，账单也当场爆炸——你只问了一句话，图片费按 600 张起算；监控每天录 8 小时，这个数还得乘 48。

你吸取教训，把密度拧到另一头：每 30 分钟才截 1 张。账单立刻安静了。然后有人来查事：进门前那 3 秒的推搡，到底谁先动的手？你翻遍抽出来的帧——整段片子只剩寥寥几张图，那 3 秒整个落在相邻两帧之间，没被抽到。抽过的帧里没有一张是它，模型再聪明也无米下锅：证据从源头上就不存在。

两次翻车，愁的是同一个旋钮的两端。视频对模型来说从来不是「一段会动的东西」，而是一叠图片——想让它看，先得抽帧。抽帧（frame extraction，把视频按固定间隔抽成一张张带时刻标签的图片）像把片子拍成连环画，每张标上是第几秒。抽多密，就是采样密度（sampling fps，每秒抽几帧）：像巡逻频率，每秒一趟看得清但太贵，半小时一趟省钱但漏事。PDF 主线在第 8 章收官，这一章起进入视频：先把「视频」翻译成「带时间标签的帧序列」，翻译本身零成本、纯本地，贵的那步留给成本漏斗按需再花。

## 模型看视频，看的是连环画

先把翻译的规则说透。视觉模型没有播放器：你不能把 mp4 扔给它，只能把一叠图片和问题一起发过去。所谓「让 AI 看视频」，实际发生的事是——先抽帧，再把抽出的帧当图片送出去。模型眼里的视频，就是这叠按时间排好队的连环画。

一句话的诚实边界必须先立住：**视觉模型没有耳朵**。对话声、脚步声、警报音——音频从头到尾不进这套管线，不是疏漏，是边界：往后视频侧的一切结论，只担保「画面上看得见的」。同理，两帧之间的流畅过渡也不存在，密度越疏，「翻页感」越重；快于采样密度的动作，抽出来的序列里根本没有中间过程。这些边界与本章的几处简化，统一收在附录差异清单。

帧序列一旦到手，PDF 主线的整套思路就能平移过来。帧是视频的「页」，时刻标签是视频的「页码」，第 3 章说过的那条纪律在这里原样成立：标签贴上去的那一刻，画面与时刻就绑在一起，模型引用时刻时是在照抄眼前的文本，不是在回忆。检索增强生成（先翻书、再照着答的开卷考试）搬进时间轴，靠的也是这叠带标签的帧。

## 密度是旋钮：帧数与漏检窗口

密度为什么必须是个旋钮？因为两个方向都有代价，而且都算得清。帧数 = 时长 × 每秒帧数，向上取整——采样时刻 k ÷ fps 只要小于时长就抽一张，k 从 0 数起；相邻两帧隔 1 ÷ fps 秒，这个间隔就是漏检窗口——比它短的事件，可能整个落在两帧之间。拿 600 秒的片子纸笔算一遍：

```text
纸笔演算：600 秒的片子，四档密度各是什么账

  1 fps    → 600 帧，帧间隔 1 秒   → 比 1 秒长的事件必被抽到
  0.5 fps  → 300 帧，帧间隔 2 秒   → 1~2 秒的事件开始有漏网可能
  0.25 fps → 150 帧，帧间隔 4 秒
  0.1 fps  →  60 帧，帧间隔 10 秒  → 3 秒的推搡可能整个落在两帧之间
```

乘积是整数时向上取整不显山露水（600 × 1 = 600）；乘积带小数才见分晓：61 秒 × 0.5 = 30.5，抽 31 张。

规律一句话：**事件比帧间隔长，必压得住采样时刻；比帧间隔短，就可能整个漏掉**。前半句是刻度的性质，不是运气——拿 3 秒的窗口 [31, 34) 在整秒刻度上画一遍：31、32、33 三个刻度全落进去。后半句取决于事件落在哪：同一个窗口放到 10 秒刻度上，夹在 30 和 40 之间，一个刻度都不沾。所以开头那两次翻车各据一端：600 帧是数量爆炸，3 秒推搡是间隔太宽。还有一层对照值得记住：第 3 章的 DPI 管的是单价（每张图多清楚），这里的 fps 管的是数量（抽多少张）——账单 = 单价 × 数量，成本漏斗的入口被这两个旋钮一起拴住。

数量旋钮不能让人手拍脑袋拧，实验场给它定了四档，按时长自动选：

```python
# src/vision_rag/video.py · auto_fps
def auto_fps(duration: float) -> float:
    """按时长选采样密度：≤60 秒 1fps；≤10 分钟 0.5；≤30 分钟 0.25；更长 0.1。

    越长的视频越经不起密采：600 秒 1fps 就是 600 帧、几百次模型调用。
    密度随时长降档，把宏观通读的帧数摁在分钟级素材一两百张、小时级几百张的量级——
    分界值是工程约定，不是物理定律。
    """
    if duration <= 0:
        raise ValueError(f"duration 必须为正数，收到 {duration}")
    for limit, fps in FPS_TIERS:
        if duration <= limit:
            return fps
    return FPS_LONG
```

分档的成因是帧数预算：宏观通读只要「大致知道每段在干什么」，够铺索引就行；瞬时细节不该在这个层面追——那是后面微观层次的工作。61 秒的素材刚过 60 秒线，归第二档：0.5fps、31 帧、t = 0, 2, 4 … 60。分界取 60 / 600 / 1800 秒，是工程约定而非物理定律，换一批素材完全可以重定——重要的是「按时长降档」这个形状。

## 实验场：一段合成出来的片子

老规矩，测试先行：tests/test_adaptive_sampling.py 的断言先写好、先跑出红，再让 video.py 长出来转绿。视频侧的第一块板是「视频本身」。本机没有 ffmpeg（开源的命令行视频处理工具：转格式、抽帧、切片都靠它），实验场也不依赖它——素材是合成帧源：一叠排好队的字符位图，每帧 40 × 12 格。两条声明的简化：真相帧每 0.5 秒一张（真实视频是每秒 24~30 张，降到 2 Hz 是为了让整叠帧数得清、画得出）；帧画面是字符网格而非 JPEG 字节（第 3 章已立过的口径）。

```python
# src/vision_rag/video.py · Frame 与 FrameSource
@dataclass
class Frame:
    """一帧画面加它的时刻标签：视频世界里的「页」。

    scene 与 motion 是素材自带的真相标注（真实视频只有像素，
    这两个字段得靠模型看图打标——下一章的事）。
    """

    t: float        # 时刻（秒）：这一帧在时间轴上的位置
    bitmap: Bitmap  # 画面本身：字符网格
    scene: str      # 场景名（真相标注）：画面发生在哪
    motion: str     # 运动强度（真相标注）：低 / 中 / 高


class FrameSource:
    """一段视频：总时长 + 全部真相帧（按 t 升序）。

    真实世界里它是 mp4 文件；实验场里它是一叠排好队的 Bitmap。
    抽帧只在这些真帧里挑选，不凭空造画面——这是「采样」二字的本义。
    """

    def __init__(self, duration: float, frames: list[Frame]):
        if duration <= 0:
            raise ValueError(f"duration 必须为正数，收到 {duration}")
        if not frames:
            raise ValueError("视频至少要有一帧")
        ts = [f.t for f in frames]
        if any(later <= earlier for earlier, later in pairwise(ts)):
            raise ValueError("真相帧必须按 t 升序排列，且时刻不重复")
        if ts[0] < 0 or ts[-1] >= duration:
            raise ValueError(
                f"帧时刻必须落在 [0, duration) 内：首帧 {ts[0]}，末帧 {ts[-1]}")
        self.duration = duration
        self.frames = list(frames)
```

```python
# src/vision_rag/video.py · make_clip
def make_clip() -> FrameSource:
    """课程自产示例视频：61 秒、三个场面、两次切换、一次 3 秒快速动作。

    事件窗口 (31, 34) 恰好躲开 0.1fps 的全部采样时刻（0/10/20/…秒），
    又必然含住 1fps 的三个整秒（31/32/33）——同一素材，密度定生死，
    漏检是每次重跑都复现的事实，不是随机抖动。
    """
    frames = []
    for i in range(int(CLIP_DURATION / CLIP_STEP)):
        t = i * CLIP_STEP
        motion = "高" if CLIP_EVENT[0] <= t < CLIP_EVENT[1] else "低"
        frames.append(Frame(t=t, bitmap=_draw_clip_frame(t),
                            scene=_clip_scene(t)[0], motion=motion))
    return FrameSource(duration=CLIP_DURATION, frames=frames)
```

事件的落点 (31, 34) 是特意挑的：在 10 秒刻度上它夹在 30 与 40 之间，一帧不沾；在整秒刻度上它含住 31、32、33 三个刻度。开头的两宗罪，就这样被固化进同一份素材。

## 抽帧：标签取最近真帧

采样本体只回答一个问题：理想时刻 k ÷ fps 落在哪，就贴哪张真帧。**采样不造画面**——抽出的每一帧都是素材里本来就有的一帧，标签抄那张真帧的 t，误差不超过半个真相帧间隔（本素材 ±0.25 秒）。

```python
# src/vision_rag/video.py · extract_frames
def extract_frames(source: FrameSource, fps: float) -> list[Frame]:
    """按密度采样：理想时刻 k/fps，取离它最近的真帧，标签即该帧的 t。

    采样不造画面——理想时刻落在两个真帧之间时，贴的是最近真帧的
    时刻，误差不超过半个真相帧间隔；同一张真帧不会被采两次；理想时刻
    与两张真帧等距时取先到的那张（时刻宁早不晚报）。
    """
    if fps <= 0:
        raise ValueError(f"fps 必须为正数，收到 {fps}")
    ts = [f.t for f in source.frames]
    step = 1.0 / fps
    picked: list[Frame] = []
    used: set[int] = set()
    k = 0
    while k * step < source.duration - 1e-9:
        ideal = k * step
        i = min(bisect_left(ts, ideal), len(ts) - 1)
        if i > 0 and ideal - ts[i - 1] <= ts[i] - ideal:
            i -= 1                            # 平手算前者：取先到的真帧
        if i not in used:
            used.add(i)
            picked.append(source.frames[i])
        k += 1
    return picked
```

三个细节各有其责。bisect_left（标准库二分查找，在升序的时刻表里定位理想时刻的插入点）再比远近：理想时刻 2 秒落在真帧 1.7 与 3.1 之间时，离谁近贴谁（这里贴 1.7）。等距平手取先到的那张：时刻宁早不晚报。used 集合挡重复：真帧比采样刻度稀时，两个刻度贴上同一张帧，只收一次。纸笔可验的小例子：真帧只有 0.2 / 1.7 / 3.1 秒三张、时长 4 秒，按 0.5fps 采样——理想刻度 0 与 2，贴回 [0.2, 1.7]。

「标签是估计」这件事要诚实到底：时刻标签来自采样，天生带着 ±半个真相帧间隔的误差（本素材 ±0.25 秒）。往后视频回答里的每个时间戳，精度都被这一步拴住——这个口径后面还会反复出现。真实世界里抽帧是现成工具的事：给 ffmpeg 的 fps 滤镜一个每秒帧数，它按密度吐出帧图序列，帧号换算成时刻。参数形态就这一档，具体行为以官方文档为准，本书不写死。

## 场景切换：免费的本地切分线

密度定完、帧抽出来，还有一件本地能做的好事：找场景切换（scene cut，画面内容明显突变的那一格——换镜头了，正好当切分线）。成因在于「突变」本身可以量化：把相邻两帧的画面对着数，变化的格点占全部格点的比例，就是突变分。同一个场面里主角挪 10 格，480 格里只有 10 格变，分约 0.02；场面一换，地面边框全换，分接近 1.0。两类之间隔着一条鸿沟，阈值取 0.3 轻松切开。

```python
# src/vision_rag/video.py · _change_score 与 detect_scene_cuts
def _change_score(a: Bitmap, b: Bitmap) -> float:
    """相邻两帧的画面突变分：变化的格点占全部格点的比例（0 到 1）。

    画布尺寸都变了就记满分 1.0——整个画面都换了。
    """
    if (a.width, a.height) != (b.width, b.height):
        return 1.0
    diff = sum(1 for ra, rb in zip(a.rows, b.rows)
               for ca, cb in zip(ra, rb) if ca != cb)
    return diff / (a.width * a.height)


def detect_scene_cuts(frames: list[Frame], threshold: float = 0.3) -> list[float]:
    """本地场景切换检测：只看画面，不读 scene 标签。

    相邻采样帧的画面突变分过线（≥ threshold）即判一次切换，切点时刻
    报「新场景的第一个采样帧」——精度受采样密度限制。真实工具同一
    思路：给相邻帧算一个画面变化分、过一个阈值（如 ffmpeg 的 scene
    分数配 select 过滤），阈值是旋钮不是圣旨。
    """
    if not 0 < threshold <= 1:
        raise ValueError(f"threshold 必须落在 (0, 1] 内，收到 {threshold}")
    cuts: list[float] = []
    for prev, cur in pairwise(frames):
        if _change_score(prev.bitmap, cur.bitmap) >= threshold:
            cuts.append(cur.t)
    return cuts
```

两个设计决定值得点破。其一，检测只看画面、不读 scene 标签——真实视频里根本没有标签可读，标签是素材给测试当裁判用的；测试里专门有一案：标签换了而画面没换，不报；标签没换而画面全变，照报。其二，**切点报的是新场景的第一个采样帧**，精度受采样密度拴住：0.5fps 下真相 25 秒的切换报 26.0（26 秒那帧才是新车间的第一张采样帧），1fps 下就精确报 25.0。真实工具同思路：给相邻帧算一个画面变化分、拿阈值筛。比如 ffmpeg 的 scene 分数配 select 过滤器，参数形态是 gt(scene, 某个数)——分数怎么算、默认值多少各家不同，本书只讲方向，不写死数值。

## 验证：跑什么，看到什么

本章里程碑全部钉在 tests/test_adaptive_sampling.py 里，12 个测试各验一事：

## 收线：本章落成的东西

开头两宗罪至此各有交代。600 帧的账单，病在密度没有随时长降档——auto_fps 的四档把宏观通读摁回预算内。3 秒推搡的漏检，病在间隔宽过事件——漏检窗口 1 ÷ fps 是纸笔可算的，密度选小了，遗漏就是可复现的事实。两者合成一条：密度是成本与遗漏之间的旋钮，分档是给旋钮定的刻度。

```text
  FrameSource      视频侧的固定素材：帧卡片、段聚合、问答、微观放大都在这段片子上排练
  auto_fps         密度档位表：宏观通读的帧数预算由它定
  extract_frames   一切帧序列的源头：索引批、代表帧、高密度重抽都按它的规矩出帧
  Frame.t          时刻标签：视频回答里的「页码」，误差不超过半个真相帧间隔
  detect_scene_cuts 本地切分线：免费、不联网，段边界与关键帧挑选的参考
```

离开前自查四问：

- 10 分钟的片子按 0.5fps 抽多少帧？帧间隔多少？1.5 秒的事件在这个密度下会不会漏？
- 为什么「事件比帧间隔长就必压得住采样时刻」？拿 [31, 34) 在整秒刻度上亲手画一遍。
- 抽出的帧标签为什么是「最近真帧」的时刻、而不是理想时刻？误差上界是多少？
- 场景检测为什么不读 scene 标签？0.5fps 下 25 秒的切换为什么报成 26.0？

答得上来，视频侧的第一块板就铺完了。帧还是散的——下一帧要做的事是把它们成批交给模型写成卡片、再归堆成段：帧卡片与段聚合是第 10 章，带时间戳的视频问答在第 11 章，可疑时刻拉近重看的微观放大在第 12 章。地图上的位置，到时各自展开。
