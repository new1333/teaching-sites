# 免费的第一道筛：中文 TF-IDF 粗筛

手册 96 页，读书卡也攒齐了。你问「预算表在哪一页」，第一版检索用最直觉的办法：看关键词在不在页面文本里，在的按出现次数排序。结果「审批」「预算」这类词，96 页里 74 页都有；排第一的永远是全文最长的那页——它把「审批」从头抄到尾。你要的预算表只在一页里安安静静出现了两次，排在三十名开外。排序全靠次数，长页赢，短页输，跟相关不相关没关系。

第二版你干脆放弃本地筛选：把候选页逐页发给视觉大模型问「这页跟问题有关吗」。96 页问下来，光「筛选」这一步就烧掉十几次调用、等了好几分钟——问题还没开始回答，钱先花掉了。而且这钱是每次提问都要重付一遍的：索引是固定资产，筛选却是流水开支。

两版错在同一处：把「筛」当成要么瞎筛、要么花钱筛。成本漏斗的第一层本来就是免费的——卡片在本地，文字层在本地，翻卡片不花一分钱。缺的只是一把能按相关度排页的尺。这一章就把这把尺造出来：分词、停用词、TF-IDF，三件事全是本地计算，毫秒级出结果。它是检索增强生成「先翻书」半边里，翻书翻得最快的那根手指。

## 中文没有空格，词从哪来

先解决一个英文检索不存在的问题。英文写 "budget table"，空格天然把句子切成了两段；中文写「预算表」，三个字连成一串，中间什么都没有。而检索的最小单位是词：问题里的词要跟页面里的词对上，才谈得上计数和排序。所以第一步是分词——把连成一串的中文切成可检索的小块，本课程切成相邻两字一组。

为什么是两字、不是逐字或词典？逐字太碎：「预」「算」单字到处都是，一页正文里「的」能出现几十次，字粒度上什么都指认不了。词典分词最准，但要引入词典和算法，实验场不背这个依赖。二字滑窗是中间的糙办法：中文的双字词占比极高（预算、审批、保养、退货），两字一组能兜住大多数实义词；兜不住的，下一节告诉你为什么也无妨。

```text
「年度预算表」的二字滑窗：相邻两字一组，逐位右滑

  年 度 预 算 表
  [年度]
    [度预]        ← 跨词边的碎片：不是任何真词
      [预算]
        [算表]
  切出 = {年度, 度预, 预算, 算表}
```

跟着切一遍：「每90日更换滤芯」切出 {90, 日更, 更换, 换滤, 滤芯}——90 是数字整段成词；「日更」是跨过数字边界的碎片。碎片有害吗？害处被对称性抵消了：问题用滑窗切，页面同样用滑窗的世界里数子串出现次数，「日更」这种组合在正经文本里几乎不出现，双方都切不中对方。锚点收一句：中文是一整串，先切成两字一小块的碎片，才好对暗号——碎片切歪了不怕，两边切得一样歪。

## 停用词：先把空气扔出去

切出来的词不都值得留。「怎么」「什么」「哪里」是问法，不是线索——问「预算表在什么地方」，你要找的是预算表，不是找「什么」。这类词叫停用词——到处都有、不携带任何检索信息的词，检索前先扔掉。锚点：它们像空气，哪儿都在，指认不了任何人。

不扔会怎样？算一笔就知道。假如一个词在全部 n 页里都出现，它的身价是 log(1 + n/n) = log 2 ≈ 0.693——跟总页数无关，永远贱到底。也就是说，页页都有的词，打分公式自己就会把它压到地板上；停用词表是在公式之外提前扔一次，省的计算是小事，关键在问题侧：问法词若留着，滑窗还会顺着它切出「在什」「么地」这类碎片，去 96 页里乱撞，偶尔就撞出一页冤枉的命中。实验场的停用词表是一张手工小清单，29 个词，正文引用时你看得到全貌——真实系统的停用词表动辄数百词，这是本课程登记在案的简化。

## TF-IDF：这页越多、全书越少，越值钱

现在造尺的主体。TF-IDF（term frequency–inverse document frequency，词频-逆文档频率）回答一个问题：某个词对某一页的「指认力」有多强。它由两个直觉相乘。直觉一：问题里的词在这页出现得越多，这页越可能正经在谈这件事——这是 TF，词频。直觉二：一个词全书页页都有，它出现一万次也区分不了任何页；只在个别页出现，它一露面指向性就极强——这是 IDF，逆文档频率，「逆」就是反着比，含它的页越少越值钱。锚点：评线索的规矩——这页出现得越多、全书出现得越少的词，越值钱。

写成公式只有两行：词的身价 idf = log(1 + n/df)，其中 n 是总页数，df 是含这个词的页数；页面得分 = 每个问题词的 idf × min(该词在这页的次数, 8)，逐词加总。log 是为了让稀有程度按倍数计价——df 从 2 降到 1，跟从 50 降到 25，身价涨幅同级，不会因为语料一大数字就爆炸；加 1 是缓冲垫，页页都有的词身价压在 log 2 附近，不归零也不抬头。

拿 3 页小语料（语料＝全部页面文本的总和）徒手算一遍——这一节卡片留空、按纯文字层计次，卡片的 ×3 加权两节之后再叠加。问「预算表报销」：

```text
纸笔演算：3 页小语料，问「预算表报销」
  第 1 页  报销制度：差旅报销需部门审批，报销单据留存两年。   报销 ×3
  第 2 页  报销制度：餐费报销需两级审批，审批记录归档。       报销 ×2
  第 3 页  预算表：年度预算表附项目明细。                    预算 ×2、算表 ×2
  问题切词 {预算, 算表, 表报, 报销}（表报是跨词边碎片，三页都无命中）
  n = 3，df(报销) = 2，df(预算) = df(算表) = 1
  idf(报销) = log(1 + 3/2) = log 2.5 ≈ 0.916
  idf(预算) = log(1 + 3/1) = log 4   ≈ 1.386
  第 1 页 = 0.916 × min(3, 8)     ≈ 2.75
  第 2 页 = 0.916 × min(2, 8)     ≈ 1.83
  第 3 页 = 1.386 × 2 + 1.386 × 2 ≈ 5.54   ← 词频最低，得分最高
  排序 [3, 1, 2]：稀有词压倒高频词
```

每个数都能纸笔复算（对数拿计算器或 `math.log` 核）。第 3 页每个词只出现两次，得分却是第 1 页的两倍——因为「预算」「算表」全书只它家有。这正是开章那个 96 页困局的解法：「审批」74 页都有，df 高达 74，idf 被压到 log 2 附近；「预算表」只 1 页有，idf 是 log 97。稀有词一出场就把高频词踩下去了。

## 词频为什么要封顶

公式里那个 min(tf, 8) 不是装饰，防的是开章第一版的病：按次数排序，长页霸榜。反例可以复算：

```text
反例演算：不封顶会发生什么

  第 1 页  正文谈保养，「保养」出现 8 次
  第 2 页  附录整页罗列关键词，「保养」抄了 100 次
  两页其余内容相同 → 两页的每个问题词 idf 相同

  不封顶：得分比 = 100 : 8 = 12.5 倍 → 第 2 页霸榜
  封顶后：min(100, 8) = min(8, 8) = 8 → 并列，按页序稳定输出 [1, 2]
  封顶线以下照常分高下：7 次 < 9 次 → min 后 7 < 8 → 9 次的页在前
```

成因说穿了是：词频与相关度不是直线。一个词第 1 次出现是强信号——这页在谈它；第 9 次相对第 8 次，几乎不再提供新信息。可页的长度是线性的：附录、抄录、关键词罗列页会把词频无限堆高。不封顶，排序就从「选最相关的页」退化成「选最长的页」。真实检索引擎为此设计了平滑递减的饱和函数（词频收益越往后越薄），方向一致；实验场用最粗的一刀切——超过 8 次按 8 次算，这也是登记在案的简化。

## 实验场：scoring.py

三个函数落地上面全部原理。先是两张清单和两个旋钮：

```python
# src/vision_rag/scoring.py · 常量
STOP_TERMS = frozenset({
    "什么", "怎么", "哪些", "如何", "为什么", "这个", "那个", "请问", "告诉",
    "一下", "资料", "文档", "书里", "书中", "里面", "文中", "介绍", "描述",
    "the", "a", "an", "of", "in", "is", "what", "how", "which", "and", "to",
})
TF_CAP = 8         # 词频封顶：超过 8 次按 8 次计
FIELD_WEIGHT = 3   # 卡片字段权重：标题/摘要/关键词各重复 3 次
```

切词的是一个函数，中文滑窗、英文数字整段、去停用词三步走完：

```python
# src/vision_rag/scoring.py · tokenize
def tokenize(text: str) -> set[str]:
    """把一段文本切成检索词：英文数字整段成词、中文相邻二字滑窗、去停用词。

    中文没有空格，「保养周期」四个字连成一串，没法直接跟问题对暗号——
    相邻两字一组滑过去（保养、养周、周期）。问题与页面不用对齐分词
    结果：词只是子串，页里数出现次数就行。滑窗会切出跨词边的碎片
    （养周），但问题与语料两边噪音对称，通常谁也匹配不到谁。
    英文与数字整段成词并统一小写：GLM-4.5v 切成 glm 与 4.5v。
    """
    terms: set[str] = set()
    lowered = (text or "").lower()
    terms.update(_LATIN_RE.findall(lowered))
    for run in _HAN_RE.findall(lowered):
        terms.update(run[i:i + 2] for i in range(len(run) - 1))
    return terms - STOP_TERMS
```

页面的「可检索形态」由 page_document 摊开。这里藏着第 4 章那摞卡的回报：标题、摘要、关键词是模型浅阅读挑出来的干货，各重复 3 次——同一句话，写在摘要里值 3 分，埋在正文里值 1 分。文字层全文垫底 1 次，卡片没写到的字眼还有一次被数到的机会。扫描页文字层是空的，它在粗筛里的全部存在感都来自卡片——第 3 章埋的伏笔在这里兑现：

```python
# src/vision_rag/scoring.py · page_document
def page_document(card: PageCard, page_text: str) -> str:
    """把一张读书卡摊成一篇可检索的文档：卡片字段重复 3 次＋文字层 1 次。

    卡片是模型浅阅读的浓缩，比原文干净：标题、摘要、关键词各重复
    3 次——模型认为要紧的字眼，检索时按 3 倍计。文字层全文垫底 1 次：
    卡片没写到的字眼，原文还有一次被数到的机会。扫描页文字层为空，
    它在粗筛里的全部存在感都来自卡片。
    """
    parts: list[str] = []
    for h in card.headings:
        parts.extend([h["text"]] * FIELD_WEIGHT)
    parts.extend([card.summary] * FIELD_WEIGHT)
    parts.extend([str(k) for k in card.keywords] * FIELD_WEIGHT)
    parts.append(page_text or "")
    return "\n".join(parts)
```

主函数 score_pages 把公式原样译成代码，一分不差：

```python
# src/vision_rag/scoring.py · score_pages
def score_pages(cards: dict[int, PageCard], texts: list[str],
                question: str) -> list[int]:
    """本地粗筛：问题词 × 页面文档的 TF-IDF 打分，按总分降序返回页码。

    词的身价是 idf = log(1 + 页数 ÷ 含该词的页数)——只在 1 页出现的词
    身价最高，页页都有的词身价趋近 log 2。页面总分 = Σ idf × min(词频,
    8)：词频封顶防「最长的那页」霸榜。一个词都没命中的页不进榜；
    整个问题一个词都命中不了（或全是停用词）时，回退全部页序——
    粗筛交不出判断，就把判断原样交给下一层漏斗。
    """
    pages = sorted(cards)
    if not pages:
        return []
    if pages[-1] > len(texts):
        raise ValueError(f"texts 必须覆盖所有页：最大页码 {pages[-1]}，"
                         f"texts 只有 {len(texts)} 条")
    terms = tokenize(question)
    docs = {p: page_document(cards[p], texts[p - 1]) for p in pages}
    if not terms:
        return pages                                  # 问题全是停用词：回退页序
    n = len(pages)
    df = {t: sum(1 for d in docs.values() if t in d) for t in terms}
    scored = []
    for p in pages:
        doc = docs[p]
        s = 0.0
        for t in terms:
            tf = doc.count(t)
            if tf:
                idf = math.log(1 + n / df[t])         # 稀有 = 贵，常见 = 贱
                s += idf * min(tf, TF_CAP)            # 词频封顶：8 次封神
        scored.append((p, s))
    scored.sort(key=lambda ps: -ps[1])                # 稳定排序：同分按页序
    return [p for p, s in scored if s > 0] or pages   # 全不沾：回退页序
```

两个设计判断值得停一下。其一，回退语义：整个问题一个词都命中不了时，返回全部页序而不是空列表。粗筛的失败模式是「没主意」，不是「崩溃」——没主意就把判断原样交给下一层，列表清空才是把活干死。其二，同分按页序：稳定排序让并列的页保持页码顺序，输出可复现——同样的输入永远得到同样的榜单，这盒尺子才算可靠。 还有一类页这把尺天生量不着：空白页上没有任何词，粗筛永远给不出判断——无字页的把关，留给第 6 章的精排。

## 验证：跑什么，看到什么

本章里程碑全部写成测试，钉在 tests/test_local_tfidf.py 里，四组断言各验一事：

- **稀有词压倒高频词**——74 页满篇「审批」（词频 15，早超封顶）、只有第 75 页有「预算表」的语料上，问「预算表审批」，第一名恰是第 75 页，75 页全部进榜；
- **词频封顶**——第 1 页写 8 次、第 2 页抄 100 次，并列第一按页序输出；7 次对 9 次仍分高下，证明封顶线画在 8；
- **加权字段生效**——同一个词，躺在摘要里（×3）的页压过只在正文出现 1 次的页；手册第 5 页扫描件文字层为空，问「保修范围」它仍排第一，命中全来自卡片；
- **无词命中回退**——问题词全不沾语料、或问题全是停用词，都回退全部页序。

## 收线：从「在不在」到「值不值」

回头看三版检索。第一版问「关键词在不在、出现几次」——长页霸榜。第二版干脆全交模型——十几次调用，钱受不了。这一版用 TF-IDF 问「这个词对这页的指认力值多少」：分词解决中文没法对词、停用词解决问法词乱撞、idf 解决高频词不值钱、词频封顶解决长页霸榜。四个零件各管一个病，合起来就是漏斗第一层那道免费的闸。

```text
本章落成的东西，后面谁在用

  tokenize          切词入口：问题与文档共用一把刀，第 11 章视频段粗筛复用
  page_document     卡片摊成可检索文档：字段 ×3 的加权在此生效
  score_pages       漏斗第一层：毫秒级圈候选页，产出交给精排
  词频封顶纪律      「按相关度排，不按长度排」的保证
  回退语义          粗筛没主意时交回全部页序，不空转
```

这把尺也有言明的盲区：它只认字面。问「退货政策」，写「售后与退换」的那页一个词都对不上——词面匹配的天生短板。补这个盲区要靠看得见版面与语义的第二层漏斗，那是下一章的事。再往大里说一句：真实世界这一层更常用向量检索——把每页的语义压成一串数字坐标、按远近找相似——本课程的词面打分是它的极简替身，胜在零依赖、每一步都算得清。
