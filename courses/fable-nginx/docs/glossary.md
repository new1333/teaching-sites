# 术语表

全书术语的一句话大白话定义；每条在正文首次出现时另有当场解释。

| 术语 | 英文 | 一句话大白话定义 |
|---|---|---|
| Web 服务器 | web server | 接收 HTTP 请求、返回 HTTP 响应的常驻程序；你打开的每个网页背后都有一个它在应答。 |
| 套接字 | socket | 操作系统给「一条网络对话」发的门牌号，程序通过它收发字节。 |
| 监听 | listen | 在一个端口上守着等人来连——像总机守着电话线。 |
| 接受连接 | accept | 把等在门口的连接接进来，拿到一个可以开始说话的套接字。 |
| 端口 | port | 同一台机器上的分机号，Web 服务常驻 80/443 这类号码。 |
| HTTP 报文 | HTTP message | HTTP 说的话，纯文本：一行请求行（要什么）、若干行头部（备注）、一个空行、可选正文。 |
| 请求行 | request line | 报文第一行：方法 + 路径 + 版本，如 GET /index.html HTTP/1.1。 |
| 状态码 | status code | 响应第一行里的三位数结果代号：200 成功、404 没找到、500 服务器自己出错了。 |
| Content-Length | Content-Length | 头部里标明正文有几个字节的字段，收发双方靠它知道这条消息何时算完。 |
| 进程 | process | 操作系统里一个独立运行的程序实例，有自己的内存空间。 |
| 线程 | thread | 进程里干活的执行工人，同进程的线程共享内存，每个线程还自带一块栈。 |
| 栈内存 | thread stack | 每个线程预留的工作台内存（可按 MB 计），线程闲着也占。 |
| 上下文切换 | context switch | CPU 从一个线程换到另一个线程要做的存档/读档动作，纯开销不产出。 |
| C10K 问题 | C10K problem | 1999 年提出的难题：一台服务器如何同时伺候一万个并发连接——「一连接一线程」的朴素模型在这里倒下。 |
| 非阻塞 IO | non-blocking IO | 读不到数据就立即返回「暂时没有」，而不是卡住干等。 |
| 文件描述符 | file descriptor (fd) | 内核给每个打开的东西（socket、文件）发的整数编号牌。 |
| IO 多路复用 | IO multiplexing | 一个线程同时盯一堆描述符、谁就绪了只报告谁——select 和 epoll 是它的两代实现。 |
| select | select | 老一代多路复用：每次调用都要把全部描述符重新报给内核，数量还有硬上限（Windows 上 512 个）。 |
| epoll | epoll | Linux 的多路复用：描述符常驻内核登记表，就绪了内核记名单，调用只取名单——万级连接的底座。 |
| 事件循环 | event loop | 一个 while 循环：问多路复用「谁就绪了」，逐个处理，再问——单线程扛大量连接的骨架。 |
| Reactor 模式 | Reactor pattern | 「事件循环 + 就绪分发」这套结构的学名：事件来了交给对应的处理逻辑。 |
| 状态机 | state machine | 把「进行到哪一步了」写成显式状态（读到请求行/头部/完成），每来一段数据推进一步。 |
| 缓冲区 | buffer | 一段攒字节的内存：接收缓冲区攒没到齐的请求，发送缓冲区攒没发完的响应。 |
| 部分读 | partial read | 一次 read 只读到半条消息——字节流没有消息边界，这是常态不是异常。 |
| 部分写 | partial write | 一次 write 只写出去一半，返回值告诉你实发字节数，剩下的要自己记账。 |
| 水平触发 | level-triggered (LT) | 「还有数据没处理完就每次都提醒」的通知方式，select/epoll 的默认行为。 |
| 边缘触发 | edge-triggered (ET) | 「状态变化那一瞬间提醒一次」的通知方式，nginx 的选择，配合非阻塞必须读到空为止。 |
| accept 惊群 | thundering herd | 多个进程同时等同一个监听套接字，一个连接到来全员被惊醒抢一个活的现象。 |
| master-worker 架构 | master-worker | nginx 的骨架：一个 master 管大局（配置、派工人），N 个 worker 各带一条事件循环干连接的活。 |
| 优雅重载 | graceful reload | 换配置不断服务：master 拉新 worker 接新连接，老 worker 把手头连接伺候完再退场。 |
| 正向代理 | forward proxy | 替客户端出头的中间人——服务器看不到真正的客户端是谁。 |
| 反向代理 | reverse proxy | 替服务器出头的「总机」——对外一个门面，对内把请求转给真实应用、响应再转回来，客户端看不到真服务器。 |
| 上游 | upstream | 反向代理眼里的真实干活者——请求最终要去的那台服务器。 |
| 负载均衡 | load balancing | 把请求分摊到多台上游的策略，分摊的是请求数不是流量字节数。 |
| 轮询 | round-robin | 按固定顺序一圈圈发牌：第 1 个请求给 A，第 2 个给 B，第 3 个又回到 A。 |
| sendfile | sendfile | 让内核直接把文件送进网卡、不经用户程序搬字节的系统调用——静态文件加速的核心。 |
| 零拷贝 | zero-copy | 消灭「内核与用户程序之间重复搬运字节」的技术统称，sendfile 是代表。 |
| 内存池 | memory pool | 整块领、统一还的内存管理方式：按请求批量分配、结束一次归还，少跑成千上万次系统级内存调用。 |
