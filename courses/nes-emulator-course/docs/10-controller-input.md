# 手柄:一次移一位的串行输入

按 Start 开始游戏——画面毫无反应。你把按键状态直接塞进一个字节,游戏一读就拿到了,这有什么难的?打日志发现游戏在读 $4016,而且一口气读了八次;你的「按键字节」让它每次都读到同一个值,于是菜单以每秒六十帧的速度疯狂自翻,或者干脆纹丝不动。更诡异的是有的游戏能玩、有的不能——区别在于它们读手柄的姿势。

病根:手柄在硬件上不是「一个字节」,是一根数据线加一个移位寄存器。CPU 每次读只能拿到一位,八次读完一组;读的时机、strobe 的时序,每个细节都是协议的一部分。这一章把这个协议原样实现——它只有五十行,却决定了「按 Start 有没有反应」。

## 协议:strobe、快照、八次读

真机的读取流程分三步:

1. **写 $4016 置 strobe(写 1)**:手柄把当前八个键的状态锁存进内部的 8 位移位寄存器——「拍照」。高电平期间照片持续刷新。
2. **写 $4016 复位 strobe(写 0)**:照片定格,移位指针回到第一位。
3. **连读 $4016 八次**:每次读返回一位,顺序固定——A、B、Select、Start、上、下、左、右。第九次开始,硬件恒返回 1(不是 0)。

实验场的实现就是一个忠实于这三步的小类:

```ts
// src/controller.ts · Pad
setStrobe(on: boolean): void {
  this.strobe = on
  // 高电平期间寄存器持续重载;落到低电平时定格的就是「此刻」的按键状态
  this.snapshot = this.state
  if (on) this.index = 0
}

read(): number {
  if (this.strobe) return this.state & 1 // 高电平期间读:恒为 A 键(不消耗位序)
  if (this.index >= 8) return 1 // 移空后硬件恒返回 1
  return (this.snapshot >> this.index++) & 1
}
```

三个容易做错的语义都藏在这十几行里。其一,strobe 高电平期间读,返回的是 A 键的**实时**状态,且不消耗移位指针——有些游戏故意保持 strobe 高来轮询 A 键。其二,读满八位后返回 1:游戏常连读两次取「两次一致才认」的防抖逻辑,返回 0 会把「没按」误判成有第九个键。其三,读取中途重新 strobe,位序从头开始——快门重开,之前读到一半的作废。

$4017 是第二手柄的端口,读法相同;但 strobe 只由写 $4016 控制,两个手柄同时「拍照」。

为什么1983 年的硬件要设计成「一次一位」?算一笔连线账就知道:手柄插座只有五根有效引脚,其中数据线只有一根。八个按键若并行传输要八根数据线,还要对付插座触点氧化、线缆弯折的老化问题;串行方案只用一根线,代价是 CPU 侧多花十几条指令。当年 CPU 时间便宜、连线昂贵,这笔账天经地义——四十年后你在这门课里复刻它,顺便理解了老硬件一个贯穿性的设计哲学:**寄存器位宽永远比内存便宜,时序永远可以拿指令去换**。

游戏软件也在这套协议上长出了惯用法。经典的开局是「连读两轮、逐位与运算」:两次读取不一致的位视为抖动丢弃。这套防抖依赖「读满后返回 1」的硬件行为做终止条件,也依赖两次 strobe 之间按键快照的独立性——模拟器少实现任何一个细节,防抖逻辑都会把真实按键当成抖动吞掉,表现又是「按了没反应」。硬件语义、软件惯用法、故障现象,三层之间的因果链在这一根数据线上体现得淋漓尽致。

## 接线:总线的 ioRead/ioWrite 缝隙

第 6 章的总线给手柄留了两个委托缝隙,现在接上:

```ts
// tests/controller-input.test.ts · makeMachine(节选)
bus.ioRead = (a) => (a === 0x4016 || a === 0x4017 ? controller.cpuRead(a) : 0)
bus.ioWrite = (a, v) => controller.cpuWrite(a, v)
```

一行注入,总线其余部分零改动——第 6 章「总线从第一天就是插板子的形状」这句话在此兑现。`$4016` 的读值只看 D0,高 7 位是 open bus,简化为 0;上一章的整机 Nes 会把这两个委托默认接好,`Nes.setButton()` 就是按键事件的入口。

## 验证

`tests/controller-input.test.ts` 六个用例:按下 A 与 Start 后八次读出 `10010000` 的位序列;读取中途重新 strobe,位序重置(Up 回到第 5 位);读满 8 位后恒返回 1;strobe 高电平期间读恒为 A 键实时值、落沿定格;第二手柄走 $4017 且与一手柄互不串扰;连续写多次 1 再落沿,仍得到完整一轮。位序列的断言直接按硬件顺序表 `['A','B','Select','Start','Up','Down','Left','Right']` 对照,不靠魔法数字。累计 97 个用例全绿。

## 小结

手柄教会的是一条更广的原理:**老硬件的外设几乎都是「串行协议 + 专用时序」,不是内存里的一个变量**。读写端口、边沿、位序,缺一样,程序层面的表现就是「按键失灵」这类无法从代码报错里看出来的故障。至此整机只差最后一步:把真卡带插上总线,让 .nes 文件里的一切真正跑起来。
