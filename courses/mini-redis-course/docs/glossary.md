# 术语表

全书术语的一句话大白话（按首现章的大致顺序编排见正文，此处按登记序）。后续遇到拿不准的词，回这页翻。

| 术语 | 英文 | 一句话定义 |
| --- | --- | --- |
| 键值存储 | Key-Value Store | 只会两件事的数据库：按一个键存一个值、按键取回——像一个大号 JS 对象，但活在另一个进程里。 |
| 缓存 | Cache | 把慢的地方取来的数据在快的地方暂存一份，下次直接拿快的——用空间换时间。 |
| 旁路缓存模式 | Cache-Aside | 最常用的缓存姿势：读先查缓存、没有再查库回填；写先写库再删缓存。缓存站在数据库旁边，不在中间。 |
| 内存数据库 | In-Memory Database | 数据平时全部放在内存里的数据库——快是快，断电就忘，所以要配持久化。 |
| 数据结构服务器 | Data Structure Server | Redis 的自我定位：不只是存字符串，还提供列表、哈希、集合、有序集合这些结构级操作，让计算靠近数据。 |
| RESP 协议 | REdis Serialization Protocol | Redis 客户端与服务端之间的对讲机话术：每条消息先标类型（+ $ : - *），再标长度，最后是内容，行尾统一 \r\n。 |
| 字节流 | Byte Stream | TCP 送货的方式：一串连续字节，没有消息边界——切成几段、几段合送都不保证，收货方要自己认边界。 |
| 半包与粘包 | partial / coalesced packets | 字节流的常态：一条消息分两次到达（半包），或几条挤在一次到达（粘包）——不是 bug，是本性。 |
| 阻塞 IO | Blocking IO | 线程走到 read 门口没数据就原地睡着——等一个人，误所有人。 |
| IO 多路复用 | IO Multiplexing | 让一个线程同时盯着许多连接的技术：谁有数据到达内核就报告谁（select/poll/epoll 都是它的实现），而不是一个连接一个线程干等。 |
| 事件循环 | Event Loop | 一个永动的调度循环：有事件（连接到达、数据可读）就处理，没事件就歇——单线程也能同时服务上千连接的底层机制。 |
| 事件驱动 | Event-Driven | 程序不主动等事情，而是注册『这事发生时叫我』的回调，控制权交还给循环。 |
| 管道 | Pipelining | 客户端一口气发多条命令、一次收回全部应答——省掉每条命令一个网络往返，RESP 的解析模型天然支持。 |
| 哈希函数 | Hash Function | 把任意键算成一个数组下标的函数——同一个键永远算出同一个下标。 |
| 哈希冲突 | Hash Collision | 两个不同的键被算到同一个桶——用桶里挂链表解决（链地址法）。 |
| 链地址法 | Separate Chaining | 解冲突的主流做法：每个桶住一条链，落到同桶的键在链上排队——查桶 O(1)，再沿链比对。 |
| 负载因子 | Load Factor | 已存键数 ÷ 桶数组长度——这个比值越大链越长，查得越慢，所以要盯着它扩容。 |
| 渐进式 rehash | Incremental Rehash | 扩容时新旧两张表同时在场，每次操作顺带搬一个桶——把一次长阻塞摊薄成无数次微秒动作。 |
| 跳表 | Skip List | 多层索引的有序链表：底层站站慢车，上层跳站快车——查找/插入 O(logN)，范围查询天然顺手。 |
| 有序集合 | Sorted Set / ZSET | 成员各带一个分数、永远按分数排好队的集合——排行榜的标准答案。 |
| 对象编码 | Encoding | Redis 的同一类数据（type）底下按大小换不同物理结构（encoding）：小用紧凑省内存，大换高效保性能。 |
| 过期字典 | Expires Dict | 另一张表：键 → 到期时间戳。键本身不知道自己会过期，到期与否查这本登记簿。 |
| 惰性删除 | Lazy Expiration | 过期键在被访问那一刻才检查、才删——不花后台 CPU，代价是没人碰的过期键一直占内存。 |
| 定期删除 | Periodic Expiration | 每隔一小段时间随机抽一批带 TTL 的键，过期的删掉，过期比例高就再抽一轮——惰性删除的补刀。 |
| 内存淘汰 | Eviction | 内存（本课简化为键数上限）满了之后主动腾地方的策略——与『过期』不同：过期删的是到期键，淘汰牺牲的是还活着的键。 |
| 近似 LRU | Approximated LRU | 不维护全局精确链表，而是随机抽 5 个键、踢掉其中最久未用的——牺牲一点准确换回性能。 |
| AOF | Append Only File | 追加式日志文件：每条写命令执行完就追加一笔，重启时从头重放恢复数据。 |
| AOF 重写 | AOF Rewrite | 按当前内存现状生成一份等价的最小命令集换掉臃肿日志——100 次 SET 同一个键只留最后一条。 |
| 刷盘策略 | fsync policy | 日志什么时候真正写到磁盘：always 最稳最慢、everysec 每秒一次折中、no 交给操作系统最快最险。 |
| RDB 快照 | RDB Snapshot | 某一瞬间全库的二进制照片——恢复比 AOF 重放快，但两次快照之间的写入会丢。 |
| 写时复制 | Copy-On-Write | fork 出的子进程先与父进程共享内存页，谁先改哪页才复制哪页——快照期间主进程照常写入的秘密。 |
| fork | fork | 操作系统复制出一个几乎一样的子进程的调用——页表先共享、各改各的（配合写时复制）。 |
| 主从复制 | Replication | 从库先要一份全量数据（RDB 传输），之后主库把每条写命令流水线同步过去——数据搬家+读扩容。 |
| 哨兵 | Sentinel | 几个旁观的看门进程：盯主库心跳，多数派认定它挂了就自动把某个从库提成新主——自动故障转移。 |
| 哈希槽 | Hash Slot | 集群把键空间切成 16384 个固定槽，每台节点负责一段——扩容只需搬槽，不用全量重哈希。 |
| 缓存雪崩 | Cache Stampede | 缓存同一时刻大面积失效/清空，请求全部砸向数据库——冷启动重启、批量同刻过期都会触发。 |
| 简单串与批量串 | simple string / bulk string | RESP 的两种字符串：一行到底不能含换行的短回话（+），和带长度前缀、想装什么装什么的（$）。 |
| 多层索引 | multi-level index | 跳表的上层抽稀链：每升一层约四分之一的节点留下，查找从顶层往下蹭——链表上做出二分的味道。 |
| 随机层数 | random level | 新节点抛硬币决定自己盖几层：每层 1/4 概率晋升、封顶 32——用概率平均换掉全局再平衡。 |
| 抽样 | sampling | 不看清全貌、随机抽一小把来做决定——定期删除抽键、近似 LRU 抽候选，都是拿一点准确换大量时间。 |
| LRU 与 LFU | Least Recently / Frequently Used | 两种「热」的定义：新近用过的算热（LRU），用得勤的算热（LFU）——报表扫描洗得动前者，洗不动后者。 |
| idle 时钟 | idle clock | 每个键记一笔最近被使用的时间戳——谁最久没人碰，谁就是近似 LRU 眼里最该走的。 |
| 写后日志 | Write-After Log | 先执行命令、成功后才记账的日志——与数据库先记账再执行的 WAL 相反，好处是账上不会有被拒的坏账。 |
| 重放 | Replay | 恢复的手段：新进程把日志里的命令从头到尾再执行一遍——重启后的「记忆」其实是重演。 |
| 快照一致性 | snapshot consistency | 快照拍到的是某一瞬间完整一致的状态，而不是写入中途的半张脸——fork+COW 让「那一瞬」被冻结。 |
| 页表 | page table | 操作系统给每个进程记的账：虚拟地址哪一页对应物理内存哪一页——fork 复制的是这本账，不是内存本身。 |
| 全量同步 | full sync | 主从复制的第一次：主库把当时的全部数据（RDB）发给从库——之后的增量才是日常。 |
| 增量复制 | Partial Resynchronization | 断线重连后只补发缺失的那段命令流——靠主库留着的复制积压缓冲圈住最近的写。 |
| 故障转移 | failover | 主库挂了自动把某个从库提成新主、大家改认新主人——哨兵存在的主要理由。 |
| RDB | Redis Database file | Redis 全量快照的代称与文件格式——拍某一瞬全库的照片，恢复比 AOF 重放快。 |
