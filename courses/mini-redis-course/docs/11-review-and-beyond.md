# 终章对账：你写了一个迷你 Redis

第 1 章的开头，如果有人问你「Redis 为什么快」，你多半只答得上一句：「因为数据在内存」。现在把同样的问题再问一遍——你的答案已经不是一个短语，而是四段拆得开、讲得动的账：快从哪来、内存怎么管、数据怎么不丢、一台挂了怎么办。四问对账，就是终章的全部内容。这一章不添新零件，做三件事：把十章收拢成一张全景，把这门课开篇立下的那句大问话正式收口，最后盘点你手里有什么、缺什么、往哪走。

## 前情回顾：十章路，一条主线

用六句话把来路重走一遍：

- 第 1 章立标尺：内存一次访问 ~100ns、机械盘寻道一次 ~10ms，隔着五个数量级。缓存因此是刚需，旁路缓存模式的写路径还藏着一扇关不上的脏数据窗口；
- 第 2、3 章让你听懂它说话、再让一个线程照看一千个连接：RESP 协议加带缓冲的解码器（TCP 是字节流，半包与粘包是常态），事件循环免「等 IO」之阻塞；
- 第 4、5 章给键安家：手写哈希表、扩容不停机（渐进式 rehash），排行榜插得快取得快（跳表）；
- 第 6、7 章管内存：寿命到了就删（惰性加定期），内存满了就淘汰（近似 LRU）；
- 第 8、9 章管断电：每条写命令记账（AOF），某一瞬全库拍照（RDB 快照）——重启不再两袖清风，缓存雪崩少了一个最典型的引信；
- 第 10 章把镜头拉远：一台不够，复制、哨兵、集群，mini 止步于单机。

一条主线贯穿十章：Redis 这个住在内存里的键值存储兼数据结构服务器，速度与脆弱来自同一枚硬币——内存。全书所有机制，都是在这枚硬币的两面上做工程。

## 四问对账：指到章，指到文件，指到测试

四问各记一段账：靠哪几章的机制、落在你写下的哪个文件、哪条测试在作证。

### 第一问：快从哪来——第 2、3、4、5 章

「在内存」只买了介质这一笔账（第 1 章），把它兑现成日常的快，靠的是四件事。

对话本身要便宜（第 2 章）。客户端与服务器之间是对讲机话术：RESP 协议每条消息先标类型、再标长度、行尾统一，解析不需要回溯。TCP 是字节流，一条命令切两段到、三条挤一次到都是常态，所以解码器必须带缓冲、不完整就攒着等下一段。resp.ts 里的 RespDecoder 逐行喂、命令整条吐；简单串与批量串的区别，就藏在 + 与 $ 两个记号里。这一章的十八个用例，最硬的那几条就是专喂半包与粘包。

快还来自不排队（第 3 章）。最笨的服务器一个线程从头伺候一个客户端——telnet 连上不敲回车，全场冻结，阻塞 IO 等一个人、误所有人。IO 多路复用让内核替一个线程盯住所有连接，谁就绪通知谁；事件循环配事件驱动，就是你天天用的 setTimeout 那套并发模型的延伸。一条连接一口气发十条命令、一次收回十条应答（管道），省的是九个网络往返。六条测试里有一条专门养着那个一言不发的连接——它不说话，不代表能卡住别人。

定位要快，扩容那一刻更要快（第 4 章）。GET 的路径短到两步：哈希函数算下标、链上比一次键。哈希冲突用链地址法排队，负载因子到 1 就翻倍。真功夫在扩容不停机：渐进式 rehash 双表同场，每次操作顺路搬一个桶。快不只是平均快，最坏那一刻也不能卡——这一切住在 dict.ts，十条测试里有一条灌十万键、边扩容边抽查最老的键：INFO 的 rehash 翻成 1，GET 依旧瞬回。

不是所有操作都该 O(1)（第 5 章）。排行榜要插得快、还能按分数切前一百：跳表用多层索引把有序链表做出二分的味道，新节点抛硬币定随机层数——1/4 晋升、免全局再平衡。有序集合等于跳表管序、字典管找——skiplist.ts 的功力由「一万随机分数与 Array.sort 基准对表」那条测试作证；真货还有第三层心思，type 之下按大小换 encoding（对象编码），小数据用紧凑结构省内存——视野一句，mini 不做。

四件事合起来，第一问一句话收账：**快是三笔账的合计——介质给底，对话便宜、结构保路径，调度保不排队**。

### 第二问：内存怎么管——第 6、7 章

内存贵且有限（第 1 章算过：比磁盘贵一到两个数量级）。mini 用两道闸把它管住。

寿命闸（第 6 章）。SET code ex 300 的验证码不会到点自动消失——百万键配百万个定时器不现实。真身是另一张表：过期字典记着每个键到期的绝对时刻。访问时顺带查一遍、到期就地删（惰性删除）；再配一个周期任务抽样检查，过期比例高就再加一轮、每轮掐着时间预算（定期删除）——第 3 章「摊薄」的药方在这里用了第二次。两招都住在 expire.ts，十九个用例把两条路各自单独钉死。合起来是 CPU 与内存的账：全靠惰性，没人碰的过期键一直占房；全靠定期，空转烧 CPU。

容量闸（第 7 章）。内存满了删谁？先分清两本账：过期删的是到期键，内存淘汰牺牲的是还活着的键。默认策略 noeviction 宁可拒写（返回 OOM 原文）不扔数据；换 allkeys-lru 才腾地方：随机抽 5 个、踢 idle 时钟最长的那位——近似 LRU 不求精确，只求最近访问过的存活概率高。LRU 与 LFU 是两种「热」的定义：新近用过算热，还是用得勤算热——报表扫描洗得动前者、洗不动后者，mini 只做了前者。eviction.ts 的 onWrite 在每次写入前抽 5 踢人，十二个用例守着三种局面：写满、拒写、腾位。

INFO 的 expires、expired、evicted 三个字段是这一问的仪表。**省内存是两道闸：寿命闸删到期的，容量闸让位最冷的**——两道闸删键都走同一个出口 dropKey，第 8 章的账本因此不撒谎。

### 第三问：数据怎么不丢——第 8、9 章

内存断电就忘，mini 配了两本思路相反、互相补台的账。

记过程的账（第 8 章）。AOF 是写后日志：命令先执行、干成了才记账——与数据库先记账再执行的 WAL 相反，账上因此不会有被拒的坏账。重启即重放：新进程把账本逐条再执行一遍，重启后的记忆其实是重演。账本臃肿了就 AOF 重写，按内存现状反推最小命令集，一百次 SET 同键只剩一条。落盘分两层：write 每笔都走，管的是进程崩；fsync 才真钉盘，管的是断电——刷盘策略三档（always / everysec / no）就是稳与快的档位。服务器自发的删除（过期、淘汰）统一补记一条 DEL，不然重放出来的库与内存对不上。aof.ts 的 append 与 rewriteFrom 是这一章的两只手，十三个用例钉着重放等价与补记 DEL。

拍结果的账（第 9 章）。RDB 快照拍某一瞬的全库现状：恢复成本只看数据量、不看账长——重放一亿条命令与装一张照片，差的就是这个量级。难在拍照时数据还在被写：真货用 fork 复制页表而非内存本身，配合写时复制，子进程看到的是冻结的那一瞬，主进程照常接客——快照一致性不必停写。mini 的 SAVE 在主线程同步拍，这条差异第 9 章当场声明。rdb.ts 的 dump/load 是一对纯函数，九个用例守着「拍—砸—装」往返等价。

诚实账也收在这里：**「不丢」从来是档位，不是绝对**。everysec 有一秒的窗口，两次快照之间的写入全在窗外；要一条不丢，得付同步复制的延迟税——第 10 章算过。INFO 的 aof 与 rdb 两行是这一问的仪表。

### 第四问：一台挂了怎么办——第 10 章，清一笔旧账

前三问都在一台机器之内；机器整个没了，账本与照片一起陪葬。第 10 章给的是地图：主从复制把数据搬去第二台（全量同步三阶段——PSYNC 握手、传一张 RDB、增量缓冲补发；断线重连靠增量复制只补缺口），哨兵用 quorum 认定加多数授权完成故障转移，集群把键空间切成 16384 个哈希槽、扩容搬槽不搬家。

第 10 章末尾留了一句：「终章对账会回到这一条——**mini 缺的不是单机内核，是多机的那一层**」。现在对账。零件你全有：全量同步要传的 RDB，就是你写的 dump 与 load；主库发给从库的命令流，与 AOF 记的是同一份账——dropKey 补的那条 DEL，另一半读者正是从库；从库追平数据靠重放——第 8 章的 restore 一行不用改；哨兵盯的心跳，是你第 2 章写的 PING。缺的是把零件摆上多台机器的协议与胶水：PSYNC 的握手与 backlog 环形缓冲、哨兵间的投票与授权、槽的路由与迁移。单是「两台机器对同一事实达成一致」，就是另一个世界的学问。这笔账到此清了：mini 的边界画在单机，边界外的世界第 10 章交了地图，也留了登记（[差异清单](./divergence)）。

## 收口：开篇那句大问话，现在整句回答

「一个把全部数据放进内存的键值服务器，凭什么做到快、省内存、还不丢数据？」

凭快：介质打底（全内存的 ~100ns），RESP 让对话本身便宜，O(1) 哈希定位与 O(logN) 跳表保路径，单线程事件循环免锁免切换、不排队——第 1 到 5 章。凭省内存：该走的快点走（寿命闸），走不完的按冷热让位（容量闸）——第 6、7 章。凭不丢：两本账互补，AOF 记过程一条不落，RDB 快照拍结果一刻不等，档位自选——第 8、9 章。

问话里没问到的第四问——一台挂了怎么办——单机答不了，答案在机器之外；那是 mini 的边界，也是这门课诚实的终点。再往深一层说：**内存给的是天性，省与不丢是后天修来的自律**——天性人人拿得到，自律才分得出工程的高下。这门课教的从来不是 Redis 的用法，是这份自律怎么一行行写出来。

## 能力对账：你亲手写出了什么

不夸大，逐项盘点 companion：

- 十三个源文件、约 1300 行（不含空行，含注释）。核心十件：resp、dict、skiplist、expire、eviction、aof、rdb、db、server、client。再加 naive-server（第 3 章的串行反例）与 boot、boot-naive 两个开机入口；
- 八个测试文件、101 条测试，此刻全绿。第 2 章的 18 条到今天还在跑——测试只增不改，旧章持续绿，就是公共 API 从没变过的哨兵；
- 十六条命令，按用途分四组：PING、INFO、CONFIG、FLUSHALL 管观察与运维；SET（带 EX）、GET、DEL、EXPIRE、TTL、KEYS 管字符串与寿命；ZADD、ZRANGE、ZCARD 管有序集合，BGREWRITEAOF、SAVE、LOAD 管账本与照片；
- 亲手开机：node src/boot.ts 起服务，本机 redis-cli -p 6399 连上去收发——全书的终点目标，一路就是奔它去的。

一条 INFO 就能看四问。右列是教学注解，真实输出只有左列：

```text
keys:3      全景：此刻住着几个键
expires:1   内存·寿命闸：登记了寿命的键
expired:1   内存·寿命闸：已删掉的过期键
evicted:0   内存·容量闸：已淘汰的活键
rehash:0    快：哈希表正在搬家吗
aof:4       不丢：账本记了几笔
rdb:1       不丢：最近一张照片拍了几个键
```

没写出来的也照实说：多机的那一层（复制、哨兵、集群）。RESP3 与 inline command、一切后台线程（everysec 的后台 fsync、BGSAVE 的 fork）。按字节计的内存、listpack 这类对象编码、SipHash——每一笔都登记在[差异清单](./divergence)，一条不漏。**差异不是缺陷，是界桩**：界桩之内，每行代码你都写得出、每条测试都读得懂；界桩之外，你知道路怎么走。

## 继续往哪走

三条路都真实可查，不开空头支票。

一、官方文档补视野。三页各对一问——快没有单页文档，散在各结构页：

| 想补哪块 | 入口 |
| --- | --- |
| 不丢：AOF、RDB、fork 与写时复制的原文 | [持久化页](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/) |
| 内存：近似 LRU、LFU、maxmemory-samples | [淘汰页](https://redis.io/docs/latest/develop/reference/eviction/) |
| 一台挂了：复制、哨兵、集群各专页 | [文档站 develop 区](https://redis.io/docs/latest/develop/) |

你已经有实现体感，读它们是验收自己，不是从头学。

二、读真源码，对答案。Redis 源码公开在 github.com/redis/redis 的 src/ 下，你写过的几乎每个文件都有同名真身。单机五件：dict.c、expire.c、evict.c、aof.c、rdb.c。多机三件：replication.c、sentinel.c、cluster.c。读法有讲究：先读文件头注释与核心结构体，再对照自己的教学版找差异。dict.c 的头注释写着链地址、桶数取 2 的幂、渐进一步搬一个桶，第 4 章讲过的口径，在那里能看到原话。地图你已经亲手画过一遍，读真货不是探险，是对答案。

三、再写一遍。[练习路线](./exercises)把 companion 的测试梯子交给你：清空实现目录，按章序让测试从红到绿重写一遍。第二遍你会写得快很多——快出来的那些部分，就是真懂了的部分。

## 收束：自查三问，然后合上书

开头的那个你，只会说「因为在内存」；现在的你，四问各有一段拆得开的账，还有一台自己写的机器作证。合书之前，最后三问。

1. 同事说：「快不就是在内存嘛，我用 C 写个哈希表放内存，一样快。」你打算怎么接？至少指出他漏掉的三笔账。
2. 先猜后跑，把仪表盘全亮一遍：删掉旧的 appendonly.aof（第 8 章起开机要重放旧账），node src/boot.ts 起服务。用 redis-cli -p 6399 依次执行 SET a 1、SET b 2、SET c 3 EX 100。再 CONFIG SET maxmemory 3、SET d 4。先猜 INFO 七个字段各是几，写下再跑 INFO 对照。然后 CONFIG SET maxmemory-policy allkeys-lru、SET e 5，先猜 evicted 与 keys，再跑一遍。
3. 一只键的长镜头：SET s 1 EX 600 之后立刻 SAVE；把时钟拨过 601 秒（测试里注入 now 就是这么干的）。此时 GET s 返回什么？INFO 的 expired 与 rdb 各是几？接着按第 9 章的剧本 FLUSHALL 再 LOAD，GET s 又返回什么——为什么照片装回来，它还是不在？

<details>
<summary>第 1 问答案</summary>

他只对了介质那一笔。漏掉的至少还有：调度账——一千个连接怎么不被一个慢客户端冻结（IO 多路复用加事件循环，第 3 章）；最坏时刻账——扩容那一瞬不许全场停机（渐进式 rehash，第 4 章），有序操作不许退化成全表排序（跳表，第 5 章）；还有内存与断电两本账——满了删谁、断电丢多少（第 6 到 9 章）。锚点：第一问的四件事。
</details>

<details>
<summary>第 2 问答案</summary>

第一轮应看到：keys:3、expires:1、expired:0、evicted:0。rehash:0、aof:3、rdb:0。三条 SET 各记一笔账；被拒的 SET d 不记账——写后日志只记干成了的。SET d 回的是 OOM 错误，默认策略 noeviction 宁拒不让。第二轮：evicted:1——三个候选全被抽中，a 的 idle 时钟最长，出局；keys:3，踢一进一；aof:5——a 的死讯（dropKey 补记的那条 DEL）也进了一笔账。数字对不上的话，先看是不是忘了删 appendonly.aof。锚点：第 7 章的 noeviction 与近似 LRU、第 8 章「干成了才记账」。
</details>

<details>
<summary>第 3 问答案</summary>

GET s 返回 nil——惰性删除在访问那一刻把它删了，expired 变 1；rdb 仍是 1——照片记的是 SAVE 那一刻的键数，当时的 s 还活着，拍了进去。FLUSHALL 再 LOAD 后，GET s 仍是 nil：照片里带的是绝对到期时刻，装回来时时刻已过，惰性检查照样拦下。这正是第 9 章「寿命记绝对时刻、不记剩余秒」的原因——记剩余秒，键就还魂了。锚点：第 9 章的快照收集、第 6 章惰性删除。
</details>

四问收拢，账本合上。往后再在事故复盘或面试桌上遇到「内存数据库凭什么」，你不必背任何人的答案——你写过一台。全书完。
