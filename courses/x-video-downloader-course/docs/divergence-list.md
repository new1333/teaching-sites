# 本课程简化了什么

正文每处「教学版认了这笔账」的简化与未实现项，集中登记在这里。简化不等于错——每条都注明为什么可以这样做、以及想做完整该怎么走。表中的正文出处指向所在章节。

| 简化 / 未实现 | 为什么可以 | 正文出处 |
| --- | --- | --- |
| EXT-X-MAP 的 BYTERANGE 属性不实现，只读 URI | 初始化分片单独成文件是主流形态；字节区间下载是传输优化，不改变「先取说明书」的语义 | [第 3 章](./03-m3u8-parse)「fMP4」一节 |
| 多份 EXT-X-MAP 中途换说明书，按点播单一说明书处理 | X 的点播清单从头到尾一份说明书；中途换表是直播切流场景 | [第 3 章](./03-m3u8-parse)「fMP4」一节 |
| 直播滑窗 / MEDIA-SEQUENCE 滚动不处理 | 本课只下载点播（有 ENDLIST 的清单），滑窗清单拼出来也不完整 | [第 3 章](./03-m3u8-parse)逐行讲解 |
| I-frames-only 清单不涉及（EXT-X-MAP 版本号细则） | 那类清单用于 trick play 缩略图轨，视频下载用不到 | [第 3 章](./03-m3u8-parse)「fMP4」一节 |
| 消息递整段字节（base64）而非分段流式 | 两个世界无共享内存，消息传拷贝；几十 MB 视频多住一份内存，教学版认了。分段流式可把峰值内存压下来 | [第 4 章](./04-download-pipeline)第三步 |
| revoke 延迟取常量 10 秒 | 浏览器接住下载只需一瞬间，10 秒是宽裕的经验值 | [第 4 章](./04-download-pipeline)第三步 |
| 不做分片完整性校验（EXTINF 时长合计 vs 实际字节） | 分片来自自家管线，404/异常走 SegmentFetchError；字节级校验要懂容器格式，超出教学面 | [第 4 章](./04-download-pipeline) |
| 并发数 concurrency=4 未经吞吐调优 | 4 是礼貌的默认值；教学重心在「乱序并发、按序归位」的机制 | [第 4 章](./04-download-pipeline) |
| 消息通道 64 MiB 上限未绕开（超大视频会撞顶） | base64 过河的代价；真要下超长视频需分段传输 | [第 5 章](./05-inject-ui)「第四宗罪」 |
| 对号账本按「标签页最近看到的视频」，不做媒体 id 级精确对号 | 一个标签页同时播多条视频的场景罕见；精确对号要解析页面 GraphQL 数据，复杂度不成比例 | [第 5 章](./05-inject-ui)收束 |
| MutationObserver 回调整页重扫，不增量精查、不节流 | 重扫幂等（BUTTON_ATTR 防重复），代码简单可靠；增量精查是性能优化 | [第 5 章](./05-inject-ui) |
| tweetLinkFrom 取第一个 /status/ 锚，引用卡等非标准形态提不到 id → 不注入按钮 | 宁可少注入不可错注入；引用视频去原推下即可 | [第 5 章](./05-inject-ui) |
| storage.session 账本条目不随标签页关闭清理 | 会话存储浏览器重启即清；逐标签页清理要监听标签页生命周期 | [第 5 章](./05-inject-ui) |
| 核对脚本的证据是静态文本匹配（chrome.* 正则、import 闭包正则），非运行时验证 | 静态匹配已拦得住「报了不用/用了没报」两类主案；运行时验证要注入真实页面 | [第 6 章](./06-permissions-publish)演练 |
| zip 拖回 chrome://extensions 装载不被接受（Chrome 拒收拖放） | 官方装载通道是「加载已解压的扩展程序」；验证走解压后装载的等价路径 | [第 6 章](./06-permissions-publish)验证 |
| manifest 无 icons 字段 | 图标不影响装载与功能；真上架需在开发者后台补 128×128 列表图标 | [第 6 章](./06-permissions-publish)打包 |
| 上架演练止步于 zip 与自查：5 美元注册、隐私政策、版权审核未实际执行 | 教学边界如实声明；真上架大概率倒在版权关——这是课程设计时接受的边界 | [第 6 章](./06-permissions-publish)「版权」段 |
| DONE 消息缺 bytesB64 时按钮仍显「已存盘」（静默失败） | 作为第 7 章自查的靶子留给读者修（加上类型校验转 error 态即可） | [第 7 章](./07-full-chain-review)自查第 3 题 |
| heightFromUrl 对竖屏 mp4（720x1280）文件名标 720p（取尺寸段第一个数字） | 文件名指纹用途，不影响内容；按第二数字取高度即可修 | [第 7 章](./07-full-chain-review) |
| 同一 statusId 的多条推文（转推共享同一视频 id）只路由到最后注入的按钮 | buttons 以 statusId 为键，后来的覆盖先前的；先前按钮可能停在中间态。改复合键（statusId+元素）可修 | [第 5 章](./05-inject-ui)第五步 |
