# 申购费：外扣法一笔算清

拿 1 万元买基金，当日净值 1.0231。心算：10000 ÷ 1.0231，约 9774 份。第二天确认到账，只有 9759.58 份——少的 14.64 份去哪了？这一章把这笔账算到分，顺便纠正一个几乎人人中招的直觉算法。算完你会知道：平台多半没算错，是你的心算漏了一步；而知道差在哪，才谈得上下单前先把代价算出来。

## 直觉算法错在哪

多数人的直觉是「先扣手续费，剩下的钱买基金」：1 万元扣掉 15 元（按 0.15% 算），9985 元除以净值 1.0231，得 9759.55 份。这个思路叫内扣，理解起来顺，但制度实际用的是外扣法（external deduction）：**净申购金额 = 申购金额 ÷（1 + 申购费率）**，费用隐含在价内，像「含税价还原成不含税价」。

为什么用外扣？口径统一是主因：打折后的费率、分档收费在内扣口径下容易算出不同结果，外扣把「含费的总价」和「费率」两个量直接挂钩，全国一套公式。行业自 2007 年起统一执行外扣口径；现行标称申购费上限按 2026 年施行的销售费用新规执行（主动偏股不超过 0.8%，指数与债券不超过 0.3%），存量产品随合同约定，具体以各基金招募说明书为准（截至 2026-08）。

## 三步算清

用真实数字走一遍外扣法。申购金额 10000 元，申购费率取折扣后的 0.15%（标称费率与折扣因基金和渠道而异，存量老产品标称多为 1.5%、新规产品上限更低——计算方法完全相同），当日净值 1.0231：

```text
第一步 净申购金额 = 10000 ÷ (1 + 0.0015) = 9985.02 元
第二步 申购费用   = 10000 − 9985.02 = 14.98 元
第三步 申购份额   = 9985.02 ÷ 1.0231 = 9759.58 份
```

注意两件事。第一，费用是 14.98 元而不是 15 元——外扣的费基（净申购金额）比内扣的费基（全额）小，同一标称费率下你交的钱略少。第二，与完全免费的 9774.22 份相比，差额 14.64 份对应的就是那笔费用。若把费用摊到每一份上，你的「含费成本净值」是 10000 ÷ 9759.58 = 1.0246——比当日净值高出的那一点点，就是费用的痕迹。

这些数字不是手算的——课程伴生仓里是几个一行的纯函数核对脚本：下面这个输入同样的三个数，输出前三个数（第四个「含费成本净值」由另一个一行函数 costNavInclFee 用 10000 除以份额得到）：

<details><summary>src/fees.mjs · purchase（核对脚本核心，6 行）</summary>

```js
// src/fees.mjs · purchase
export const purchase = ({ amount, feeRate, nav }) => {
  const net = amount / (1 + feeRate) // 外扣法：净申购金额 = 申购金额 / (1 + 费率)
  const fee = amount - net
  return { net, fee, shares: net / nav }
}
```

</details>

## 两个容易混淆的概念

到这里有一对词必须分开：**费率打折**和**外扣法**。打折是渠道给的优惠——标称 1.5% 的申购费率，互联网平台常打一折收 0.15%，这是「价格」变了；外扣是计算口径——同样收 0.15%，用外扣法你实际交 14.98 元而不是 15.00 元，这是「算法」变了。前者省的是大头（135 元），后者省的是零头（0.02 元），但两者叠加生效，缺一不可。别把「打完折还有几毛钱差距」当成平台乱扣费——先按三步公式复算，再下结论。

另一件值得知道的事：申购费率通常按金额分档。比如 100 万元以下一档、100 万元以上更低档——金额越大，边际费率越低。分档影响的是「费率」这个输入，不影响三步公式的形状。你的确认单上写的实收费率，永远是分档加折扣后的最终值。

## 小结与自查

外扣法三步：先除（1 + 费率）得净申购金额，再相减得费用，最后除以净值得份额。费用在确认单上明码标价，一分不差。下一章讲卖出那头的赎回费——那边的费率不是固定值，而是一张与持有天数挂钩的阶梯表；两头的费用最终会在第 9 章串成一张完整的对账单。
