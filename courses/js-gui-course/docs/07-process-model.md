# 为什么是两个进程

把时间拨回 2006 年前后的单进程浏览器时代，翻一翻当年的事故记录，三种崩溃反复出现。其一：某个页面写了 `while(true){}`，整个浏览器连同另外九个标签页全部冻结，用户只能杀进程，九个未提交的表单一起陪葬。其二：某个 Flash 插件的解码器越界写内存，进程直接崩——所有页面、所有插件、下载进度，全部消失。其三：某个广告页里的脚本能调用浏览器的文件接口，安全研究者的论文里这类漏洞一抓一把。这三个现象方向不同，根因却相同：**所有角色——界面、插件、网页脚本——挤在一个进程里，共享同一份内存、同一条线程、同一套权限，谁出事都是全体出事**。

桌面端框架最终全都走向了同一个答案：把「跑不可信界面代码的地方」和「握着系统能力的地方」拆进不同进程。Electron 把这条路线推到了明面上，所以用它的术语来讲：主进程（main process）与渲染进程（renderer process）。这一章讲墙是怎么砌的——为什么非进程不可、拆完之后丢了什么。

## 三步逻辑：崩溃隔离、权限收缴、能力外借

第一步，崩溃隔离。进程是操作系统提供的内存隔离单位：每个进程有独立地址空间，A 进程崩溃只是内核回收它的内存，B 进程毫发无伤。线程做不到这一点——一个线程把栈写穿，整个进程一起完蛋。所以「渲染崩溃不能带走浏览器」这个需求，只有进程边界能满足。用第 3 章的话说：给每个渲染单元一个自己的宿主实例、自己的隔离环境，物理上隔开，而不是靠约定。单进程时代的第一个事故（死循环冻结全体）在多进程下变成：一个标签页转圈，其他标签页照常刷视频。

第二步，权限收缴。进程隔离顺带解决了权限问题：系统能力（开窗口、读写文件、调摄像头）只交给主进程；渲染进程被有意做成「什么都没有」——没有 fs、没有 shell、没有原生 binding。跑不可信代码（网页脚本、npm 拉来的前端依赖）的地方，干脆让它没钥匙可丢。第三个事故（广告页摸到文件接口）在这道墙下失去存在前提：不是「禁止它调用」，是「它那里根本没有这个函数」——权限模型从黑名单变成缺席。

第三步，能力外借。渲染进程终究需要系统能力（存个文件、弹个保存框），怎么办？借。两个进程之间开一条消息通道——进程间通信（IPC）——渲染进程发请求，主进程代办后回传结果。关键词是「代办」：**渲染进程从未获得能力，它获得的是一次服务**。开不开窗口、准不准读文件，决定权始终在主进程手里，所以主进程可以在通道这一侧做校验、限流、拒绝。第 5 章的句柄思想在这里升了一级：JS 对原生如此，渲染进程对主进程也是如此——遥控器关系在更大的尺度上重演。

## 拆完丢掉了什么：序列化的全面化

这道墙不是免费的，代价就是第 4 章那条规则从「语言边界」升级成「进程边界」。进程不共享内存，所以：

- 跨进程传的一切数据必须序列化——对象、数组、Buffer，无一例外；
- 函数彻底不能传——回调变成「传个 id，对端拿 id 反查注册表再调用」；
- 每次调用都有往返成本——一次 IPC 的耗时以毫秒计，高频调用（每帧同步状态）会把它放大成性能事故。

真实 Electron 里你天天撞的墙全是这条规则的投影：渲染进程里 `require('fs')` 不存在；`ipcRenderer.invoke` 的参数里放了函数就报 `Error: object is not serializable`；主进程的对象传不过去，传过去再传回来已经是深拷贝——两边 `===` 永远是 false。调包时代这些是「Electron 的怪癖」，原理视角下它们是进程边界的必然推论，与我们第 4 章 binding 层手写的 `serialize` 拒收函数是同一条规则的两级形态。

## 为什么偏偏是 Chromium 整体搬进来

还有一个级别的选择问题值得想清楚：Electron 的渲染进程不是「手写的界面库」，是把整个 Chromium（含 Blink 渲染引擎、V8、整套 Web API）作为库链接进来。为什么？因为「用 Web 技术写界面」的完整含义是：要 DOM、要 CSS、要整套浏览器兼容行为。自己实现等于重写一个浏览器，所以 Electron 的选择是干脆背一个来。这解释了它著名的体积与内存占用，也是后面讲生态对比那章的核心变量——Tauri 换成系统自带 WebView、Qt 绑定干脆不用 Web 渲染，都是在这同一个「界面从哪儿来」的问题上给出不同答案。

进程模型还有两个工程红利顺带收下：并行（多个渲染进程各占各的核，天然利用多核）与按需回收（一个页面内存泄漏，关掉那个进程即刻还给系统）。但主脉络始终是那三步：隔离崩溃、收缴权限、外借能力。

## 小结

主进程握系统能力，渲染进程跑界面代码，中间一条序列化通道。墙的两边各是一个完整的「宿主 + JS 引擎」（第 3 章），各自有独立的消息循环（第 2 章），渲染进程想借能力只能发消息求主进程代办。开篇三个单进程时代的事故——冻结全体、插件崩全灭、脚本摸文件——分别被进程隔离、权限缺席、代办校验逐个拆掉。下一章我们把那条通道亲手造出来：invoke/handle 的请求-响应（request-response）配对，send/on 的事件推送（event push）。
