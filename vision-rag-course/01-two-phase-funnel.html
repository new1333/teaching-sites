先通读做笔记，再按笔记翻书：两阶段架构与成本漏斗 ​

周五下午，你要在一本 300 页的设备手册里查一个配置项。手册一半是表格和示意图，你不想一页页翻，于是写了段 Python 脚本：把整本 PDF 逐页渲染（把每一页画成一张图片），连同问题一起打包发出去。收图的是视觉大模型（Vision Language Model，常简称 VLM）——一位看得见照片的远程助手：你把图片和问题发过去，它回你一段文字。

然后你开始等。两分钟后答案来了，这一问烧掉几十块。你追问一句「具体在第几页」，又是两分钟、又是几十块。你安慰自己：查手册嘛，这个成本认了。

直到你按它说的翻到第 187 页——那一页讲的是接线端子的安装间距，和你的问题毫无关系。再问一遍，它改口说在第 212 页。翻过去，还是不对。页码是编的，而且每次都编得理直气壮。

这不是模型坏了，是用法错了。整本塞给模型，同时踩了三个坑：贵、慢、页码不可信。这一章讲清三个坑各自的成因，再给出贯穿全书的解法形状。代码从下一章开始动手，此刻你只需要一张地图。

先认识这台机器：看得见照片的远程助手 ​

视觉大模型的特别之处，是文字和图片装进同一次请求它都接得住，还能就画面内容跟你讨论。这种「一个模型同时处理文字、图片等多种信息」的能力，行话叫多模态（multimodal）——也就是不挑信息的类型：问题是一段字，页面是一张图，一起发。

一次调用的形状如下：

text
一次调用的形状

  请求 ─ [ 文字：你的问题 ][ 图片：一页或好几页的图 ]
                   │  按请求内容的量计费：越多越贵、也越慢
                   ▼
  响应 ─ [ 文字：模型生成的回答 ]

  调用结束即两清：模型不记得这次会话——这个性质叫无状态

对整套架构最要紧的一条性质：调用是无状态的。挂断这一次请求，模型就把你忘得干干净净。它没有「读过你的手册」这回事，只有「这一次请求里带了哪些图」：你不发，它就没看见。

所以「每次提问都整本塞」不是偶然的浪费，是这台机器上唯一的笨办法——想让模型看见 300 页，每次都得把这 300 页重发一遍，每一遍都重新计费、重新等待。贵和慢，直接从这个性质里长出来。

桌子就这么大：上下文窗口 ​

无状态决定了每次重发，而重发的总量有硬约束。模型一次调用里能摊开读的全部内容，叫上下文窗口（context window）——把它想成助手面前的一张桌子：一次只能摊开这么多材料，摆满了就放不下。

text
上下文窗口 = 这一次调用里能摊开的全部材料

  [ 问题 ][ 第 1 页 ][ 第 2 页 ] … [ 第 299 页 ][ 第 300 页 ]
   └────────────────── 桌面就这么大 ──────────────────┘

上限为什么存在？读进来的每段文字、每张图，都要占用模型的计算和显存（模型芯片上的工作内存）；摊开的材料越多，单次调用越重。所以每次调用必有容量上限，超出就装不下——各家上限不同、随版本变化，但「上限存在」这件事不变。

计费也顺着这个量走。方向性的事实有两条：图片进模型按像素量折算费用，图越清晰越贵；文字按字数折算。计费和窗口共用的计量单位叫 token——模型世界的度量衡：文字和图片读进来都折成 token 数，账单按它算，窗口上限也按它算。

徒手算一笔账（口径是本书声明的简化模型，不是任何平台真实价格）：

text
对账用的简化口径：一页页图折合约 1500 token

每次提问都整本塞：300 页 × 1500 = 45 万 token
一天提问 20 次：  20 × 45 万 = 900 万 token，每问都要等约两分钟

三个坑到这里有了两个的着落：

  • 贵：无状态加重发，45 万 token 每问重付一遍；
  • 慢：生成耗时随内容量涨，两分钟的等待就是处理 45 万 token 的时间；
  • 页码是编的：最反直觉，值得单独一节。

页码为什么是编的：幻觉 ​

先给现象起名字：模型一本正经地编造不存在的内容或出处，叫幻觉（hallucination）——像考试不会答还硬编一个页号，语气还特别自信。

成因藏在「生成」两个字里。模型不是先查再答的查询引擎，它是逐字续写的机器：接到「答案在第几页」，它就续写一个格式完美的页码——此刻它手里并没有一张查过的页码对照表，页码只是恰好长得像引用的文字。

资料越厚，这毛病越重。300 页摊在窗口里，模型对单处细节的把握随篇幅变稀；第 187 页和第 212 页对它都只是「听起来可信的续写」。方向性的经验是：把同样的细节放进五六页里问，把握明显更稳。

所以解药不是换更聪明的模型，而是改结构。一，让页码来自物理事实：图片渲染出来时就和「第 N 页」的标签绑死，页码不需要模型猜。二，让模型一次只读几页，细节不再稀释。这两条分别在第 3 章和第 7 章兑现。

换个用法：先通读做笔记，再按笔记翻书 ​

回头看你查手册的动作，你自己早就会解这道题：没人查书时把整本书从封面读到封底——先看目录，翻到那一节，只细读那几页。把同样的纪律交给机器，就是两阶段。

阶段一，通读做笔记，每份资料只做一次：把每一页交给视觉模型读，让它为每页写一张卡片——这页讲什么、有哪些标题、关键词是什么、有没有图表。300 张卡片存成本地文件，这份资料从此算「读过了」，不必重做。这份卡片集就是索引（index）——让程序不用翻原书就能快速定位内容的目录。

阶段二，按笔记翻书，每次提问走一遍：先在卡片里筛出候选页，再让模型看图确认，最后只对确认的几页深读作答。

这套做法有正式名字：检索增强生成（Retrieval-Augmented Generation，业界简称 RAG）——先从资料里检索出相关内容，再让模型照着找到的部分作答。一句话：开卷考试，先翻书、再照着答；不是闭卷背诵，更不是现场编。

全书要造的机器，形状就这么点：

python
# 原理示意（伪码）：全书要造的东西，骨架就这么多
cards = read_once_and_take_notes(pdf)              # 阶段一：每页一张卡，只做一次

def ask(question):                                 # 阶段二：每次提问走三步
    hits = search_cards_locally(cards, question)   # 查卡片：免费
    best = model_look_and_pick(hits, question)     # 看图挑页：便宜
    return model_read_deeply(best, question)       # 深读作答：昂贵，答案带页码

其中「查卡片」这步你现在就能亲手试——它不碰任何模型，只是在本地的笔记文字里查字：

python
# 用法示例：粗筛的本质——在本地笔记里查字，一次模型调用都不用发
cards = {5: "退货政策：七天无理由退货", 12: "保修条款与顺延", 30: "客服联系方式"}
hits = [p for p, note in cards.items() if "退货" in note]
print(hits)  # [5]：三百页的书，只有这一页值得惊动模型

把这三行粘进 Python 解释器（命令行输入 python 回车）就能跑。检索的对象是卡片不是原书——索引的意义就在这：把 300 页图压成 300 行文字，查起来毫秒级、零费用。

三层漏斗：便宜的先粗定位，昂贵的只看刀刃 ​

阶段二内部还有个花钱的次序问题：粗筛之后候选仍有十来页，全部直接深读吗？工程上的答案是层层收口，越往后的手段越贵、页数越少。这个结构叫成本漏斗——像招聘：简历机筛（免费）刷掉大多数人，面试精选（便宜）定出小名单，终面细聊（昂贵）只留给最后几个人。

层一句人话代价
粗筛在读书卡片里查字，圈出十来页候选本地程序：免费、毫秒
精排把候选页的图给模型看一眼，挑出真正相关的几页一次低档调用：便宜、几秒
深读只把选中的几页摊开高档细读，带页码作答一次高档调用：昂贵、十几秒

表里「低档/高档」指推理档位——模型下笔前「想多深」的旋钮：批量过卡用低档省时省钱，深度分析才拧到高档。粗筛凭什么免费？因为它只是本地文字运算，第 5 章动手写它。

text
        300 页（旧用法：每次提问都整本塞，45 万 token）
                          │
  第一层 粗筛 ── 查卡片，圈出 12 页候选      免费 · 毫秒
                          │
  第二层 精排 ── 看候选页的图，挑出 4 页     便宜 · 一次低档调用
                          │
  第三层 深读 ── 4 页连同前后邻页摊开细读    昂贵 · 一次高档调用
                          │
                          ▼
        答案带 [第N页] 引用 + 证据页图，可核对

深读那行为什么带邻页：表格常在页缝处断成两半，只看半张表必猜错，所以每个选中页带上前后各一页——4 页最多展开成 12 页。

新旧用法对账（同一简化口径）：

text
建索引（只付一次）：300 页 × 1500 = 45 万 token
每次提问：精排 12 页 + 深读最多 12 页 = 24 页 × 1500 = 3.6 万 token

一天 20 问的总账：
整本塞：20 × 45 万 = 900 万 token，每问约两分钟
漏斗：  45 万 + 20 × 3.6 万 = 117 万 token，约为整本塞的 1/8，每问十几秒

卡片建好就存成文件，资料不变就永远复用。你为这本书付的钱，从「每问 45 万」变成「一生一次 45 万，之后每问 3.6 万」。慢的问题同步解掉：每问只处理三万多 token，十几秒出答案。页码问题也在结构里解掉：深读只摊开几页，且每页图带着渲染时绑好的页码标签——页码来自物理事实，不再靠模型猜。

全书地图：每一章在漏斗里的位置 ​

一条诚实的边界先立在这：本书代码不追求生产级，追求每条原理都能亲手验证。全书实现是一个千行级的伴生实验场，用假模型按剧本回放响应——不联网、不花真钱，每个断言都有测试盯着；真引擎只隔着一层可替换的传输接口——下一章就造它，随时换得上。

带上地图出发 ​

这一章没写一行真实现，但全书的路线就此定下：视觉大模型是看得见照片的远程助手，调用无状态、按量计费、窗口有限，整本塞必然又贵又慢；页码编造源自「生成不是查询」，解法是让页码绑定物理事实、让深读只看几页；两阶段——先通读做笔记，再按笔记翻书——加上三层成本漏斗，把每一问的代价压到整本塞的约八分之一。
